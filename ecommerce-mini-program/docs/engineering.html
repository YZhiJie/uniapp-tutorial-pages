工程化收尾（阶段五交付） ​

范围：单测矩阵、各端 CI 上传、构建体积检查、灰度放量演练、Mock → HttpTransport 转接演练。 所有命令在 ecommerce-mini-program/ 下执行。

1. 质量门禁 ​

命令作用失败含义
pnpm typecheckvue-tsc --noEmit，严格模式全量类型检查类型契约被破坏
pnpm test:runVitest 一次性运行全部单测业务逻辑或降级路径回归
pnpm ci:guard静态守卫：业务目录禁条件编译、flag 注册表合规、api 不反向依赖 store架构边界被破坏
pnpm ci:perf构建产物体积预算检查（需先 build），并输出与上次的体积趋势主包/总体积超限
pnpm run ci一键流水线：typecheck → test:run → ci:guard → build:all → ci:perf任一门禁失败即中断
pnpm e2e:marketing营销端到端回归：拼团 / 秒杀 / 直播，自动起 dev server 并驱动无头 Chrome（H5 + Mock）营销链路行为回归

建议流水线顺序：install → pnpm run ci；上传单独执行 ci:upload:<platform>，营销端到端单独执行 e2e:marketing。仓库已接入 .github/workflows/ci-ecommerce.yml，push / PR 命中 ecommerce-mini-program/** 时自动执行 verify 与 e2e-marketing 两个 job，并把体积历史作为 artifact 保留。

3. 各端 CI 上传 ​

脚本：scripts/ci/upload.mjs，入口命令：

pnpm ci:upload:weixin    # mp-weixin
pnpm ci:upload:alipay    # mp-alipay
pnpm ci:upload:toutiao   # mp-toutiao
pnpm ci:upload:qq        # mp-qq
pnpm ci:upload:baidu     # mp-baidu
pnpm ci:upload:all       # 依次上传五端

加 --build 可先构建后上传：node scripts/ci/upload.mjs mp-weixin --build。 缺少密钥、官方 CLI 或构建产物时脚本安全跳过并以 exit 0 结束，不阻塞流水线。

4. 性能检查 ​

pnpm ci:perf 扫描 dist/build/<platform>，按 src/pages.json 的 subPackages[].root 区分主包与分包。

预算默认值覆盖方式
主包体积2MB（支付宝单独 3MB）全局 PERF_MAIN_LIMIT_MB；分端 PERF_MAIN_LIMIT_MB_MP_ALIPAY
总体积20MB（H5 至少按 10MB 计）全局 PERF_TOTAL_LIMIT_MB；分端 PERF_TOTAL_LIMIT_MB_MP_ALIPAY

分端变量优先级：分端环境变量 > 全局环境变量 > 分端默认 > 全局默认。变量名规则 PERF_<MAIN|TOTAL>_LIMIT_MB_<平台大写，非字母数字转下划线>，如 PERF_MAIN_LIMIT_MB_MP_QQ。支付宝 vendor.js 约 0.5MB，故主包默认放宽到 3MB，实际产物 0.76MB 仍有充足余量。

输出内容：各端总体积 / 主包体积 / 分包数、Top5 大文件、H5 gzip 体积；并与上次记录对比输出增减趋势。超预算 exit 1；无产物时提示后安全退出。

体积历史默认写入 dist/perf-history.json（保留最近 30 次，可用 PERF_HISTORY_FILE 覆盖），CI 中作为 artifact 上传便于查看趋势。

专项建议：

  • 营销页与低頻页面全部放进分包，主包只保留 tabBar 四页与公共组件。
  • 图片一律走 CDN 或 static，不内联大图；构建前用 pnpm build:<platform> 产出真实数据。
  • 长列表使用 src/components/business/VirtualList.vue（定高或 dynamic 动态高模式），避免一次性渲染全量节点。

5. 灰度演练 runbook（5% → 100% → 秒级关闭） ​

演练 flag：feature.couponCenter（注册于 src/config/flags.ts，默认关闭，Mock 侧默认 100% 可见）。

前置：pnpm dev:h5 或任一小程序端开发模式（VITE_MOCK_MODE=local），进入「我的」页。

  1. 确认基线：优惠券中心入口可见；「我的 → 工程演练」显示 开放 · 桶 N · BUCKET。
  2. 5% 放量：工程演练面板点「5% 放量」。POST /config/flag-drill 写入 { key, percent: 5, enabled: true }，随后刷新远程配置。
    • 桶号小于 5 的用户入口保留，其余用户入口立即消失；
    • 面板 toast 会显示当前桶号与命中结果，便于换账号验证。
  3. 100% 全量：点「100% 全量」。同一用户桶号不变（hash(userId + flagKey) % 100 稳定），入口恢复。
  4. 秒级关闭：点「秒级关闭」（percent: 0, enabled: false）。入口消失，reason=DISABLED；优惠券列表等老数据仍可读取，无报错。
  5. 免手动刷新：App.vue 在 onShow 启动 10s 配置轮询（CONFIG_REFRESH_INTERVAL），onHide 停止。只改服务端配置、不动客户端，最多 10s 生效；也可在面板操作后立即手动 refresh()。
  6. 验收断言：关闭态入口消失且无报错；开启态链路完整；同一用户多端多次启动桶号一致（单测 remote-config.spec.ts 已固化 u_1001 → 桶 16）。

生产环境把 /config/flag-drill 换成配置平台写接口即可，客户端逻辑不变。

6. 转接演练 runbook（随机 2 个接口 Mock → HttpTransport） ​

实现要点：

  • src/config/runtime.ts 的 isRealRequest(domain, path) 依次判断：MOCK_MODE=http → 域级 gray.api.<domain> → 接口级 grayApis[path]。
  • src/transport/index.ts 的 transportFor(domain, path) 按接口选择 Transport，业务 API 不改一行代码。
  • Mock POST /config/transport-drill 从候选池（/goods/list、/goods/categories、/goods/detail、/order/list、/favorite/list）随机抽 2 个，或 reset 清空。

推荐在 H5 演示，真实请求可被现有 msw worker 回归，形成闭环：

bash
# .env.development 已配置 VITE_API_BASE_URL=/api
VITE_MOCK_MODE=msw pnpm dev:h5
  1. 打开「我的 → 工程演练」，点「随机抽取 2 个」，面板展示本次抽中的接口路径。
  2. 触发对应业务：首页/分类加载商品、进入商品详情、订单列表、收藏列表。
  3. 观察 Network：被抽中接口请求 /api/*，由 msw 拦截并返回同构数据；其余接口仍走 LocalMock，无网络请求。
  4. 截图/记录 traceId 头（X-Trace-Id）用于归因。
  5. 点「回滚全部」→ grayApis 清空 → 所有接口回到 Mock；再次触发业务确认无真实请求。
  6. 回归断言：整个过程业务代码零改动；transport.spec.ts 覆盖域级/接口级切换与回滚。

小程序端演练：把 grayApis 下发到真实后端地址（替换 VITE_API_BASE_URL），流程相同；未接后端时保持 grayApis 为空即可。

7. 已知限制 ​

  • 微信上传依赖 miniprogram-ci；支付宝依赖 minidev；抖音/QQ/百度依赖各自开发者工具 CLI。仓库不内置这些二进制，CI 需自行安装或提供 *_UPLOAD_CMD。
  • 缺少真实后端与上传密钥时，上传脚本按设计跳过（exit 0），不会产生假成功。
  • 体积预算为经验值，可按业务调整 PERF_MAIN_LIMIT_MB / PERF_TOTAL_LIMIT_MB；首次接入请先跑一次 build 建立基线。
  • 配置轮询间隔固定 10s（常量在 src/config/env.ts），仅前台运行；后台/冷启动依赖启动拉取。
  • 灰度桶号基于 userId + flagKey，匿名身份（未登录）会随匿名 ID 变化，属预期行为。
