企业级场景清单与选型结论（阶段一交付） ​

要求：至少落地 8 个。本清单共 12 个，全部给出「业务背景 → 方案对比 → 选型结论 → 实现位置 → 验证方式」。 具体代码在阶段二～四实现，本阶段只锁定方案，避免返工。

场景 1：登录态与路由守卫 ​

业务背景：六端静默登录能力不同，订单/地址/售后需要登录；登录后要回到原页面，token 过期要静默续期，401/403 要统一拦截。

方案做法优点代价
A. 每页 onShow 自行判断每个页面复制登录判断与跳转实现快重复代码、遗漏风险高、无法统一续期
B. 登录 Provider + 路由守卫LoginProvider 统一各端票据，拦截器统一 401/403，白名单 + 回跳参数一处治理、可测试、六端一致需要设计守卫与页面栈回跳协议

选型：B。 实现位置：providers/login/、platform/login.ts、utils/route-guard.ts、api/core 拦截器。验证：未登录进入订单页 → 跳登录 → 登录成功回原页；token 过期 → 自动续期一次 → 仍失败才跳登录。

场景 2：列表分页抽象 ​

业务背景：首页瀑布流、分类列表、搜索、订单列表都需分页；快速切 Tab 会产生重复请求与错序数据。

方案做法优点代价
A. 各页面自行维护 page/loading每页复制分页逻辑无抽象成本状态分散，竞态治理困难
B. usePagination 组合式函数统一 loading/finished/error/reset/loadMore，内部用请求序号丢弃过期响应行为一致、易测需要约定 request 签名与错误处理

选型：B。 实现位置：composables/usePagination.ts（阶段二）。验证：连续快速切换分类 Tab，旧分类响应不覆盖新分类列表；下拉刷新重置页码。

场景 3：请求竞态与取消 ​

业务背景：搜索联想、筛选切换会并发请求；只丢弃响应仍会浪费流量，小程序还需要真正中止请求。

方案做法优点代价
A. 只做响应打标丢弃axios/请求层加序号实现简单请求仍占用连接与配额
B. 真取消 + 响应丢弃小程序 RequestTask.abort，H5 AbortController，平台层统一省流量、状态干净需要平台适配与取消错误码归一

选型：B。 实现位置：platform/request.ts、api/core。验证：输入关键词连续触发 5 次请求，仅最后一次生效，控制台可见前 4 次 aborted；取消不产生错误提示。

场景 4：购物车数据一致性 ​

业务背景：详情页加购、购物车增减、结算回退都会修改购物车；弱网下需要即时反馈又不能丢数据。

方案做法优点代价
A. 每次操作后全量刷新服务端为准，重新拉列表一致性强弱网卡顿、数量闪烁、体验差
B. 本地乐观更新 + 失败回滚先改本地快照，请求失败回滚并提示；跨页事件同步响应快、体验好需要版本号/快照与冲突处理

选型：B。 同 SKU 合并加购；购物车 store 维护 snapshotVersion，写入成功才更新基准快照。实现位置：stores/cart.ts、api/cart.ts。验证：飞行模式下加购 → 数量先 +1 → 失败回滚 + Toast；恢复网络后数据一致。

场景 5：SKU 规格选择器 ​

业务背景：多规格商品需要在任意组合下正确置灰、回溯选中路径、计算价格区间与库存。

方案做法优点代价
A. 每次点击全量重算可选性遍历所有 SKU 判断逻辑直观O(n*m) 重复计算，长规格易卡顿
B. 预构建规格可达矩阵初始化时构建邻接/可达表，点击只做局部回溯点击 O(1) 级判断，易扩展构建逻辑复杂，需要单测覆盖

选型：B。 实现位置：components/business/SkuPopup.vue + composables/useSku.ts + utils/sku-matrix.ts（阶段二）。验证：单测覆盖「选中 A 后 B 不可选」「取消 A 后 B 恢复」「无库存组合置灰」「价格区间计算」。

场景 6：订单超时与倒计时 ​

业务背景：待支付订单 15/30 分钟关闭；本地时间可被修改，页面隐藏后计时会漂移。

方案做法优点代价
A. 直接 Date.now() 倒计时页面内 setInterval实现快本地时钟不准、后台挂起后错乱
B. 服务端校准 + 页面恢复重算记录 serverTimeOffset，onShow 用服务端时间重算，归零自动刷新订单准确、可恢复需要统一时间工具与生命周期处理

选型：B。 实现位置：utils/time.ts、components/business/CountDown.vue、stores/order.ts。验证：手动改系统时间倒计时不变；切后台 5 分钟后回前台时间正确；归零自动请求订单状态。

场景 7：支付结果确认 ​

业务背景：支付回跳不可靠，存在「已支付但订单状态未同步」；重复点击支付还会重复下单。

方案做法优点代价
A. 仅依赖支付回调/回跳回跳后直接展示成功简单回跳丢失、状态延迟时误判
B. 回跳 + 主动查询 + 轮询退避先查一次，PENDING 时按 1s/2s/4s 退避轮询，超时给人工入口结果可靠、可观测需要轮询管理、幂等与取消

选型：B。 支付按钮加防重锁；PaymentProvider 内部封装各端差异；查询与轮询统一走 stores/payment.ts。验证：Mock 配置「支付成功但回调延迟 3s」仍能确认成功；连续点击支付只产生一笔支付单；取消支付回到待支付态。

场景 8：Schema 驱动表单 ​

业务背景：地址新增/编辑字段多、联动显隐、动态校验；后续售后申请、发票信息也要复用。

方案做法优点代价
A. 每个表单手写模板与校验页面内写死字段与规则直接重复代码、校验口径不一致
B. Schema 配置 → 渲染 + 校验FormSchema 组件读取字段配置、规则与联动复用高、易测试需要设计 schema 结构与渲染器

选型：B。 实现位置：components/common/FormSchema.vue、utils/form-schema.ts。验证：地址表单必填/手机号/邮编校验；选择「其他标签」时出现自定义输入；编辑态正确回填。

场景 9：图片上传（售后凭证/头像） ​

业务背景：售后上传凭证需要压缩、限并发、失败重试、进度反馈，弱网下不能整批失败。

方案做法优点代价
A. 直传原图，串行选图后逐张上传简单大图慢、流量浪费、失败即中断
B. 压缩 + 并发上限 + 单张重试uni.compressImage，并发 3，失败指数退避，展示进度体验稳、可恢复需处理各端压缩能力差异

选型：B，已落地。 实现位置：platform/upload.ts（选图 / 压缩 / 上传，Mock 与真实切换）、composables/useUpload.ts（并发 3、自动重试 1 次、单张手动重试、上限 9）、pages-sub/order/after-sale/index.vue（凭证上传 UI 与提交拦截）。验证：upload.spec.ts 覆盖并发上限与重试；H5 售后页实测可新增凭证、进度展示、失败重试与删除。

场景 10：拼团状态机 ​

业务背景：团单经历「待成团 → 成团 → 超时退款」，并发参团、满员、超时都要有确定 UI 与错误码。

方案做法优点代价
A. 页面内 if/else 判断状态各页面自行拼装文案起步快状态爆炸、分支遗漏、无法复用
B. 显式状态机 + store 推进定义状态/事件/副作用表，定时器推进成团与退款可穷举、可测试需要状态机建模与定时器治理

选型：B。 实现位置：stores/marketing/group.ts、mock/handlers/group.ts（阶段四）。验证：2 人团在 1 人时展示「还差 1 人」；第 2 人加入立即成团；超时自动进入退款并刷新 UI；满员参团返回 GROUP_FULL。

场景 11：秒杀状态机与轮询 ​

业务背景：秒杀有「未开始 / 排队中 / 成功 / 售罄 / 失败」五态，必须处理排队 token、结果轮询、退避和防重复提交。

方案做法优点代价
A. 点击后等待接口返回单次请求 + 按钮文案简单长排队会超时、无法表达中间态
B. 五态状态机 + token 轮询退避排队拿 token，按 1s→2s→4s（上限 8s）轮询，终态停止状态清晰、可回滚需要轮询生命周期与页面隐藏处理

选型：B。 实现位置：stores/marketing/seckill.ts、mock/handlers/seckill.ts（阶段四）。验证：活动未开始按钮置灰并倒计时；排队中展示进度；成功后跳订单；售罄展示「已抢光」；页面隐藏停止轮询、回前台恢复。

场景 12：权限与曝光埋点 ​

业务背景：曝光埋点若在 mounted 触发，会把未进入视口的商品也计入；权限（相册/通知）需要统一判断。

方案做法优点代价
A. mounted 即上报页面加载后批量上报实现简单数据失真，无法归因真实曝光
B. 可见性触发 + 统一权限入口createIntersectionObserver / 页面可见性，去重后上报；权限统一封装数据可信、可归因需要曝光去重与观察器生命周期管理

选型：B，已落地。 实现位置：composables/useExposure.ts（观察器生命周期 + 可见上报）、utils/track.ts（dedupeKey 会话去重、20 条批量上报、失败写入本地队列并按指数退避重发、启动补发）、platform/permission.ts（getSetting → authorize → openSetting 引导）、pages/index/index.vue（首页瀑布流曝光接入）。验证：exposure.spec.ts 覆盖同 id 去重与重复 observe，track.spec.ts 覆盖失败保留、自动重发与重启恢复；H5 首页快速滑动只上报进入视口的商品；相册权限拒绝后弹出「去设置」引导。
