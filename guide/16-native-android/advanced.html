16.2 进阶应用：WXModule / WXComponent 与插件工程 ​

上一章解决了「环境与工程能跑」，这一章解决「插件怎么写」。uni-app 的 Android 插件只有两种形态：

  • WXModule：无 UI 的能力模块，JS 调 uni.requireNativePlugin('X').method(...)。
  • WXComponent：有 UI 的原生组件，只能在 .nvue 页面里使用，例如 <native-demo-view>。

两者都依赖 weex 的 WXSDKInstance，也都必须按 uni-app 的插件规范注册。

一、插件工程的最小闭环 ​

text
uni.requireNativePlugin('UniNativeDemo')
        │
        ▼
nativeplugins/UniNativeDemo/package.json     ← HBuilderX 读取插件描述
        │
        ▼
com.example.unidemo.NativeDemoModule          ← @JSMethod 暴露方法
        │
        ▼
Android SDK / 厂商 SDK

四件事必须对齐，否则插件「装了但调不到」：

  1. package.json 的 id 与 uni.requireNativePlugin('id') 一致。
  2. _dp_nativeplugin.android.plugins[].class 与真实全限定类名一致。
  3. 插件方法用 @JSMethod 注解，且方法参数顺序与 JS 调用一致。
  4. 产物是 .aar，并放在 nativeplugins/<id>/android/ 下。

二、WXModule：能力模块 ​

2.1 最小可用模块 ​

java
// nativeplugins/UniNativeDemo/android/src/main/java/com/example/unidemo/NativeDemoModule.java
package com.example.unidemo;

import android.content.Context;
import android.os.Build;
import android.widget.Toast;

import com.taobao.weex.annotation.JSMethod;
import com.taobao.weex.bridge.JSCallback;
import com.taobao.weex.common.WXModule;

import java.util.HashMap;
import java.util.Map;

public class NativeDemoModule extends WXModule {

    private static final String TAG = "UniNativeDemo";

    /**
     * JS 侧：
     * uni.requireNativePlugin('UniNativeDemo').getDeviceInfo({}, (res) => {...})
     */
    @JSMethod(uiThread = false)
    public void getDeviceInfo(Map<String, Object> options, JSCallback callback) {
        try {
            Map<String, Object> data = new HashMap<>();
            data.put("brand", Build.BRAND);
            data.put("model", Build.MODEL);
            data.put("osVersion", Build.VERSION.RELEASE);
            data.put("abi", Build.SUPPORTED_ABIS.length > 0 ? Build.SUPPORTED_ABIS[0] : "unknown");

            callback.invoke(makeResult(0, "ok", data));
        } catch (Exception e) {
            callback.invoke(makeResult(5001, e.getMessage(), null));
        }
    }

    /**
     * 必须弹 UI 的方法放在主线程
     */
    @JSMethod(uiThread = true)
    public void showToast(Map<String, Object> options, JSCallback callback) {
        Context ctx = mWXSDKInstance.getContext();
        if (ctx == null) {
            callback.invoke(makeResult(5002, "页面已销毁", null));
            return;
        }
        String text = options != null && options.get("text") != null
                ? String.valueOf(options.get("text"))
                : "Hello from native";
        Toast.makeText(ctx, text, Toast.LENGTH_SHORT).show();
        callback.invoke(makeResult(0, "ok", null));
    }

    private Map<String, Object> makeResult(int code, String message, Object data) {
        Map<String, Object> result = new HashMap<>();
        result.put("code", code);
        result.put("message", message);
        if (data != null) result.put("data", data);
        return result;
    }
}

2.2 @JSMethod 的两个关键点 ​

写法执行线程适用场景风险
@JSMethod(uiThread = true)主线程Toast、Dialog、View 操作耗时任务会卡 UI
@JSMethod(uiThread = false)JS/工作线程网络、文件、定位、SDK 初始化直接碰 UI 会崩

默认值在不同版本里可能是 true，永远显式写出来，不要依赖默认值。

2.3 回调：一次性 vs 保活 ​

java
// 一次性：调用后即释放，适合「查一次设备信息」
callback.invoke(result);

// 保活：可多次回调，适合「定位持续上报」「扫码连续回调」
callback.invokeAndKeepAlive(result);

保活回调必须自己管理释放：

java
private JSCallback locationCallback;

@JSMethod(uiThread = false)
public void startLocation(Map<String, Object> options, JSCallback callback) {
    locationCallback = callback;
    // ... 启动定位
}

@JSMethod(uiThread = false)
public void stopLocation() {
    if (locationCallback != null) {
        locationCallback.invokeAndKeepAlive(makeResult(0, "stopped", null));
        locationCallback = null; // 断开引用，避免页面销毁后仍持有 JS 回调
    }
}

内存泄漏的高发点：把 JSCallback 存进 static 变量或单例。页面关闭后回调对象仍被持有，最终导致整个 WebView 无法释放。

2.4 Context 与权限 ​

Android 6.0+ 的敏感权限必须运行时申请。插件里先检查，再决定是否继续：

java
private boolean hasPermission(String permission) {
    Context ctx = mWXSDKInstance.getContext();
    return ctx != null && ctx.checkSelfPermission(permission) == android.content.pm.PackageManager.PERMISSION_GRANTED;
}

@JSMethod(uiThread = true)
public void requestCamera(Map<String, Object> options, JSCallback callback) {
    Context ctx = mWXSDKInstance.getContext();
    if (ctx == null) {
        callback.invoke(makeResult(5002, "页面已销毁", null));
        return;
    }
    if (hasPermission(android.Manifest.permission.CAMERA)) {
        callback.invoke(makeResult(0, "already granted", null));
        return;
    }
    // 注意：结果回调需要宿主 Activity 转发 onRequestPermissionsResult，
    // 或改用 androidx.activity 的 ActivityResultLauncher（推荐）
    callback.invoke(makeResult(2001, "需要用户在宿主中确认权限", null));
}

权限相关的工程约定：

  • AndroidManifest.xml 里声明 <uses-permission>，否则运行时申请直接失败。
  • 权限被拒绝后要有降级路径，不能一直转圈。
  • 高德 / 相机 / 定位等 SDK 还要在 Application 或 init 阶段设置隐私合规接口。

三、WXComponent：原生 UI 组件 ​

3.1 什么时候必须用 WXComponent ​

需求方案
纯逻辑、无 UIWXModule
原生地图 / 相机预览 / 视频硬解WXComponent（nvue）
页面里嵌入原生 ViewWXComponent + nvue
只是浮层 / 蒙层plus.nativeObj.View（见 18.2）

WXComponent 只能用于 nvue 页面，普通 vue 页面无法渲染原生组件。

3.2 原生组件骨架 ​

java
// nativeplugins/UniNativeDemo/android/src/main/java/com/example/unidemo/NativeDemoView.java
package com.example.unidemo;

import android.content.Context;
import android.graphics.Color;
import android.view.ViewGroup;
import android.widget.FrameLayout;
import android.widget.TextView;

import androidx.annotation.NonNull;

import com.taobao.weex.WXSDKInstance;
import com.taobao.weex.dom.WXDomObject;
import com.taobao.weex.ui.component.WXComponent;
import com.taobao.weex.ui.component.WXComponentProp;
import com.taobao.weex.ui.component.WXVirtualDom;

public class NativeDemoView extends WXComponent<FrameLayout> {

    private TextView label;

    // 构造签名随 weex-core 版本略有差异，以离线 SDK 中的 WXComponent 为准
    public NativeDemoView(WXSDKInstance instance, WXDomObject dom, WXVirtualDom virtualDom,
                          String type, int ref, boolean isHostView, WXSDKInstance rootInstance) {
        super(instance, dom, virtualDom, type, ref, isHostView, rootInstance);
    }

    @Override
    protected FrameLayout initComponentHostView(@NonNull Context context) {
        FrameLayout container = new FrameLayout(context);
        label = new TextView(context);
        label.setTextColor(Color.WHITE);
        label.setTextSize(16);
        container.addView(label, new FrameLayout.LayoutParams(
                ViewGroup.LayoutParams.WRAP_CONTENT,
                ViewGroup.LayoutParams.WRAP_CONTENT));
        return container;
    }

    @WXComponentProp(name = "label")
    public void setLabel(String text) {
        if (label != null) label.setText(text);
    }

    @WXComponentProp(name = "bgColor")
    public void setBgColor(String color) {
        if (getHostView() != null) {
            getHostView().setBackgroundColor(Color.parseColor(color));
        }
    }
}

nvue 页面使用：

vue
<!-- pages/native/native-demo.nvue -->
<template>
  <view class="page">
    <native-demo-view
      label="原生组件"
      bg-color="#007aff"
      style="width: 300rpx; height: 120rpx;"
    />
  </view>
</template>

<script setup>
// 自定义原生组件无需 import，由运行时按 package.json 注册名解析
</script>

标签名 native-demo-view 与 _dp_nativeplugin 里的 name: "NativeDemoView" 对应：大驼峰转 kebab-case。如果注册名不一致，页面会静默渲染为空。

3.3 原生组件事件 ​

java
// 在 initComponentHostView 或 viewDidLoad 中绑定
getHostView().setOnClickListener(v -> {
    Map<String, Object> params = new HashMap<>();
    params.put("timestamp", System.currentTimeMillis());
    fireEvent("onNativeClick", params);
});
vue
<native-demo-view @onNativeClick="onNativeClick" />

事件名建议加业务前缀（onNativeClick），避免与内置事件冲突。

3.4 生命周期与销毁 ​

java
@Override
public void onActivityDestroy() {
    super.onActivityDestroy();
    // 释放传感器、相机、地图、监听器
}

WXComponent 在页面销毁时会被回收，但你手动注册的全局监听器不会被自动注销。相机、传感器、定位、广播接收器都必须在 onActivityDestroy 或 destroy 时释放。

jsonc
{

        "androidx.core:core:1.13.1"
      ]
    },
    "ios": {
      "plugins": [
        {
          "type": "module",
          "name": "UniNativeDemo",

      "integrateType": "framework",
      "deploymentTarget": "13.0"
    }
  }
}

字段解释：

字段必填说明
id✅JS 侧 requireNativePlugin 的 key
name✅展示名；组件名同时决定 nvue 标签名
_dp_type✅固定 nativeplugin
integrateType✅Android 用 aar，iOS 用 framework
plugins[].type✅module 或 component
abis建议控制打包进基座的 ABI
dependencies可选Gradle / CocoaPods 依赖
deploymentTargetiOS 建议最低系统版本

五、调试与排错 ​

5.1 三个必查项 ​

js
// 1. 插件是否被找到
const plugin = uni.requireNativePlugin('UniNativeDemo')
console.log('plugin keys:', Object.keys(plugin || {}))
  • 输出空对象：插件没打进基座，或 id 写错。
  • 有对象但方法 undefined：plugins[].class 与真实类名不一致，或方法没有 @JSMethod。
  • 调用后无回调：方法内部异常被吞掉，用 adb logcat -s UniNativeDemo 看日志。

5.2 自定义调试基座 ​

  1. HBuilderX → 运行 → 运行到手机或模拟器 → 制作自定义调试基座。
  2. 勾选本地插件 UniNativeDemo。
  3. 打出的基座安装到真机，再「运行到自定义基座」。
  4. 每次改 Java/资源都要重新打基座；只改 JS 不需要。

5.3 常见坑 ​

现象原因处理
requireNativePlugin 返回 {}插件未打入 / id 不一致检查基座插件列表与 package.json
ClassNotFoundException类名、包名、aar 未打包adb logcat 看完整堆栈
NoSuchMethodError宿主与插件版本不一致统一依赖版本，重新打基座
Duplicate class插件把 weex 打进 aar改为 compileOnly
原生组件空白使用了 vue 页面改 .nvue 页面
回调不触发页面已销毁 / 回调被 GC判空 + 避免 static 持有
