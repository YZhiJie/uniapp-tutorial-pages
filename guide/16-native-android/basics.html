16.1 基础入门：Android 原生开发环境与工程结构 ​

写 uni-app 的 App 端功能，前期可以只写 Vue；一旦要接厂商 SDK、自研插件、离线打包，就绕不开 Android 原生开发。本章的目标不是把你培养成 Android 工程师，而是让你能看懂原生工程、能改插件代码、能定位构建与运行时问题。

先明确边界：uni-app 的 App 端是「HTML5+ 运行时 + 原生插件」的混合体。你的 Vue 代码运行在 WebView / 原生渲染层，真正碰硬件、碰系统 API 的部分由原生模块（Android 的 WXModule / WXComponent）完成。所以 Android 侧要掌握的是 工程与桥接的最小闭环，而不是从零学一遍 Android 应用开发。

一、Android 技术栈分层 ​

mermaid
flowchart TB
    A[你的 Vue / TS 代码] --> B[uni-app 运行时<br/>HTML5+ / weex]
    B --> C{需要原生能力?}
    C -- 否 --> D[uni.* / plus.* API]
    C -- 是 --> E[WXModule / WXComponent]
    E --> F[Android SDK / 厂商 SDK]
    F --> G[Android Framework]
    G --> H[Linux Kernel]

对应到工程里，你会同时遇到四层：

层你接触到的文件你需要会什么
业务层.vue / .ts已有 Vue 基础即可
桥接层WXModule.java / WXComponent.java注解、回调、线程切换
原生库层.aar / .jar / jniLibs/*.soGradle 依赖、ABI
宿主工程build.gradle / AndroidManifest.xml构建、权限、签名

二、环境搭建：JDK、Android Studio、SDK、Gradle ​

2.1 版本选择（2026 年仍稳定的组合） ​

组件推荐版本说明
JDK17AGP 8.x 要求 JDK 17；不要用 JDK 21 赌兼容性
Android StudioLadybug / Meerkat 及以上自带 SDK Manager 与模拟器
Android Gradle Plugin8.5–8.7与 Gradle 8.7+ 配套
Gradle8.7–8.9用 Wrapper 固定版本，不要用系统全局 Gradle
compileSdk / targetSdk34 / 34上架要求持续提高，按当年商店政策调整
minSdk21–23uni-app 离线模板通常 21 起

企业项目里把版本写进 gradle/libs.versions.toml 或根 build.gradle，并在 CI 里固定 JDK，避免「我本地能编，CI 编不过」。

2.2 安装与验证 ​

bash
# macOS 安装 JDK 17（也可用 Android Studio 内置 JBR）
brew install --cask temurin@17

# 配置环境变量（写入 ~/.zshrc）
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin

# 验证
java -version
adb version
sdkmanager --list | head

安装 SDK 组件：

bash
sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"

常见坑：

  • JAVA_HOME 指向 JRE 而不是 JDK：java -version 正常，但 Gradle 报 No compiler。
  • 只装了 Android Studio，没装 Command Line Tools：CI / 脚本里找不到 sdkmanager。
  • 公司网络需要代理：在 ~/.gradle/gradle.properties 配 systemProp.https.proxyHost / proxyPort。

三、工程目录结构：一个最小可编译的 Android 库 ​

原生插件通常以 Android Library 形式产出 .aar，目录如下：

text
UniNativeDemo/
├── android/
│   ├── build.gradle                 # library 模块构建脚本
│   ├── settings.gradle
│   ├── gradle.properties
│   └── src/main/
│       ├── AndroidManifest.xml      # 库清单（权限、provider 等）
│       ├── java/com/example/unidemo/
│       │   ├── NativeDemoModule.java
│       │   └── NativeDemoView.java
│       ├── res/                     # 资源（布局、drawable）
│       └── jniLibs/                 # 可选：第三方 .so
├── package.json                     # uni-app 插件描述（_dp_nativeplugin）
└── ios/                             # iOS 插件源码（见模块十七）

关键文件职责：

文件作用最容易出错的地方
settings.gradle声明模块忘记 include ':android'
android/build.gradle依赖、编译版本、混淆compileSdk 与宿主不一致
AndroidManifest.xml权限、<application> 合并权限没声明导致运行时崩溃
package.json告诉 HBuilderX 插件类名与集成方式class 与真实包名不一致

3.1 android/build.gradle 模板 ​

groovy
plugins {
    id 'com.android.library'
}

android {
    namespace 'com.example.unidemo'
    compileSdk 34

    defaultConfig {
        minSdk 21
        targetSdk 34
        consumerProguardFiles 'consumer-rules.pro'
    }

    compileOptions {
        sourceCompatibility JavaVersion.VERSION_17
        targetCompatibility JavaVersion.VERSION_17
    }
}

dependencies {
    // uni-app 离线打包 SDK 中已包含 weex / WXModule，编译期用 provided 避免重复打包
    compileOnly files('libs/weex_core.jar')       // 实际路径以离线 SDK 为准
    implementation 'androidx.appcompat:appcompat:1.7.0'
    implementation 'androidx.core:core:1.13.1'
}

WXModule、JSCallback、WXSDKInstance 来自 weex / uni-app 运行时。做离线打包时这些类在宿主工程里已经存在，插件里应使用 compileOnly / provided，否则会出现 Duplicate class。

四、Kotlin / Java 必须掌握的最小语法 ​

插件代码可以用 Java，也可以用 Kotlin。uni-app 官方示例与插件市场以 Java 居多，排错时你必须能读 Java；新写的插件推荐 Kotlin。

4.1 类、属性、空安全 ​

kotlin
// Kotlin：data class 自动生成 equals/hashCode/copy
data class DeviceInfo(
    val model: String,
    val osVersion: String,
    val abi: String
)

class DemoBridge {
    var callback: ((DeviceInfo) -> Unit)? = null

    fun emit(info: DeviceInfo) {
        callback?.invoke(info)   // ?. 安全调用，避免 NPE
    }
}

Java 对应写法：

java
public final class DeviceInfo {
    public final String model;
    public final String osVersion;
    public final String abi;

    public DeviceInfo(String model, String osVersion, String abi) {
        this.model = model;
        this.osVersion = osVersion;
        this.abi = abi;
    }
}

4.2 接口、匿名类、Lambda ​

kotlin
// Kotlin
val listener = object : View.OnClickListener {
    override fun onClick(v: View?) { /* ... */ }
}
java
// Java 8+ Lambda
View.OnClickListener listener = v -> { /* ... */ };

4.3 协程 vs 线程 ​

场景推荐原因
网络 / 文件 / 数据库Dispatchers.IO 协程自动取消、结构化并发
必须回调主线程withContext(Dispatchers.Main)更新 UI 只能在主线程
老代码 / 简单任务Thread + Handler兼容性好，但容易泄漏
kotlin
// 在 WXModule 里做异步任务的标准写法（Kotlin）
@JSMethod(uiThread = false)
fun loadData(callback: JSCallback) {
    CoroutineScope(Dispatchers.IO).launch {
        val result = runCatching { repository.fetch() }
        withContext(Dispatchers.Main) {
            result.onSuccess { callback.invoke(mapOf("code" to 0, "data" to it)) }
                  .onFailure { callback.invoke(mapOf("code" to 5001, "message" to it.message)) }
        }
    }
}

五、Activity、Context 与生命周期 ​

5.1 Context 三种形态 ​

类型获取方式能做什么不能做什么
Application ContextmWXSDKInstance.getContext().getApplicationContext()启动服务、读资源、初始化 SDK弹 Dialog、启动 Activity（需 FLAG）
Activity ContextmWXSDKInstance.getContext()弹窗、申请权限、启动 Activity长期持有（会泄漏）
Service ContextService 内 this后台任务UI 相关

最常见的内存泄漏：单例 / 静态变量持有 Activity Context。插件里保存 Context 时，一律转成 applicationContext，需要 UI 时再从 mWXSDKInstance 取当前 Activity。

5.2 Activity 生命周期与插件的关系 ​

text
onCreate → onStart → onResume → onPause → onStop → onDestroy

插件常见问题：

  • 在 onCreate 之前调用 mWXSDKInstance.getContext()，拿到 null。
  • 页面切后台后原生回调仍在跑，回来时 View 已销毁 → WindowManager.BadTokenException。
  • 申请权限的回调绑在 Activity，页面销毁后回调丢失。

解决思路：所有异步回调都加 页面存活判断：

java
if (mWXSDKInstance == null || mWXSDKInstance.getContext() == null) {
    return; // 页面已销毁，丢弃结果
}

5.3 主线程模型 ​

Android 只有 UI 线程能改 View。@JSMethod(uiThread = false) 表示方法在 JS 线程/工作线程执行，任何 UI 操作都必须切回主线程：

java
activity.runOnUiThread(() -> {
    Toast.makeText(activity, "来自原生插件", Toast.LENGTH_SHORT).show();
});

6.2 Android Studio 断点调试原生插件 ​

  1. 用 Android Studio 打开 nativeplugins/UniNativeDemo/android。
  2. 选择 app（宿主离线工程）或把插件模块 implementation project(':android') 引入宿主。
  3. Run/Debug Configuration 选择 app，Deploy 到真机。
  4. 在 NativeDemoModule 方法里下断点，触发 JS 调用即可命中。
  5. 若断点不命中：确认宿主用的是 debug 基座，且插件代码与基座里的代码一致（改完插件必须重新打基座）。

云打包 / 正式包默认不可调试。日常开发用「自定义调试基座」；问题复现用 adb logcat + 崩溃堆栈。

七、ABI 与 64 位要求 ​

ABI设备是否必选
arm64-v8a现代真机（几乎所有）必须
armeabi-v7a老设备 / 部分低端机建议保留
x86_64模拟器 / Chromebook调试可选
  • Google Play 与国内商店普遍要求 64 位包；只打 armeabi-v7a 会被拒。
  • 第三方 SDK 的 .so 必须覆盖你声明的 ABI，否则运行时报 UnsatisfiedLinkError。
  • 用 abiFilters 控制产物，避免把不需要的 ABI 打进去：
groovy
android {
    defaultConfig {
        ndk {
            abiFilters 'arm64-v8a', 'armeabi-v7a'
        }
    }
}

uni-app 侧Android 侧说明
