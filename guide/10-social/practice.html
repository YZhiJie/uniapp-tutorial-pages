10.3 实战案例：WebSocket 封装与离线消息 ​

10.2 的 Socket 客户端解决了「能连能发」，本篇解决「任何网络条件下消息不丢、不重、有序」。

一、重连策略完善 ​

指数退避 + 随机抖动 ​

固定间隔重连会造成「服务重启后所有客户端同时重连」的惊群。加抖动：

ts
private scheduleReconnect(token: string) {
  if (this.retry >= 8) {
    // 超过上限转为网络状态监听驱动（uni.onNetworkStatusChange）
    return
  }
  const base = Math.min(1000 * 2 ** this.retry, 30000)
  const delay = base + Math.random() * 1000
  this.retry++
  this.reconnectTimer = setTimeout(() => this.connect(token), delay)
}

网络状态驱动 ​

ts
uni.onNetworkStatusChange((res) => {
  if (res.isConnected && state === State.Closed) {
    connect()
  }
})

二、心跳与僵尸连接检测 ​

TCP 断网未必触发 onClose（尤其 App 切后台/电梯场景）。没有心跳，连接可能「看起来开着、实际已死」。

ts
private startHeartbeat() {
  this.stopHeartbeat()
  let pongMissing = 0
  this.heartbeatTimer = setInterval(() => {
    this.send({ type: 'ping' })
      .then(() => {
        pongMissing = 0
      })
      .catch(() => {
        if (++pongMissing >= 2) this.forceReconnect()
      })
  }, 25000)
}

服务端收到 ping 回 pong（或任意下行帧都可视为连接存活）。参数权衡：

  • 心跳越短，发现死亡越快，但更耗电；IM 场景 20–30s 是常见区间。
  • App 后台期间停止心跳，回前台立即探测一次。

前后台切换补偿 ​

ts
// #ifdef APP-PLUS
document.addEventListener('resume', onForeground) // nvue/plus 环境用对应生命周期
// #endif
// 通用：uni.onAppShow / onAppHide
uni.onAppShow?.(onForeground)

async function onForeground() {
  if (!isAlive()) await reconnect()
  // 无论是否重连，都拉一次增量，覆盖后台期间丢消息的窗口
  syncOfflineSince(lastSyncAt)
}

三、离线消息同步窗口 ​

核心思想：客户端记录最后一条已确认消息的序号（服务端单调递增 seq），重连/回前台时带上 seq 拉增量。

ts
// src/services/im/sync.ts
const SEQ_KEY = 'im:lastSeq'

export function getLastSeq(): number {
  return uni.getStorageSync(SEQ_KEY) || 0
}
export function saveLastSeq(seq: number) {
  const current = getLastSeq()
  if (seq > current) uni.setStorageSync(SEQ_KEY, seq)
}

export async function syncOfflineSince(seq = getLastSeq()): Promise<ChatMessageDTO[]> {
  const res = await http.get<{ messages: ChatMessageDTO[]; maxSeq: number }>('/im/sync', {
    data: { after: seq } as unknown as Record<string, unknown>
  })
  // 去重入库
  res.messages.forEach((dto) => imStore.dispatchIncoming(dto))
  saveLastSeq(res.maxSeq)
  return res.messages
}

握手时服务端也可以直接在连接建立的首个响应中携带 miss 消息，减少一次往返：

ts
this.task.onOpen(async () => {
  this.retry = 0
  this.startHeartbeat()
  await this.send({ type: 'hello', lastSeq: getLastSeq() })
  // 服务端回 welcome 帧带增量；同时保留 HTTP 兜底通道
})

去重靠 clientId/serverId 双轨：

  • 上行：消息在 ack 前重发（重连后自动补发 sending 队列），服务端按 clientId 幂等。
  • 下行：按 seq 去重，乱序到达时按 seq 排序入库。

四、发送可靠性：sending 队列持久化 ​

弱网下杀进程，未发出的消息也要保留：

ts
// 消息入队时
function persistOutbox(messages: Message[]) {
  uni.setStorageSync('im:outbox', messages.filter((m) => m.status === 'sending'))
}

// 连接成功后
async function flushOutbox() {
  const outbox: Message[] = uni.getStorageSync('im:outbox') || []
  for (const msg of outbox) {
    try {
      await imSocket.send({ type: 'message', clientId: msg.id, conversationId: msg.conversationId, content: msg.content })
    } catch {
      break // 连接再次中断，等下次
    }
  }
}

状态流转：sending → sent（发出）→ delivered（ack）→ read（已读回执），任何一步失败都可定位重发位置。

五、平台通知适配（离线触达） ​

连接不在线时，消息要走平台通道，封装统一适配层：

ts
// src/platforms/push/index.ts
// #ifdef MP-WEIXIN
export async function requestMessageNotify(templateIds: string[]) {
  return new Promise<boolean>((resolve) => {
    wx.requestSubscribeMessage({
      tmplIds: templateIds,
      success: (res) => resolve(templateIds.every((id) => res[id] === 'accept')),
      fail: () => resolve(false)
    })
  })
}
// #endif
// #ifdef APP-PLUS
export async function requestMessageNotify() {
  // UniPush 开通后获取 pushClientId 上报服务端
  return new Promise((resolve) => {
    uni.getPushClientId({
      success: (res) => {
        http.post('/im/push/register', { clientId: res.cid })
        resolve(true)
      },
      fail: () => resolve(false)
    })
  })
}
// #endif
// #ifdef H5
export async function requestMessageNotify() {
  return false // H5 无可靠离线通知，产品上降级为站内未读
}
// #endif

服务端推送策略（产品侧要明确）：

  • 单聊消息：在线走 WS；离线推平台通知。
  • 群消息：只推「免打扰关闭」的会话，并做折叠（「群里有 3 条新消息」而不是连发 3 条）。
  • 用户点通知进入应用：根据推送 payload 路由到对应聊天页（冷启动参数在 onLaunch(options) 处理）。

六、完整状态机（Socket 生命周期） ​

text
Idle → Connecting → Open ⇄ Closed(可重连)
                      │
                      ├─ 心跳失败 ×2 → Reconnecting（指数退避+抖动）
                      ├─ onClose(非主动) → Reconnecting
                      ├─ App 后台 → Suspended（停心跳）
                      └─ App 回前台 → 探活/重连 + syncOffline
主动登出 → Closed(不重连)

把状态显式化（而不是只用一个布尔值），UI 可以展示「连接中…」「网络不可用」等状态，重发逻辑也有据可依。

综合练习 ​

  1. 断线实验：用开发者工具的 Offline 开关，完成「发消息 → 断网 → 杀进程 → 重启 → 联网」全流程，验证消息不丢不重。
  2. 乱序实验：模拟服务端乱序推送 seq=10、seq=9，验证会话排序与未读计数正确。
  3. 多端一致性：同一账号两台设备，A 已读后 B 的未读角标应清零，设计这个回执同步帧。
  4. 给聊天页增加本地搜索（历史消息检索），注意大消息量下的索引与分页。
