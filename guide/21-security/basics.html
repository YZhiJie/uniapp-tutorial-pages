21.1 基础入门：客户端不可信模型与密钥生命周期 ​

前端安全的第一原则：客户端是公开环境。安装包能被反编译、H5 能被调试、小程序包能被解包、本地存储能被读取。任何下发到客户端的「密钥」都应视为已泄露。

本篇建立威胁模型，并给出密钥与令牌的生命周期规范。

一、威胁模型：先分清什么能信任 ​

资产存放位置攻击者能否获取结论
微信 appSecret若写在客户端能（解包即得）绝不下发，只存服务端
支付商户私钥若写在客户端能绝不下发，签名在服务端完成
数据库密码客户端配置能绝不下发
用户 access token本地存储能（越狱/调试）可下发，但必须短时效、可撤销、绑定用户
接口签名密钥客户端能只能作为「防重放」手段，不能当身份凭证
业务数据内存 / 存储部分能敏感字段不明文落盘、不写日志

由此推出三条硬规则：

  1. 需要长期保密的秘密，永远不进客户端。
  2. 客户端的任何校验都只是体验优化，服务端必须再校验一次。
  3. 令牌按最小权限签发，能撤销、能轮换、能审计。

二、常见反模式 ​

ts
// ❌ appSecret 进入前端包：解包即泄露，可直接调用微信接口
const APP_SECRET = 'a1b2c3d4...'
uni.request({ url: `https://api.weixin.qq.com/sns/jscode2session?secret=${APP_SECRET}` })

// ✅ 只把 code 发给自己的服务端，由服务端换取 openid
uni.request({ url: '/api/auth/wechat', method: 'POST', data: { code } })
ts
// ❌ 把「管理员标识」存本地，前端据此显示管理入口
if (uni.getStorageSync('isAdmin')) showAdminPanel()

// ✅ 权限由服务端下发能力列表，入口只是展示；操作时服务端再鉴权
const { abilities } = await authApi.profile()
if (abilities.includes('order:refund')) showRefundButton()

三、令牌生命周期 ​

推荐双令牌模型：

令牌时效存储用途
access token15–30 分钟内存优先，必要时本地存储调业务接口
refresh token7–30 天原生安全存储 / 小程序 storage换新 access token，只调用刷新接口

3.1 单飞刷新：避免并发请求各刷一次 ​

ts
// src/services/token.ts
interface Session {
  accessToken: string
  refreshToken: string
  expiresAt: number
}

let session: Session | null = null
let refreshing: Promise<Session> | null = null

export function setSession(next: Session | null) {
  session = next
}

export function getAccessToken() {
  if (!session) return null
  // 提前 60 秒刷新，避免临界过期
  if (session.expiresAt - Date.now() < 60_000) return null
  return session.accessToken
}

export function refreshSession(): Promise<Session> {
  if (refreshing) return refreshing
  const current = session
  if (!current) return Promise.reject(new Error('NO_SESSION'))

  refreshing = new Promise<Session>((resolve, reject) => {
    uni.request({
      url: '/api/auth/refresh',
      method: 'POST',
      data: { refreshToken: current.refreshToken },
      success: (res) => {
        const next = res.data as Session
        setSession(next)
        resolve(next)
      },
      fail: (err) => reject(new Error(err.errMsg))
    })
  }).finally(() => {
    refreshing = null
  })

  return refreshing
}

请求层遇到 401 时统一走 refreshSession()，多个并发 401 只会触发一次刷新：

ts
async function requestWithAuth<T>(config: RequestConfig): Promise<T> {
  const token = getAccessToken()
  try {
    return await request<T>({ ...config, header: { ...config.header, Authorization: `Bearer ${token}` } })
  } catch (err) {
    if (!isUnauthorized(err)) throw err
    const next = await refreshSession()
    return request<T>({
      ...config,
      header: { ...config.header, Authorization: `Bearer ${next.accessToken}` }
    })
  }
}

3.2 存储选择 ​

端推荐存储原因
微信小程序uni.setStorage（短期 token）无系统级安全存储，靠短时效 + 服务端风控
H5内存 + sessionStorage，避免长期 localStorage降低 XSS 窃取窗口
App原生安全存储（Keychain / Keystore）系统级加密，卸载可清理

任何端都不要把 token 拼进 URL（会进浏览器历史、Nginx 日志、Referer）。

3.3 令牌吊销与轮换 ​

  • 用户改密、退出登录、检测到异地登录时，服务端立即吊销 refresh token。
  • refresh token 一次性使用：每次刷新返回新的 refresh token，旧的立即失效（检测重放）。
  • 记录签发设备指纹与时间，异常刷新进入风控队列。

四、密钥生命周期（服务端视角） ​

阶段要求
生成使用 CSPRNG（crypto.randomBytes），长度 ≥ 256 bit，禁止时间戳/自增
分发通过密钥管理服务 / CI secrets 注入，禁止写进仓库与镜像
使用最小权限、按环境隔离（测试密钥不得用于生产）
轮换支付/开放平台密钥至少每年轮换；支持双密钥并行过渡
吊销泄露时立即吊销并审计调用记录；保留 90 天操作日志
销毁旧密钥从所有环境删除，确认无调用后归档审计记录

五、日志与埋点脱敏 ​

ts
// src/services/log.ts
const MASK_KEYS = ['token', 'authorization', 'password', 'phone', 'idCard', 'appSecret']

export function maskSensitive(input: Record<string, unknown>) {
  const out: Record<string, unknown> = {}
  for (const [key, value] of Object.entries(input)) {
    if (MASK_KEYS.some((k) => key.toLowerCase().includes(k))) {
      out[key] = '***'
    } else if (typeof value === 'string' && value.length > 6) {
      // 手机号 / 身份证保留首尾，便于排查又不泄露
      out[key] = `${value.slice(0, 3)}***${value.slice(-2)}`
    } else {
      out[key] = value
    }
  }
  return out
}

埋点上报前统一过 maskSensitive；服务端日志同样要过滤 Authorization 头。

六、验收标准 ​

bash
# 1. 仓库内不存在真实密钥（示例占位符需登记）
pnpm security:scan

# 2. 依赖无高危漏洞（需要网络）
pnpm security:scan:deps

自查清单：

  • 全仓库搜索 appSecret、privateKey、secretKey，确认只出现在服务端目录与文档示例。
  • 退出登录后，旧 access token 在服务端立即失效（用 curl 验证返回 401）。
  • 并发 5 个 401 请求，刷新接口只被调用 1 次（看服务端日志）。
  • 日志中搜不到完整 token、手机号、身份证号。
