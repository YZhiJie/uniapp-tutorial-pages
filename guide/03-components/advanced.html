3.2 进阶应用：自定义组件与六种组件通信方式 ​

easycom：约定优于配置 ​

把组件放在 src/components/组件名/组件名.vue，即可在任意页面直接使用、无需 import：

text
src/components/
└─ tag-pill/
   └─ tag-pill.vue
vue
<!-- 任意页面，无需 import 与注册 -->
<tag-pill text="Pinia" type="primary" />

easycom 规则在 pages.json 中可扩展（例如让 uni-ui 组件自动引入）：

jsonc
{
  "easycom": {
    "autoscan": true,
    "custom": {
      "^uni-(.*)": "@dcloudio/uni-ui/lib/uni-$1/uni-$1.vue"
    }
  }
}

TIP

easycom 只自动注册组件，composables（useXxx）、工具函数仍需手动 import。

方式一：props / emits（父子通信的默认答案） ​

封装一个标签胶囊：

vue
<!-- components/tag-pill/tag-pill.vue -->
<template>
  <view
    class="pill"
    :class="`pill--${type}`"
    @tap="$emit('select', text)"
  >
    {{ text }}
    <text v-if="closable" class="pill__close" @tap.stop="$emit('close', text)">×</text>
  </view>
</template>

<script setup lang="ts">
withDefaults(
  defineProps<{
    text: string
    type?: 'default' | 'primary' | 'danger'
    closable?: boolean
  }>(),
  { type: 'default', closable: false }
)

defineEmits<{
  select: [text: string]
  close: [text: string]
}>()
</script>

父组件：

vue
<tag-pill text="Pinia" type="primary" @select="onSelectTag" />

单向数据流原则：props 只读，修改由父组件通过事件完成。

方式二：v-model 双向绑定 ​

自定义 search-bar：

vue
<!-- components/search-bar/search-bar.vue -->
<template>
  <view class="search">
    <input
      :value="modelValue"
      @input="$emit('update:modelValue', $event.detail.value)"
    />
  </view>
</template>

<script setup lang="ts">
defineProps<{ modelValue: string }>()
defineEmits<{ 'update:modelValue': [value: string] }>()
</script>
vue
<search-bar v-model="keyword" />
<!-- 等价于 :model-value + @update:model-value -->

多个双向值可用 v-model:foo（Vue 3 具名 model），如 v-model:start、v-model:end。

方式三：插槽（内容分发） ​

vue
<!-- components/card-box/card-box.vue -->
<template>
  <view class="card">
    <view class="card__header">
      <slot name="title">默认标题</slot>
    </view>
    <view class="card__body">
      <slot :item="item" />
    </view>
    <view class="card__footer">
      <slot name="footer" />
    </view>
  </view>
</template>

<script setup lang="ts">
defineProps<{ item: { id: number; name: string } }>()
</script>

作用域插槽让父组件拿到子组件内部数据：

vue
<card-box :item="goods">
  <template #title><text>商品信息</text></template>
  <template #default="{ item }">
    <text>{{ item.name }}</text>
  </template>
</card-box>

方式四：provide / inject（跨层级依赖注入） ​

适合「主题、用户信息、地图实例」这类多层透传数据，避免 props 逐层钻取：

ts
// 父页面
import { provide, ref } from 'vue'
const theme = ref<'light' | 'dark'>('light')
provide('theme', theme) // 建议用 Symbol 作为 key，大型项目可用 InjectionKey<T> 类型化
ts
// 任意深层子组件
import { inject, type Ref } from 'vue'
const theme = inject<Ref<'light' | 'dark'>>('theme')!

纪律：provide 的数据尽量由提供方修改；如需子改父，provide 一个带 action 的对象（或 provide 函数）。

方式五：事件总线 / 全局状态（无直接关系的组件） ​

  • 跨页面、兄弟组件共享业务状态：直接上 Pinia（模块 6），不要自造事件总线。
  • 页面 A 跳转到页面 B 后需要单次回传：使用 uni.navigateTo 的 events 通道（5.2）。
  • 仅在纯组件库内部、确实需要发布订阅时，才使用 mitt 等库：
ts
import mitt from 'mitt'
export const bus = mitt<{ refresh: { tab: string } }>()
// 组件内 bus.emit('refresh', { tab: 'cart' }) / bus.on('refresh', handler)
// 务必在 onUnmounted 中 off，否则内存泄漏

方式六：模板 ref / defineExpose（父调子） ​

子组件显式暴露方法：

vue
<!-- components/stepper/stepper.vue -->
<script setup lang="ts">
import { ref } from 'vue'
const count = ref(0)
function reset() {
  count.value = 0
}
defineExpose({ count, reset }) // 不暴露则父组件拿不到任何内部成员
</script>
vue
<stepper ref="stepperRef" />
ts
import { ref } from 'vue'
const stepperRef = ref<InstanceType<typeof Stepper> | null>(null)
stepperRef.value?.reset()

通信方案选型速查 ​

场景首选
父向子传展示数据props
子通知父事件emits
表单式双向值v-model
父向子传任意 UI 片段插槽
祖孙多层透传provide/inject
跨页面/全局业务状态Pinia
跳转页之间单次通信navigateTo events
父组件命令调子组件defineExpose + ref

组件设计建议 ​

  1. props 设计原子化：布尔开关 + 枚举类型优先，不要把整个接口对象丢给组件。
  2. 组件内不发请求：展示型组件数据来自 props；请求在页面或 store 完成，便于复用与测试。
  3. 样式隔离：优先 scoped；跨端主题用 CSS 变量（--brand），避免深层选择器。
  4. 命名：多词组件名（tag-pill 而非 tag），既符合 easycom 目录约定，也避免与内置标签冲突。
