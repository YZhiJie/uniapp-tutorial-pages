2.2 进阶应用：CLI + Vite + TypeScript 工程化环境 ​

团队协作与 CI/CD 场景应使用 CLI 工程：编辑器自由、依赖透明、构建命令可进流水线。本篇全程使用 pnpm。

前置条件 ​

  • Node.js LTS（建议 20 及以上）
  • pnpm 9+（npm i -g pnpm 或 corepack enable 后 corepack prepare pnpm@latest --activate）
  • 微信开发者工具（小程序端）、HBuilderX（App 真机/打包仍需要）

创建项目 ​

官方模板（Vue 3 + Vite + TS）：

bash
npx degit dcloudio/uni-preset-vue#vite-ts my-uniapp-app
cd my-uniapp-app
pnpm install

package.json 中的关键脚本（模板可能随版本微调，以实际为准）：

jsonc
{
  "scripts": {
    "dev:h5": "uni",
    "dev:mp-weixin": "uni -p mp-weixin",
    "build:h5": "uni build",
    "build:mp-weixin": "uni build -p mp-weixin",
    "dev:app": "uni -p app",
    "dev:app-android": "uni -p app-android",
    "dev:app-ios": "uni -p app-ios"
  }
}

常用平台标识：h5、mp-weixin、mp-alipay、mp-toutiao、app（App 资源，真机运行与打包仍在 HBuilderX 中完成）。

最重要的版本纪律：@dcloudio 全家桶同版本 ​

模板的 package.json 中所有 @dcloudio/* 包版本必须完全一致：

jsonc
{
  "dependencies": {
    "@dcloudio/uni-app": "3.0.0-xxxxxxxx",
    "@dcloudio/uni-components": "3.0.0-xxxxxxxx",
    "@dcloudio/uni-h5": "3.0.0-xxxxxxxx",
    "@dcloudio/uni-mp-weixin": "3.0.0-xxxxxxxx"
  }
}

规则：

  1. 不要只升级其中某一个，编译期会出现「找不到组件/API 行为不一致」等怪问题。
  2. 版本号与 HBuilderX 正式版配套发布，升级时整体跟进官方发布说明。
  3. pnpm 若因幽灵依赖报模块解析错误，确保相关包都显式声明在 package.json 中（模板已处理，自行新增包时注意）。

目录结构与职责 ​

text
src/
├─ pages/              # 页面（与 pages.json 对应）
├─ components/         # 符合 easycom 规范的组件自动注册
├─ stores/             # Pinia（模块 6）
├─ api/                # 接口模块（模块 4）
├─ utils/              # 工具函数
├─ platforms/          # 平台专属实现（条件编译引用，模块 7）
├─ static/             # 原样拷贝的静态资源
├─ App.vue
├─ main.ts
├─ pages.json
├─ manifest.json
└─ uni.scss
.env / .env.production  # 环境变量
vite.config.ts
tsconfig.json

路径别名 ​

模板默认提供 @ -> src。在 vite.config.ts 中确认：

ts
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'
import { fileURLToPath } from 'node:url'

export default defineConfig({
  plugins: [uni()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  }
})

tsconfig.json 同步配置，TS 才不会报红：

jsonc
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  }
}

小程序端也能使用 @ 别名——由 uni 的 Vite 插件在编译期改写，不用担心小程序运行时不认识。

环境变量 ​

使用 Vite 的 VITE_ 前缀约定：

bash
# .env（所有环境共享）
VITE_APP_NAME=uni-app 教程示例

# .env.development
VITE_API_BASE=https://dev-api.example.com

# .env.production
VITE_API_BASE=https://api.example.com

业务代码中读取：

ts
export const API_BASE = import.meta.env.VITE_API_BASE as string

封装一个类型化入口，避免散落的 import.meta.env：

ts
// src/utils/env.ts
type Env = 'development' | 'production'
export const env = {
  mode: import.meta.env.MODE as Env,
  apiBase: import.meta.env.VITE_API_BASE as string,
  isDev: import.meta.env.DEV,
  isProd: import.meta.env.PROD
}

小程序的合法域名

环境变量只解决「打包时连哪个地址」。微信小程序还需要在管理后台配置 request 合法域名（HTTPS）；开发期可在开发者工具勾选「不校验合法域名」。

在微信开发者工具中打开 CLI 产物 ​

  1. pnpm dev:mp-weixin，保持终端运行（watch 模式）。
  2. 微信开发者工具导入 dist/dev/mp-weixin。
  3. 后续改代码自动重新编译，开发者工具自动刷新。

H5 端调试 ​

pnpm dev:h5 后打开终端打印的地址。可直接使用 Vue DevTools 浏览器扩展；条件编译的 H5 分支、DOM 结构都可在普通 DevTools 中检查。

编辑器选择 ​

CLI 工程可以用 VS Code / Trae / WebStorm。推荐插件与配置：

  • Vue - Official（原 Volar）：Vue 3 模板类型检查
  • ESLint + Prettier（2.3 会落地配置）
  • tsconfig 开启 strict，把类型问题挡在编译前

常见问题 ​

Q：pnpm install 后提示构建脚本未运行？ pnpm 10+ 默认拦截依赖的安装脚本。在 pnpm-workspace.yaml 中声明白名单（或按提示运行 pnpm approve-builds）：

yaml
allowBuilds:
  esbuild: true

Q：dev 启动报错「@dcloudio/uni-mp-vue 找不到」？ 基本都是 @dcloudio 包版本不一致或安装不完整。统一版本号后删除 node_modules 与 lockfile 重装。

Q：可以用 npm/yarn 吗？ 可以，但团队请统一一种包管理器并提交 lockfile。本教程统一 pnpm，monorepo 与磁盘占用优势明显。
