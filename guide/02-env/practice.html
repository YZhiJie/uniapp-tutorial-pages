2.3 实战案例：ESLint、路径别名与多端调试配置 ​

本篇产出一个可以直接复制到新项目的工程基线：写完代码，团队任何人 pnpm install 后都能 lint、类型检查、三端调试。

1. 安装 lint 工具链 ​

bash
pnpm add -D eslint @eslint/js typescript-eslint eslint-plugin-vue vue-eslint-parser globals prettier eslint-config-prettier

eslint.config.js（ESLint 9 flat config）：

js
import js from '@eslint/js'
import tseslint from 'typescript-eslint'
import pluginVue from 'eslint-plugin-vue'
import globals from 'globals'
import prettier from 'eslint-config-prettier'

export default tseslint.config(
  {
    ignores: ['dist/**', 'node_modules/**', 'src/static/**', 'unpackage/**']
  },
  js.configs.recommended,
  ...tseslint.configs.recommended,
  ...pluginVue.configs['flat/recommended'],
  {
    files: ['**/*.{ts,vue}'],
    languageOptions: {
      ecmaVersion: 'latest',
      sourceType: 'module',
      globals: {
        ...globals.browser,
        uni: 'readonly',
        wx: 'readonly',
        plus: 'readonly',
        getCurrentPages: 'readonly',
        UniApp: 'readonly'
      }
    }
  },
  {
    files: ['**/*.vue'],
    languageOptions: {
      parserOptions: { parser: tseslint.parser }
    }
  },
  {
    rules: {
      'vue/multi-word-component-names': 'off',
      '@typescript-eslint/no-explicit-any': 'off',
      '@typescript-eslint/consistent-type-imports': 'warn'
    }
  },
  prettier
)

关键点：把 uni、wx、plus、getCurrentPages 声明为全局变量，避免业务代码满文件 no-undef。

Prettier 配置 .prettierrc.json：

jsonc
{
  "printWidth": 100,
  "singleQuote": true,
  "semi": false,
  "trailingComma": "none"
}

package.json 脚本：

jsonc
{
  "scripts": {
    "lint": "eslint . --fix",
    "type-check": "vue-tsc --noEmit",
    "dev:h5": "uni",
    "dev:mp-weixin": "uni -p mp-weixin",
    "build:h5": "uni build",
    "build:mp-weixin": "uni build -p mp-weixin"
  }
}

提交前自动检查可配简单的 git hook（或使用 husky + lint-staged）：

bash
pnpm add -D husky lint-staged
pnpm exec husky init
jsonc
// package.json
{
  "lint-staged": {
    "*.{ts,vue}": ["eslint --fix"],
    "*.{json,md,scss}": ["prettier --write"]
  }
}

.husky/pre-commit：

bash
pnpm lint-staged

2. 路径别名与目录骨架 ​

vite.config.ts 与 tsconfig.json 的别名配置见 2.2。在此基础上创建分层目录：

text
src/
├─ api/             # 按业务域拆分的接口模块
│  ├─ request.ts    # 请求层（模块 4）
│  └─ user.ts
├─ stores/          # Pinia（模块 6）
├─ utils/
├─ constants/
├─ components/
└─ pages/

导入示例：

ts
import { request } from '@/api/request'
import { useUserStore } from '@/stores/user'

3. 环境变量与类型声明 ​

src/env.d.ts 给自定义环境变量补类型：

ts
/// <reference types="@dcloudio/types" />

interface ImportMetaEnv {
  readonly VITE_API_BASE: string
  readonly VITE_APP_NAME: string
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}

@dcloudio/types 提供 uni.* 的完整类型，强烈建议安装：pnpm add -D @dcloudio/types。

.env.development：

bash
VITE_APP_NAME=示例App-dev
VITE_API_BASE=https://dev-api.example.com

4. 多端调试配置 ​

H5 ​

bash
pnpm dev:h5

VS Code 调试（.vscode/launch.json，针对 Chrome）：

jsonc
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "chrome",
      "request": "launch",
      "name": "调试 H5",
      "url": "http://localhost:5173",
      "webRoot": "${workspaceFolder}/src"
    }
  ]
}

微信小程序 ​

  1. pnpm dev:mp-weixin watch 运行。
  2. 微信开发者工具导入 dist/dev/mp-weixin。
  3. 在源码（src）里打断点不可行时，利用 SourceMap：开发者工具 Sources 面板可以找到 webpack://vite 前缀的源码（不同版本路径显示不同），也可以直接用 debugger 语句。
  4. 真机预览：点「预览」生成二维码，用手机微信扫码，打开 vConsole 风格的调试面板（开发版自带）。

App ​

  1. pnpm dev:app 生成 App 资源到 dist/dev/app。
  2. HBuilderX 打开项目（或仅打开 dist 资源目录），运行到手机/模拟器基座。
  3. 自定义调试基座：manifest.json → App 模块配置勾选 Push/支付等 → HBuilderX「制作自定义调试基座」。

5. 一份团队约定（建议直接采纳） ​

类别约定
分支main 受保护，功能分支 feat/xxx，修复 fix/xxx
提交前必须通过 lint 与 type-check
目录跨端公共代码不得出现 window/document/wx，平台能力一律走 uni.* 或条件编译
依赖新增依赖必须说明理由；@dcloudio/* 只能整组升级
小程序合入前在微信开发者工具真机预览一次，重点查首屏与列表滚动

练习 ​

  1. 按本篇步骤给你的项目配齐 ESLint + Prettier + husky，尝试提交一个带未使用变量的文件，确认提交被拦截。
  2. 添加 .env.staging，并在 package.json 增加 build:h5:staging 脚本（提示：Vite 支持 --mode staging）。
  3. 用 Chrome 的 launch 配置在请求函数里打断点，走通一次完整调试链路。

环境就绪后，进入 模块三：内置组件与自定义组件。
