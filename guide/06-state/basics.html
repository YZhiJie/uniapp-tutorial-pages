6.1 基础入门：为什么需要全局状态管理 ​

一个没有 store 的故事会怎样演化 ​

需求：底部 tabBar 的购物车要显示数量角标；商品详情加购后，购物车页、订单确认页都要用最新数据。

没有状态管理时的典型演进路径：

  1. 每个页面自己请求购物车数量 → 详情页加购后，首页角标不更新。
  2. 用 uni.$emit / uni.$on 事件总线互相通知 → 事件来源难以追踪，返回页面重复监听，内存泄漏。
  3. 用 getApp().globalData 存数量 → 任何页面都能随意改，刷新即丢，无类型、无调试手段。

正确答案是把跨页面共享、需要响应式更新的数据放进一个受约束的全局仓库：Pinia。

五种“放数据的地方”与边界 ​

方案响应式生命周期持久化适用
组件 ref/reactive✅组件/页面❌只在当前页使用的数据
provide/inject✅组件树❌祖孙层级共享（局部主题、表单上下文）
getApp().globalData❌（非响应式）应用运行期❌极少量全局常量/实例（如地图句柄）
uni.setStorageSync❌长期✅登录令牌、缓存、草稿（配合 store 使用）
Pinia store✅应用运行期可自行持久化跨页面共享的业务状态

关键区分：storage 是数据库，store 是内存中的响应式状态。常见正解是「store 持有状态，变化时同步写入 storage 做持久化」（下一篇实现），而不是直接把 storage 当状态用（读写无响应式，UI 不会自动更新）。

什么数据该进 store ​

适合：

  • 用户身份：token、用户资料、权限
  • 购物车、消息未读数、全局配置
  • 多页面共用的缓存：地区字典、分类树
  • 跨页表单/草稿（发布流程跨多个页面）

不适合：

  • 只被一个页面使用的列表、弹窗开关、表单临时值
  • 纯静态常量（放 constants/ 目录）
  • 组件内部的展示状态（展开/收起、输入聚焦）

判断口诀：“换一个页面还要用，或者要被别的页面修改”——进 store；否则留在页面。

安装与注册 Pinia ​

bash
pnpm add pinia

src/main.ts：

ts
import { createSSRApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

export function createApp() {
  const app = createSSRApp(App)
  app.use(createPinia())
  return { app }
}

第一个 store：用户信息 ​

Pinia 有两种写法：Options 式与 Composition（setup）式。本教程统一 setup 式，与 Vue 3 心智模型完全一致。

ts
// src/stores/user.ts
import { computed, ref } from 'vue'
import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', () => {
  // state
  const token = ref('')
  const profile = ref<{ id: number; nickname: string; avatar: string } | null>(null)

  // getter
  const isLoggedIn = computed(() => Boolean(token.value))
  const nickname = computed(() => profile.value?.nickname ?? '游客')

  // action
  function setToken(value: string) {
    token.value = value
  }
  function setProfile(data: NonNullable<typeof profile.value>) {
    profile.value = data
  }
  function logout() {
    token.value = ''
    profile.value = null
  }

  return { token, profile, isLoggedIn, nickname, setToken, setProfile, logout }
})

页面中使用：

vue
<script setup lang="ts">
import { useUserStore } from '@/stores/user'

const userStore = useUserStore()

function onLoginSuccess(token: string, profile: { id: number; nickname: string; avatar: string }) {
  userStore.setToken(token)
  userStore.setProfile(profile)
}
</script>

<template>
  <text>{{ userStore.isLoggedIn ? userStore.nickname : '未登录' }}</text>
</template>

store 的模块化组织 ​

text
src/stores/
├─ index.ts        # 可选：统一导出
├─ user.ts         # 用户/鉴权
├─ cart.ts         # 购物车（6.3 实战）
├─ app.ts          # 全局配置、网络状态、系统信息
└─ im.ts           # 消息会话（模块 10）

一个 store 对应一个业务域，不要把所有东西塞进一个 useMainStore。跨 store 组合很简单：在一个 store 的 action 中直接调用另一个 store：

ts
const userStore = useUserStore()
async function submit() {
  if (!userStore.isLoggedIn) { /* 跳登录 */ }
}

状态修改的纪律 ​

  1. 所有修改走 action：组件不直接 store.xxx = yyy，便于加校验、埋点、持久化钩子。
  2. 异步逻辑（请求）放 action 内，组件只 await。
  3. store 不直接依赖页面生命周期；页面在 onShow 决定何时 refresh()。

常见问题 ​

Q：Pinia 在小程序端可靠吗？ 可靠。Pinia 只依赖 Vue 响应式，不依赖浏览器环境；uni-app Vue3 官方文档也推荐 Pinia。

Q：和 Vuex 还有关系吗？ Vuex 已停止演进，新项目一律 Pinia。存量 Vuex 项目的迁移对照见 6.2。

Q：store 数据刷新会丢吗？ 会——store 是内存状态。需要保留的字段（token、购物车）做持久化，6.2 给出实现。
