4.3 实战案例：Mock 数据与 API 模块分层 ​

后端接口没就绪时，前端干等是最大的浪费。本篇建立「接口契约先行、Mock 无缝切换」的工作流。

一、定义契约：类型即文档 ​

与后端先定好响应结构，写进 src/api/types.ts 与各模块（见 4.2）。契约确定后页面就可以开工。

二、Mock 方案选型 ​

方案适用说明
本地静态 JSON稳定不变的数据放 src/mock/，用条件编译接管
本地函数 Mock分页/搜索/延迟模拟推荐，可模拟 loading 与错误
Mock 平台（Apifox 等）团队协作提供真实 HTTP 地址，手机端也能访问
拦截适配器演示/教学替换 uni.request 内核

三、本地函数 Mock 落地 ​

环境变量增加开关：

bash
# .env.development
VITE_USE_MOCK=true
VITE_API_BASE=https://dev-api.example.com
ts
// src/utils/env.ts
export const env = {
  apiBase: import.meta.env.VITE_API_BASE as string,
  useMock: import.meta.env.VITE_USE_MOCK === 'true'
}
ts
// src/mock/db.ts
export interface Goods {
  id: number
  name: string
  price: number
}

export const mockGoods: Goods[] = Array.from({ length: 86 }, (_, i) => ({
  id: i + 1,
  name: `示例商品 ${i + 1}`,
  price: 19.9 + i
}))
ts
// src/mock/index.ts
import { mockGoods } from './db'

function delay(ms = 400) {
  return new Promise((r) => setTimeout(r, ms))
}

// 与真实接口保持完全一致的函数签名与返回结构
export const mockAdapters: Record<string, (data: any) => Promise<unknown>> = {
  async 'GET /goods'(data: { page: number; size: number; keyword?: string }) {
    await delay()
    let list = mockGoods
    if (data.keyword) {
      list = list.filter((g) => g.name.includes(data.keyword))
    }
    const start = (data.page - 1) * data.size
    return {
      code: 0,
      message: 'ok',
      data: { list: list.slice(start, start + data.size), total: list.length, page: data.page, size: data.size }
    }
  },
  async 'POST /login'() {
    await delay()
    return { code: 0, message: 'ok', data: { token: 'mock-token', refreshToken: 'mock-refresh' } }
  }
}

在请求内核入口处分流（仅开发包、且仅 H5/小程序本地调试时启用）：

ts
// request.ts 的 request() 开头
import { env } from '@/utils/env'
import { mockAdapters } from '@/mock'

async function request<T>(config: RequestConfig): Promise<T> {
  // ...合并 url 之前

  // #ifdef H5 || MP-WEIXIN
  if (env.useMock) {
    const key = `${config.method ?? 'GET'} ${config.url.replace(env.apiBase, '')}`
    const adapter = mockAdapters[key]
    if (adapter) {
      const body = await adapter(config.data ?? {})
      // 复用响应拦截器的解包逻辑
      return runResponseInterceptors<T>(body, config)
    }
  }
  // #endif

  // ……真实请求流程
}

要点：

  • Mock 开关只存在于开发环境变量，生产包构建时天然为 false，且配合条件编译可进一步裁掉代码。
  • 找不到 adapter 时透传到真实后端，允许「部分接口先行联调」。
  • Mock 的返回结构必须严格遵守契约，切真接口时零改动。

四、API 模块分层规范 ​

text
页面/组件
   │ 只调用 xxxApi.method()，不拼 url、不碰 header
   ▼
api/modules/*.ts      业务域接口（goods / order / user / im）
   ▼
api/request.ts        内核：baseURL、重试、取消
   ▼
api/interceptors.ts   横切：鉴权、解包、错误码、日志

反例（页面里散写 url 与 header）在第三个页面之后就会失控：改域名、换鉴权方案时要全局搜索替换。正例是所有变更只发生在一处。

五、错误码字典与统一提示 ​

ts
// src/api/error-code.ts
export const ERROR_MESSAGES: Record<number, string> = {
  0: '成功',
  401: '登录已过期，请重新登录',
  403: '没有操作权限',
  404: '资源不存在',
  429: '操作太频繁，请稍后再试',
  500: '服务器开小差了'
}

export function resolveErrorMessage(code: number, fallback?: string) {
  return ERROR_MESSAGES[code] ?? fallback ?? '网络异常，请稍后重试'
}

响应拦截器中统一处理登录失效：

ts
if (body.code === 401) {
  uni.showModal({
    title: '提示',
    content: '登录状态已失效，请重新登录',
    confirmText: '去登录',
    success: (res) => {
      if (res.confirm) {
        uni.reLaunch({ url: '/pages/login/index' })
      }
    }
  })
  throw new Error('unauthorized')
}

用 reLaunch 而不是 navigateTo：登录失效后要清空页面栈，防止返回到需要鉴权的页面。

六、联调检查清单 ​

切换到真实后端前逐项确认：

  • [ ] VITE_USE_MOCK=false，baseURL 指向目标环境
  • [ ] 小程序管理后台/开发者工具的域名配置正确（HTTPS）
  • [ ] 请求头 token 格式与后端约定一致（Bearer / 自定义头）
  • [ ] 时间字段、数字精度（金额单位：元/分）已与后端对齐
  • [ ] 分页参数命名（page/size 还是 pageNum/pageSize）全局统一
  • [ ] 错误码字典覆盖后端实际返回码
  • [ ] 弱网/超时/401/500 四类异常在真机上各验证一次

练习 ​
