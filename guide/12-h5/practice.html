12.3 实战案例：企业级 H5 发布（Nginx + CDN + CI/CD） ​

学习目标 ​

  • 能用一份完整可跑的 nginx.conf 同时搞定 SPA 回退 + 静态资源缓存 + 安全头 + SSR 反代
  • 理解跨域场景下 Access-Control-Allow-Origin + SameSite=None; Secure 的配套关系
  • 看懂首屏 < 1s 的优化 checklist（关键 CSS 内联、HTTP/2 push、图片 lazy）
  • 用 GitHub Actions 写出一份能自动构建 → 上传 CDN → 重启服务的 CI/CD 工作流

0. 整体架构长这样 ​

mermaid
flowchart LR
  subgraph 用户侧
    U[浏览器]
  end
  subgraph 边缘层
    CDN[CDN<br/>静态资源缓存]
  end
  subgraph 应用层
    Nginx[Nginx<br/>HTTPS + 安全头 + 反代]
    SSR[Node SSR 服务<br/>Port 3000]
  end
  subgraph 后端
    API[后端 API]
  end

  U -- HTTPS --> CDN
  CDN -- 回源 --> Nginx
  U -- 直连(SSR 页面) --> Nginx
  Nginx -- /api/* --> API
  Nginx -- /*    --> SSR
  • 静态资源（CSS/JS/图片/字体）走 CDN，缓存一年
  • SSR 动态页面直连 nginx，nginx 反代到 Node SSR 服务
  • API 请求在浏览器里 fetch('/api/*')，由 nginx 统一转发给后端服务（避免浏览器跨域）

1. 完整可跑的 nginx.conf ​

下面这份配置是生产可用版本（已在多个 uni-app H5 项目验证过），涵盖：

  • HTTPS + HTTP/2 + HSTS
  • CSP / Permissions-Policy / X-Content-Type-Options 安全头
  • SPA history 回退 + SSR 反代
  • API 反向代理（解决跨域）
  • 静态资源长缓存 + gzip + brotli
  • WebSocket（如果你的项目需要实时通讯）
nginx
# /etc/nginx/conf.d/uniapp-h5.conf

# 上游 API 服务（按实际端口改）
upstream api_backend {
  server 127.0.0.1:8080;
  keepalive 32;
}

# 上游 SSR Node 服务
upstream ssr_node {
  server 127.0.0.1:3000;
  keepalive 16;
}

# HTTP → HTTPS 强制跳转
server {
  listen 80;
  listen [::]:80;
  server_name app.example.com;

  # certbot / acme-challenge 需要的例外
  location /.well-known/acme-challenge/ {
    root /var/www/certbot;
  }

  location / {
    return 301 https://$host$request_uri;
  }
}

server {
  listen 443 ssl http2;
  listen [::]:443 ssl http2;
  server_name app.example.com;

  # —— SSL 证书（certbot 自动续签） ——
  ssl_certificate     /etc/letsencrypt/live/app.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

  # TLS 加固
  ssl_protocols       TLSv1.2 TLSv1.3;
  ssl_ciphers         HIGH:!aNULL:!MD5;
  ssl_prefer_server_ciphers on;
  ssl_session_cache   shared:SSL:10m;
  ssl_session_timeout 1d;

  # —— 安全响应头 ——
  # HSTS：告诉浏览器一年內都用 HTTPS（max-age=31536000）
  add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

  # 禁止 MIME 嗅探
  add_header X-Content-Type-Options "nosniff" always;

  # 禁止页面被嵌入 iframe（防点击劫持）
  add_header X-Frame-Options "SAMEORIGIN" always;

  # 引用策略
  add_header Referrer-Policy "strict-origin-when-cross-origin" always;

  # Permissions Policy：明确禁用不必要的浏览器能力
  add_header Permissions-Policy "geolocation=(), camera=(), microphone=(), payment=(self)" always;

  # CSP（按需修改；report-uri 指向你的 CSP 收集端点）
  add_header Content-Security-Policy "default-src 'self'; \
    script-src 'self' 'unsafe-inline' 'unsafe-eval'; \
    style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; \
    font-src 'self' https://fonts.gstatic.com data:; \
    img-src 'self' https: data:; \
    connect-src 'self' https://api.example.com wss://app.example.com; \
    frame-ancestors 'self'; \
    base-uri 'self'; \
    form-action 'self'; \
    report-uri /csp-report;" always;

  # —— 压缩 ——
  gzip on;
  gzip_vary on;
  gzip_proxied any;
  gzip_comp_level 6;
  gzip_min_length 1024;
  gzip_types text/plain text/css text/xml application/json application/javascript application/xml;

  brotli on;
  brotli_comp_level 6;
  brotli_types text/plain text/css text/xml application/json application/javascript application/xml;

  # —— 根目录 & SPA 回退 ——
  root /var/www/uniapp-h5/dist/build/h5;
  index index.html;

  # API 代理（浏览器访问 /api/* → 后端 8080）
  location /api/ {
    proxy_pass http://api_backend;
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # 大文件上传
    client_max_body_size 50m;
  }

  # WebSocket 升级（如需）
  location /ws/ {
    proxy_pass http://api_backend;
    proxy_http_version 1.1;
    proxy_set_header Upgrade    $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host       $host;
    proxy_read_timeout          86400;
  }

  # 如果启用了 SSR，把 SSR 专属路由反代到 Node
  location /ssr/ {
    proxy_pass http://ssr_node;
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # 静态资源：长缓存（文件名带 hash，可安全缓存一年）
  location /static/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
    access_log off;
    try_files $uri =404;
  }

  # favicon / manifest / sw.js 不缓存（sw.js 升级要及时）
  location ~* \.(?:html|webmanifest|js\.map)$ {
    expires -1;
    add_header Cache-Control "no-cache, no-store, must-revalidate";
  }

  # Service Worker 必须从根路径 scope 注册，且不能有 cache
  location = /sw.js {
    root /var/www/uniapp-h5/dist/build/h5;
    expires -1;
    add_header Cache-Control "no-cache";
    add_header Service-Worker-Allowed "/";
  }

  # robots.txt / sitemap.xml
  location = /robots.txt { alias /var/www/uniapp-h5/public/robots.txt; }
  location = /sitemap.xml { alias /var/www/uniapp-h5/public/sitemap.xml; }

  # SPA history 回退（兜底）
  location / {
    try_files $uri $uri/ /index.html;
  }

  # CSP report 接收端点（如果后端不接，这里临时返回 204）
  location = /csp-report {
    default_type application/json;
    return 204;
  }
}

2. CORS + SameSite Cookie 的坑 ​

场景 ​

假设你的 uni-app H5 在 https://app.example.com，后端 API 在 https://api.example.com，登录成功后端下发 cookie。浏览器默认策略（SameSite=Lax）会让跨站请求的 cookie 被静默丢弃。

正确配对 ​

后端设置 cookie 时必须带：

Set-Cookie: session_id=xxx; Domain=example.com; Path=/; Secure; SameSite=None; HttpOnly

同时 CORS 响应头必须配套：

nginx
# nginx 里 /api/  location 额外加上
location /api/ {
    # 允许跨站请求带 cookie
    add_header Access-Control-Allow-Origin  "https://app.example.com" always;
    add_header Access-Control-Allow-Credentials "true" always;
    add_header Access-Control-Allow-Methods "GET, POST, PUT, PATCH, DELETE, OPTIONS" always;
    add_header Access-Control-Allow-Headers "Content-Type, Authorization, X-Requested-With" always;
    add_header Access-Control-Max-Age      600 always;

    # OPTIONS 预检直接响应，不走后端
    if ($request_method = OPTIONS) {
        return 204;
    }

    proxy_pass http://api_backend;
    # ...
}

浏览器端 fetch 必须显式声明：

ts
const resp = await fetch('https://api.example.com/user/profile', {
  credentials: 'include', // 关键
  headers: { Authorization: `Bearer ${token}` },
})

三个容易踩的坑 ​

坑表现解法
SameSite=None 但没 SecureChrome 直接拒绝设置 cookie本地开发用 http://localhost 例外，生产必须 HTTPS
CORS 用了 Access-Control-Allow-Origin: * 同时开 credentials浏览器报错必须用具体 origin，或写死允许的域名
子域 cookie 没设 Domain只能当前域名，子域拿不到后端 cookie 加 Domain=.example.com

3. 首屏 < 1s 优化清单 ​

当你把 SSR、CDN、安全头都配好，下一步就是压首屏时间。下面这份 checklist 按投入产出比排序，前三条做完通常就能从 3~4s 打到 1s 以内：

① SSR 关键 CSS 内联 ​

uni-app H5 产物默认把所有 CSS 打成一个大 chunk，首屏必须等它下完才能渲染。SSR 场景下可以用 Vite 插件把首屏用到的 CSS 内联进 HTML，其余异步加载：

ts
// vite.config.ts
import uni from '@dcloudio/vite-plugin-uni'
import { viteSSRInlineCss } from './plugins/vite-ssr-inline-css'

export default defineConfig({
  plugins: [uni(), viteSSRInlineCss()],
})

原理：在 SSR 渲染完成后，遍历生成的 <link rel="stylesheet">，把每个文件内容读出来替换成 <style>...</style>，并在末尾加一段 </style><link rel="stylesheet" href="..." onload="this.media='all'" media="print"> 让浏览器后台继续加载完整文件。

② HTTP/2 Push 关键资源 ​

HTTP/2 支持服务器主动推送资源，浏览器还没解析完 HTML 就开始并行下载。nginx 配法：

nginx
# server 块里
http2_push_preload on;

# 或者用 Link 头（更灵活）
location = / {
    add_header Link "</static/js/index.xxx.js>; rel=preload; as=script, </static/css/index.xxx.css>; rel=preload; as=style";
    try_files $uri /index.html;
}

nginx 的 http2_push 有个坑：它会基于 Link 头触发，但浏览器如果已经缓存了这个资源，就会浪费一次推送。更稳的做法是等 SSR Node 在生成 HTML 时，根据首次访问还是缓存命中动态拼接 Link 头。

③ 图片懒加载 + AVIF/WebP ​

vue
<template>
  <!-- uni-image 默认支持 lazy-load，加上就生效 -->
  <image
    :src="product.cover"
    lazy-load
    mode="aspectFill"
    class="cover"
  />
</template>

<style>
.cover { width: 750rpx; height: 400rpx; }
</style>

如果用 CDN（七牛 / 阿里云 OSS / Cloudflare），直接在 URL 上加参数自动转 WebP/AVIF：

ts
const cover = `${product.cover}?imageView2/format/webp` // 七牛
const cover = `${product.cover}?x-oss-process=image/format,webp` // 阿里云
const cover = `${product.cover}?format=auto` // Cloudflare

④ 其他高收益项 ​

手段预期收益落地方式
静态资源走 CDNTTFB 从几百 ms 降到几十 ms把 /static/ 目录挂到 CDN 源站
prefetch 下一跳页面二次打开秒开uni.preloadPage / Vite prefetch
骨架屏 + SSR fallbackLCP 稳定在 1s 内SSR 服务偶发失败时回退静态骨架屏
字体子集化省掉几百 KB 字体fontmin 或 Google Fonts text 参数
Brotli 替代 gzipJS 体积再减 15~20%nginx brotli on（见上面的配置）

用 Lighthouse 跑一遍，H5 端目标分数：

指标目标怎么查

4. GitHub Actions 一键发布 ​

完整的 CI/CD 工作流：构建 → 压缩 → 上传 CDN → 重启 SSR 服务 → 健康检查 → 回滚。

新建文件 .github/workflows/deploy.yml：

yaml
name: Deploy uni-app H5

on:
  push:
    branches: [main]
  workflow_dispatch:

concurrency:
  group: deploy-${{ github.ref }}
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      version: ${{ steps.version.outputs.value }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: npm

      - name: Install deps
        run: npm ci

      - name: Inject version
        id: version
        run: |
          VERSION=$(date +%Y%m%d)-${GITHUB_SHA::7}
          echo "value=$VERSION" >> $GITHUB_OUTPUT
          echo "$VERSION" > VERSION

      - name: Build H5 + SSR
        run: npm run build:h5
        env:
          NODE_ENV: production

      - name: Upload artifact
        uses: actions/upload-artifact@v4
        with:
          name: h5-dist
          path: dist/build/h5
          retention-days: 7

      - name: Upload CDN (示例：阿里云 OSS)
        uses: manyuanrong/setup-ossutil@v2.0
        with:
          endpoint: ${{ secrets.OSS_ENDPOINT }}
          access-key-id: ${{ secrets.OSS_KEY_ID }}
          access-key-secret: ${{ secrets.OSS_KEY_SECRET }}
          bucket: ${{ secrets.OSS_BUCKET }}
        continue-on-error: true
      - run: ossutil cp -rf dist/build/h5/static oss://your-cdn-bucket/static/

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4

      - name: Download artifact
        uses: actions/download-artifact@v4
        with:
          name: h5-dist
          path: dist/build/h5

      - name: Deploy via rsync
        env:
          SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
          HOST: ${{ secrets.DEPLOY_HOST }}
          USER: ${{ secrets.DEPLOY_USER }}
        run: |
          mkdir -p ~/.ssh
          echo "$SSH_PRIVATE_KEY" > ~/.ssh/id_rsa
          chmod 600 ~/.ssh/id_rsa
          ssh-keyscan -H "$HOST" >> ~/.ssh/known_hosts

          # 增量上传，先传临时目录再原子替换
          rsync -avz --delete dist/build/h5/ \
            "$USER@$HOST:/var/www/uniapp-h5/releases/${{ needs.build.outputs.version }}"

          # 原子切换软链接
          ssh "$USER@$HOST" "
            ln -sfn /var/www/uniapp-h5/releases/${{ needs.build.outputs.version }} /var/www/uniapp-h5/current && \
            rm -rf /var/www/uniapp-h5/releases/*/dist 2>/dev/null || true
          "

      - name: Restart SSR service
        env:
          SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
          HOST: ${{ secrets.DEPLOY_HOST }}
          USER: ${{ secrets.DEPLOY_USER }}
        run: |
          ssh "$USER@$HOST" "pm2 restart uniapp-ssr || pm2 start ecosystem.config.js --only uniapp-ssr"

      - name: Health check
        run: |
          for i in $(seq 1 10); do
            STATUS=$(curl -s -o /dev/null -w "%{http_code}" https://app.example.com/ || echo "000")
            if [ "$STATUS" = "200" ]; then
              echo "✅ Health check passed after ${i} attempts"
              exit 0
            fi
            echo "⏳ Attempt $i: got $STATUS, retrying in 3s..."
            sleep 3
          done
          echo "❌ Health check failed — triggering rollback"
          exit 1

      - name: Rollback on failure
        if: failure()
        env:
          SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
          HOST: ${{ secrets.DEPLOY_HOST }}
          USER: ${{ secrets.DEPLOY_USER }}
        run: |
          ssh "$USER@$HOST" "
            PREV=$(ls -1t /var/www/uniapp-h5/releases | sed -n '2p')
            if [ -n \"$PREV\" ]; then
              ln -sfn /var/www/uniapp-h5/releases/\$PREV /var/www/uniapp-h5/current
              pm2 restart uniapp-ssr || true
              echo \"🔄 Rolled back to \$PREV\"
            fi
          "

这份 workflow 做到了：

  1. 原子发布：先传到 releases/版本号/，最后一秒改软链接切流量，用户不会看到半成品
  2. 并发控制：concurrency 防止多个 PR 同时发版互相覆盖
  3. 健康检查 + 自动回滚：上线后连查 10 次，全部失败就切回上一个版本
  4. 环境隔离：environment: production 在 GitHub 里可以配置审批流

服务器侧需要一个 ecosystem.config.js 给 PM2 用：

js
// ecosystem.config.js
module.exports = {
  apps: [{

常见问题 ​

Q：history 模式 + SSR + CDN 混用会不会打架？ 不会，只要搞清楚谁处理什么：(1) 静态资源 URL（/static/*）全部走 CDN；(2) HTML 页面 URL（/、/product/42）不要走 CDN，直接回源到 nginx，让 nginx 反代给 SSR Node。CDN 配置里把非 /static/* 的路径设置为「不缓存 / 直接回源」即可。

Q：CSP 报 Refused to load ... because it violates the following Content Security Policy directive 怎么办？ 把 URL 一个个对照 CSP 的各个 *-src 段，缺什么补什么。最容易被忽略的是：(1) 内联脚本如果用了 'unsafe-inline' 就省事，但也最危险；(2) Vue 生产编译可能会把一些函数内联，导致你明明没有 <script> 标签却报 inline violation——这时用 Vite 插件 vite-plugin-csp-hash 给每个 inline script 加 hash，再把 hash 放进 CSP 的 script-src。

Q：PM2 cluster 模式下 SSR 有状态吗？ SSR 服务本身应该是无状态的。用户登录态走 cookie，session 存 Redis 或 JWT，不能存在 Node 进程内存里。cluster 模式下多个 worker 同时处理请求，任何一个都可能接到同一个用户的后续请求。
