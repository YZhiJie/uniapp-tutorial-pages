12.2 进阶应用：SSR、PWA 与 SEO ​

学习目标 ​

  • 说出 uni-app SSR 的产物长什么样、在哪配置、与 SPA 的差别
  • 能为动态页面设置 <title>、<meta property="og:image"> 等 SEO 标签
  • 写出一个可用的 manifest.json 和带离线缓存的 Service Worker 骨架
  • 对照 SEO checklist 自查上线前的 H5 页面

一、SSR：让首屏 HTML 直接带内容 ​

为什么要 SSR ​

普通 SPA 的 index.html 里只有一个 <div id="app">，要等浏览器下载 JS、执行完、才会把真实内容渲染出来。结果是：

  • 首屏白屏时间长（取决于 JS 体积 + 网络）
  • 爬虫拿到空 HTML，SEO 效果差
  • 社交分享（微信/微博）抓不到页面标题和缩略图

SSR（Server-Side Rendering） 就是在服务器上把 Vue 组件渲染成完整 HTML 再下发，浏览器拿到就能直接显示内容，然后 JS 再接管交互（hydration）。

uni-app SSR 怎么开 ​

uni-app Vue3 + Vite 版内置了 SSR 支持，通过 manifest.json 开启：

jsonc
// manifest.json
{
  "h5": {
    "router": { "mode": "history" },
    "ssr": {
      "mode": "vite"
    }
  }
}

开启后执行 npm run build:h5，产物目录会变成两部分：

dist/build/h5-ssr/
├── client/           # 客户端代码（和普通 H5 产物类似）
│   ├── index.html
│   └── static/
├── server/           # 服务端入口与组件映射
│   ├── entry-server.js
│   └── static/
└── ssr-manifest.json # 组件→chunk 映射表，服务端渲染时按需加载

服务端渲染（伪代码示意） ​

js
// server.js（Node 端）
import { createSSRApp, renderToString } from '@dcloudio/uni-h5/ssr'
import { createRouter } from './router.js'

app.get('*', async (req, res) => {
  const { app, router } = createSSRApp()
  const url = req.originalUrl

  await router.push(url)
  await router.isReady()

  const html = await renderToString(app)
  const preloadLinks = renderPreloadLinks(app)

  res.writeHead(200, { 'Content-Type': 'text/html' })
  res.end(`
    <!DOCTYPE html>
    <html>
      <head>
        ${preloadLinks}
      </head>
      <body>
        <div id="app">${html}</div>
        <script src="/static/js/client-entry.js"></script>
      </body>
    </html>
  `)
})

实际项目里推荐直接用 uni-app 官方的 @dcloudio/vite-plugin-uni-ssr，它会帮你生成这个服务端入口并处理好 hydration 逻辑，无需手写。

动态 meta：title / og:image / canonical ​

每个页面的标题和分享缩略图不一样，不能写死在模板里。推荐封装一个 useMeta 组合式函数：

ts
// composables/useMeta.ts
export function useMeta(opts: {
  title: string
  description?: string
  ogImage?: string
  canonical?: string
}) {
  // #ifdef H5
  const set = (selector: string, attr: string, value: string) => {
    let el = document.head.querySelector(selector) as HTMLMetaElement | null
    if (!el) {
      el = document.createElement('meta')
      document.head.appendChild(el)
    }
    el.setAttribute(attr, value)
  }

  document.title = opts.title
  if (opts.description) set('meta[name="description"]', 'content', opts.description)
  if (opts.ogImage)    set('meta[property="og:image"]', 'content', opts.ogImage)
  if (opts.canonical)  set('link[rel="canonical"]', 'href', opts.canonical)
  // #endif

  // #ifndef H5
  // 小程序端可以更新导航栏标题
  uni.setNavigationBarTitle({ title: opts.title })
  // #endif
}

然后在页面里使用：

vue
<!-- pages/product/detail.vue -->
<script setup lang="ts">
import { onMounted } from 'vue'
import { useMeta } from '@/composables/useMeta'

const props = defineProps<{ id: string }>()
const product = await fetchProduct(props.id) // SSR 环境下这个 await 会在服务端执行

onMounted(() => {
  useMeta({
    title: `${product.name} - 我的商城`,
    description: product.summary,
    ogImage: product.cover,
    canonical: `https://shop.example.com/product/${props.id}`,
  })
})
</script>

如果开了 SSR，meta 标签建议用 @unhead/vue（Vue 3 推荐的 head 管理库）。它能在服务端渲染阶段就把标签注入到 HTML，而不是等客户端 mounted 后再改——这样爬虫第一次拿到的 HTML 就是完整的：

ts
import { useHead } from '@unhead/vue'

useHead({
  title: `${product.name} - 我的商城`,
  meta: [
    { name: 'description', content: product.summary },
    { property: 'og:image', content: product.cover },
    { property: 'og:type', content: 'product' },
  ],
  link: [{ rel: 'canonical', href: `https://shop.example.com/product/${props.id}` }],
})

二、PWA：让 H5 有「类原生」体验 ​

PWA（Progressive Web App）让网页可以被「安装」到桌面/手机主屏，支持离线访问、接收推送通知。三件套：

  1. manifest.json — 应用元数据（名称、图标、显示方式）
  2. Service Worker — 离线缓存、请求拦截
  3. 桌面图标 — 一组不同分辨率的 PNG

manifest.json ​

放在 src/manifest.webmanifest（或直接放在 H5 产物根目录）：

jsonc
{
  "name": "我的商城",
  "short_name": "商城",
  "description": "一个 uni-app 构建的电商 H5 应用",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "orientation": "portrait",
  "background_color": "#ffffff",
  "theme_color": "#ff6b35",
  "lang": "zh-CN",
  "categories": ["shopping"],
  "icons": [
    {
      "src": "/static/icons/icon-72x72.png",
      "sizes": "72x72",
      "type": "image/png",
      "purpose": "any"
    },
    {
      "src": "/static/icons/icon-192x192.png",
      "sizes": "192x192",
      "type": "image/png",
      "purpose": "any maskable"
    },
    {
      "src": "/static/icons/icon-512x512.png",
      "sizes": "512x512",
      "type": "image/png",
      "purpose": "any maskable"
    }
  ]
}

然后在 HTML 里引用（如果用 @unhead/vue）：

ts
useHead({
  link: [{ rel: 'manifest', href: '/manifest.webmanifest' }],
  meta: [{ name: 'theme-color', content: '#ff6b35' }],
})

Service Worker 骨架 ​

Service Worker 是一个独立于主 JS 的脚本，浏览器在后台运行它。典型的离线缓存策略——App Shell + Runtime Cache：

js
// sw.js  —— 放在 H5 产物根目录
const CACHE_VERSION = 'v1:2026-10-28'
const APP_SHELL = [
  '/',
  '/index.html',
  '/static/css/index.css',
  '/static/js/index.js',
  '/manifest.webmanifest',
]

// 安装：预缓存 App Shell
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_VERSION).then((cache) => cache.addAll(APP_SHELL))
  )
  self.skipWaiting()
})

// 激活：清理旧版本缓存
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) =>
      Promise.all(keys.filter((k) => k !== CACHE_VERSION).map((k) => caches.delete(k)))
    )
  )
  self.clients.claim()
})

// 请求拦截：Cache First + 网络更新
self.addEventListener('fetch', (event) => {
  const req = event.request
  if (req.method !== 'GET') return

  // 导航请求（HTML）用 Network First，失败再回退缓存
  if (req.mode === 'navigate') {
    event.respondWith(
      fetch(req)
        .then((resp) => {
          const clone = resp.clone()
          caches.open(CACHE_VERSION).then((c) => c.put(req, clone))
          return resp
        })
        .catch(() => caches.match(req).then((r) => r || caches.match('/index.html')))
    )
    return
  }

  // 静态资源用 Cache First
  event.respondWith(
    caches.match(req).then((cached) =>
      cached ||
      fetch(req).then((resp) => {
        const clone = resp.clone()
        caches.open(CACHE_VERSION).then((c) => c.put(req, clone))
        return resp
      })
    )
  )
})

注册 SW + 安装提示 ​

ts
// src/pwa/register.ts
export function registerSW() {
  // #ifdef H5
  if (!('serviceWorker' in navigator)) return
  if (!import.meta.env.PROD) return // 开发环境不注册

  window.addEventListener('load', () => {
    navigator.serviceWorker
      .register('/sw.js')
      .then((reg) => console.log('[SW] registered:', reg.scope))
      .catch((err) => console.error('[SW] register failed:', err))
  })

  // 捕获安装提示事件
  let deferredPrompt: any = null
  window.addEventListener('beforeinstallprompt', (e) => {
    e.preventDefault()
    deferredPrompt = e
    // 显示自定义的「安装到桌面」按钮
    showInstallButton(deferredPrompt)
  })
  // #endif
}

然后在 main.ts 里调用：

ts
import { registerSW } from './pwa/register'
registerSW()

注意：Service Worker 有几个硬性要求——必须走 HTTPS（localhost 除外）、必须在站点根目录或子路径根目录注册（scope 受限）、首次安装后第二次访问才会生效。调试时可以在 Chrome DevTools → Application → Service Workers 里「Update」或「Unregister」。

三、SEO Checklist ​

只要 H5 端会被搜索引擎或社交平台爬虫访问，这张表就要逐项打勾：

#检查项做法
1<title> 每页唯一动态设置，含核心关键词
2meta description150 字以内，自然含关键词
3OG 标签og:title / og:description / og:image / og:type
4canonical URL避免重复内容被多个 URL 访问
5sitemap.xml提交给搜索引擎
6robots.txt告诉爬虫哪些页能抓
7JSON-LD 结构化数据商品、文章、FAQ 富结果
8语义化 HTML<header> <nav> <main> <article> <footer>
9图片 alt所有 <img> / <image> 有描述性 alt
10SSR 或预渲染SPA 空壳基本拿不到排名

sitemap.xml 示例 ​

xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://shop.example.com/</loc>
    <changefreq>daily</changefreq>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://shop.example.com/about</loc>
    <changefreq>monthly</changefreq>
    <priority>0.5</priority>
  </url>
  <!-- 动态商品列表可以用 sitemap index 拆分 -->
</urlset>

JSON-LD 结构化数据（以商品页为例） ​

ts
useHead({
  script: [
    {
      type: 'application/ld+json',
      innerHTML: JSON.stringify({
        '@context': 'https://schema.org',
        '@type': 'Product',
        name: product.name,
        image: [product.cover],
        description: product.summary,
        sku: product.sku,
        brand: { '@type': 'Brand', name: product.brand },
        offers: {
          '@type': 'Offer',
          price: product.price,
          priceCurrency: 'CNY',
          availability: 'https://schema.org/InStock',
          url: `https://shop.example.com/product/${props.id}`,
        },
      }),
    },
  ],
})

这段 JSON-LD 会让 Google 搜索结果里出现商品卡片（图片、价格、评分），点击率比纯文本结果高不少。

常见问题 ​

Q：SSR 和 PWA 必须一起上吗？ 不是。SSR 解决「首屏空壳 + SEO」问题，PWA 解决「安装 + 离线」问题。两者独立，可以按需组合。只做 SSR 就能解决 SEO，只做 PWA 也能获得离线能力。

Q：开了 SSR 后，Node 服务挂了怎么办？ 推荐做两层保障：(1) Node 进程用 PM2 或 systemd 守护，异常自动重启；(2) 前面挂 nginx，Node 不可用时回退到静态 SPA 产物（虽然 SEO 退化，但用户还能用）。下一篇 12.3 企业级 H5 发布 会给完整的 nginx + 健康检查配置。

Q：Service Worker 升级策略是什么？ 最稳妥的方式是每次发版手动改 CACHE_VERSION = 'v1:日期'，或在 CI 里自动注入 git sha。用户下次打开页面时，浏览器会下载新 SW、触发 install、旧 SW 不会被激活——直到用户关闭所有标签页或硬刷新。想让新版本立即生效，可以在页面上加一条提示「检测到新版本，点击刷新」。
