22.1 基础入门：发布流水线、版本号与制品 ​

教程里的「能构建」和团队里的「能持续发布」是两件事。发布流水线要回答四个问题：构建什么、产物放哪、版本怎么标、失败怎么回滚。

本篇以仓库内的 ecommerce-mini-program/ 为真实样本（它已有 scripts/ci/upload.mjs 与 .github/workflows/ci-ecommerce.yml），先打通 H5 与微信两条不依赖 Apple 账号的链路。

一、流水线全景 ​

mermaid
flowchart LR
    A[push / tag] --> B[install + 静态门禁]
    B --> C[typecheck + 单测]
    C --> D[构建 H5]
    C --> E[构建 mp-weixin]
    D --> F[体积预算]
    E --> F
    F --> G[H5 制品上传 CDN/Pages]
    F --> H[小程序上传体验版]
    G --> I[灰度 / 回滚]
    H --> I

四条纪律：

纪律说明
一次构建，多处部署同一 commit 产物先上传制品库，再分发；禁止「部署时重新构建」
版本可追溯制品名包含版本号 + commit 短哈希，能反查源码
门禁前置类型、测试、体积、安全不通过就不产出可发布制品
回滚有物上一个可用版本必须保留，回滚不重新构建

二、版本号规则 ​

推荐 主版本.次版本.修订号-构建号：

text
1.4.2-20261104.1
│ │ │  └─ CI 构建序号（同日多次构建递增）
│ │ └──── 修复
│ └────── 新功能
└──────── 不兼容变更
端版本字段约束
H5package.json version + 构建号用于缓存 bust 与 Sentry release
微信小程序version + desc上传时由 CI_VERSION / CI_DESC 注入
AndroidversionName + 递增 versionCodeversionCode 必须单调递增
iOSCFBundleShortVersionString + CFBundleVersionCFBundleVersion 必须递增
wgt 热更新manifest.json 的 version必须大于线上版本才触发更新

三、H5 流水线（真实可跑） ​

H5 产物是纯静态文件，最适合先跑通全链路。仓库 ecommerce-mini-program 已提供：

bash
cd ecommerce-mini-program
pnpm install --frozen-lockfile
pnpm build:h5           # 产物：dist/build/h5
pnpm ci:perf            # 体积预算（见 23-performance）

GitHub Actions 完整示例（构建 + 制品 + 部署到 GitHub Pages）：

yaml
name: Deploy H5

on:
  push:
    branches: [main]
    paths: ['ecommerce-mini-program/**']

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: ecommerce-mini-program
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          cache-dependency-path: ecommerce-mini-program/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
      - run: pnpm build:h5
      - run: pnpm ci:perf
      - name: 重写版本号
        run: |
          VERSION="1.4.2-$(date +%Y%m%d).${{ github.run_number }}"
          echo "$VERSION" > dist/build/h5/version.txt
          echo "VERSION=$VERSION" >> "$GITHUB_ENV"
      - uses: actions/upload-artifact@v4
        with:
          name: h5-${{ github.sha }}
          path: ecommerce-mini-program/dist/build/h5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: ecommerce-mini-program/dist/build/h5

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/deploy-pages@v4

如果部署到自有 CDN（OSS / COS / S3），把最后一步换成对应 CLI：

bash
# 阿里云 OSS 示例：先传资源，再传 index.html，避免引用错位
ossutil cp -r dist/build/h5/assets oss://$BUCKET/releases/$VERSION/assets -f
ossutil cp dist/build/h5/index.html oss://$BUCKET/index.html -f

四、微信小程序流水线（真实可跑） ​

仓库已封装上传脚本，缺少密钥时安全跳过且退出码 0，方便本地与 PR 使用：

bash
cd ecommerce-mini-program

# 只构建
pnpm build:mp-weixin

# 构建并上传体验版
CI_VERSION=1.4.2-20261104.1 \
CI_DESC="灰度 10% · 修复结算页" \
WX_APPID=wx1234567890abcdef \
WX_PRIVATE_KEY_PATH=./secrets/private.wx.key \
pnpm ci:upload:weixin

GitHub Actions：

yaml
name: Upload WeChat

on:
  workflow_dispatch:
    inputs:
      version:
        description: '版本号，如 1.4.2'
        required: true

jobs:
  upload:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: ecommerce-mini-program
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with: { version: 10 }
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          cache-dependency-path: ecommerce-mini-program/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
      - run: pnpm build:mp-weixin
      - name: 写入上传私钥
        run: |
          mkdir -p secrets
          printf '%s' "$WX_PRIVATE_KEY" > secrets/private.wx.key
      - run: node scripts/ci/upload.mjs mp-weixin
        env:
          WX_APPID: ${{ secrets.WX_APPID }}
          WX_PRIVATE_KEY_PATH: secrets/private.wx.key
          CI_VERSION: ${{ inputs.version }}
          CI_DESC: ${{ github.event.head_commit.message }}
      - name: 清理私钥
        if: always()
        run: rm -rf secrets

必须使用的 Secrets：

Secret用途获取方式
WX_APPID小程序 AppID微信公众平台 → 开发管理
WX_PRIVATE_KEY上传代码私钥公众平台 → 开发管理 → 开发设置 → 小程序代码上传密钥

上传成功后在「微信公众平台 → 版本管理」把开发版设为体验版，再提交审核。上传 ≠ 发布，审核通过后仍需手动或调用发布接口。

五、制品命名与保留策略 ​

text
artifacts/
├─ h5-1.4.2-20261104.1.tar.gz
├─ mp-weixin-1.4.2-20261104.1.zip
├─ android-1.4.2-142.apk
├─ ios-1.4.2-142.ipa
└─ wgt-1.4.2.zip
制品保留原因
H5最近 10 个版本回滚与问题复现
小程序最近 10 个版本体验版对比、审核被拒后回退
Android / iOS最近 20 个版本应用商店历史版本与灰度回滚
wgt全部保留热更新回滚依赖旧包

六、验收标准 ​

bash
cd ecommerce-mini-program

# 1. 构建产出存在
pnpm build:h5 && test -f dist/build/h5/index.html && echo OK

# 2. 体积预算通过
pnpm ci:perf

# 3. 微信上传脚本在缺密钥时安全跳过（exit 0）
node scripts/ci/upload.mjs mp-weixin; echo "exit=$?"
# 期望：exit=0，输出 [skip] ... 缺少凭证

# 4. 有密钥时真实上传
pnpm ci:upload:weixin

达到以下状态才算流水线可用：

  • 任一次发布都能从制品名反查到 commit。
  • 同一制品可重复部署，不需要重新构建。
  • 私钥只在 job 运行期存在，结束后清理，日志中不出现明文。
  • 缺凭证的 PR 流水线不会被上传步骤卡死。
