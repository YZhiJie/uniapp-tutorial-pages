22.2 进阶应用：灰度、回滚与 App 双端流水线 ​

发布不是终点。真正考验工程能力的是：新版本只影响 5% 用户、出问题时 10 分钟内回滚、回滚不丢数据。

一、三种灰度载体 ​

载体粒度生效速度适用场景回滚方式
服务端开关（flag）用户 / 设备 / 比例秒级功能逻辑、接口切换关开关
wgt 热更新版本分钟级（需下次启动）App 前端逻辑下发旧 wgt / 关闭更新
安装包 / 小程序版本渠道 / 审核小时–天原生代码、权限变更应用商店回退 / 小程序版本回退

原则：能用开关灰度的，不要发新包。开关是唯一能在事故中「秒级止血」的手段。

1.1 分桶开关（同一用户稳定命中） ​

ts
// src/services/flag.ts
function hashCode(input: string) {
  let hash = 0
  for (let i = 0; i < input.length; i++) {
    hash = (hash * 31 + input.charCodeAt(i)) | 0
  }
  return Math.abs(hash)
}

export interface FlagConfig {
  name: string
  enabled: boolean
  percent: number        // 0–100
  whitelist?: string[]
}

export function isEnabled(flag: FlagConfig, userId: string) {
  if (!flag.enabled) return false
  if (flag.whitelist?.includes(userId)) return true
  // 同一 userId + flag 永远落在同一个桶，避免刷新页面后灰度状态跳变
  return hashCode(`${flag.name}:${userId}`) % 100 < flag.percent
}

服务端下发配置，客户端缓存 5 分钟；配置拉取失败时使用「保守默认值」（新功能关闭）。

1.2 灰度节奏 ​

text
内部账号 → 1% → 5% → 20% → 50% → 100%

每个阶段观察至少 30 分钟，重点看：崩溃率、支付成功率、核心接口错误率、客诉关键词。任一指标越过阈值立即停止放量。

二、回滚：三类载体分别怎么做 ​

2.1 H5：制品回切 + 缓存治理 ​

bash
# 发布时保留历史目录，回滚只改软链，不重新构建
releases/1.4.2-20261104.1/
releases/1.4.2-20261103.2/
current -> releases/1.4.2-20261104.1

# 回滚
ln -sfn releases/1.4.2-20261103.2 current

两个坑：

  1. index.html 不能被长缓存，否则用户仍加载旧入口；对 index.html 设置 Cache-Control: no-cache，资源文件才用内容哈希长缓存。
  2. 回滚后要主动刷新 CDN 的 index.html，不能只改源站。

2.2 微信小程序：版本回退 ​

微信公众平台「版本管理」支持将线上版本回退到上一个版本，但有次数与时间限制。更稳的做法是：

  • 提交审核前用体验版 + 灰度人群验证；
  • 保留上一版代码包与配置，确需回退时在后台操作；
  • 服务端接口保持向后兼容至少两个版本，给回退留窗口。

2.3 App：wgt 回滚 + 安装包回退 ​

ts
// src/services/update.ts
const CURRENT_WGT = '1.4.2'
const MIN_SUPPORTED_WGT = '1.4.0' // 服务端下发，低于此版本强制更新

export async function checkUpdate() {
  const res = await updateApi.check({ current: CURRENT_WGT })
  if (res.action === 'none') return

  if (res.action === 'rollback') {
    // 服务端发现新版本异常，指示回退到 res.targetVersion
    await plus.runtime.install(res.wgtUrl, { force: true })
    return
  }

  if (compareVersion(CURRENT_WGT, MIN_SUPPORTED_WGT) < 0) {
    // 低于最低支持版本：强更，避免旧客户端打挂新接口
    uni.showModal({ title: '需要更新', content: '当前版本已停止服务', showCancel: false })
  }
}

三、App 双端流水线模板（需证书 / keystore） ​

App 端无法在普通 CI 上「开箱即跑」，下面是完整模板与所需 secrets。没有证书时流水线应在第一步明确失败，而不是产出不可用包。

3.1 所需 secrets 清单 ​

Secret用途备注

ANDROID_KEY_PASSWORD密钥口令—

APPLE_CERT_PASSWORD证书口令—

3.2 Android job ​

yaml
android:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-java@v4
      with:
        distribution: temurin
        java-version: 17
    - name: 还原签名文件
      run: |
        echo "$ANDROID_KEYSTORE_BASE64" | base64 -d > android/app/release.keystore
    - name: 构建 Release
      working-directory: android
      run: |
        ./gradlew assembleRelease \
          -Pandroid.injected.signing.store.file=app/release.keystore \
          -Pandroid.injected.signing.store.password="$ANDROID_KEYSTORE_PASSWORD" \
          -Pandroid.injected.signing.key.alias="$ANDROID_KEY_ALIAS" \
          -Pandroid.injected.signing.key.password="$ANDROID_KEY_PASSWORD"
    - uses: actions/upload-artifact@v4
      with:
        name: android-apk
        path: android/app/build/outputs/apk/release/*.apk

3.3 iOS job（macOS runner） ​

yaml
ios:
  runs-on: macos-14
  steps:
    - uses: actions/checkout@v4
    - name: 导入证书与描述文件
      run: |
        echo "$APPLE_CERT_P12_BASE64" | base64 -d > cert.p12
        security create-keychain -p "$KEYCHAIN_PASSWORD" build.keychain
        security import cert.p12 -k build.keychain -P "$APPLE_CERT_PASSWORD" -T /usr/bin/codesign
        mkdir -p ~/Library/MobileDevice/Provisioning\ Profiles
        echo "$APPLE_PROVISION_PROFILE_BASE64" | base64 -d > ~/Library/MobileDevice/Provisioning\ Profiles/profile.mobileprovision
    - name: Archive
      run: |
        xcodebuild archive \
          -workspace ios/App.xcworkspace \
          -scheme App \
          -configuration Release \
          -archivePath build/App.xcarchive \
          -allowProvisioningUpdates
    - name: Export IPA
      run: |
        xcodebuild -exportArchive \
          -archivePath build/App.xcarchive \
          -exportOptionsPlist ios/ExportOptions.plist \
          -exportPath build/ipa
    - name: Upload TestFlight
      run: |
        xcrun altool --upload-app \
          --file build/ipa/App.ipa \
          --type ios \
          --apiKey "$APP_STORE_CONNECT_API_KEY" \
          --apiIssuer "$APP_STORE_CONNECT_ISSUER_ID"

以上两段是模板：仓库内没有 Android/iOS 原生工程与证书，因此未在 CI 中执行。首次落地时必须先在本地跑通签名，再把命令原样搬进流水线。

四、发布开关与 kill switch ​

即使回滚来不及，也要有一个「关掉功能」的开关：

服务端下发的配置形如：

json
{
  "flags": {
    "checkout.v2": { "enabled": true, "percent": 10 },
    "payment.alipay": { "enabled": false },
    "home.newFeed": { "enabled": true, "rollback": true }
  }
}

客户端收到 rollback: true 时直接走旧实现，不依赖发版。开关本身要满足：

要求说明
默认关闭配置拉取失败时使用保守值
可审计谁、何时、把哪个开关改成了什么
有到期时间临时开关超过 30 天必须清理，否则技术债堆积
与代码分支对应开关删除前确认旧代码路径已无流量

五、回滚演练（必须做） ​

演练操作通过标准
H5 回滚切换 current 软链 + 刷新 CDN5 分钟内首页版本号回到上一版
开关回滚后台关闭 checkout.v21 分钟内新用户走旧结算
wgt 回滚下发旧 wgt冷启动后版本号回退，功能正常
小程序回退后台版本回退线上版本恢复，核心链路可用

回滚演练的频率：每个大版本发布前至少一次；新人入职一个月内必须参与一次。
