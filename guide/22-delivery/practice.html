22.3 实战案例：发布演练与回滚 Runbook ​

本篇是一份可以打印出来贴在工位上的发布清单：每次发版按顺序执行，任何一步失败都能明确知道「停在哪、怎么退」。

一、发布前 24 小时 ​

bash
cd ecommerce-mini-program

# 1. 全量门禁（与 CI 同一条命令）
pnpm typecheck && pnpm test:run && pnpm ci:guard

# 2. 六端构建与体积预算
pnpm build:all && pnpm ci:perf

# 3. 营销主链路 E2E（H5 + Mock）
pnpm e2e:marketing

# 4. 安全扫描（仓库根目录）
cd .. && pnpm security:scan && pnpm depcruise
检查项通过标准失败处理
类型 / 单测全绿阻断发布
体积预算主包、总体积均未超阻断，先做体积优化
E2E拼团 / 秒杀 / 直播通过阻断，定位是数据还是逻辑
安全扫描error 为 0阻断；警告需评审记录
分层检查无新增越层阻断，回退导入或走用例层
数据库变更有回滚脚本且已在预发验证阻断

1.1 本机实测记录（2026-11-05 复测） ​

步骤命令结果
H5 构建pnpm build:h5通过，7.933s，产物 dist/build/h5（主包 1029.5 KB）
微信构建pnpm build:mp-weixin通过，8.026s，产物 dist/build/mp-weixin（主包 611.7 KB）
体积预算pnpm check:budget:ci通过；H5 gzip 383.1/420 KB、微信总体积 798.2/2048 KB
营销 E2Epnpm e2e:marketing3/3 通过（拼团 1.2s、秒杀、直播）
主链路 E2Epnpm e2e:purchase3/3 通过（登录 1234ms、商详加购 1733ms、结算下单 2440ms），订单 EC840187452101
微信小程序 E2Epnpm e2e:wx未执行：uni-automator 用例已写，但开发者工具 HTTP 自动化端口未开启，启动 23.3s 后报错
微信上传pnpm ci:upload:weixin未执行：开发者工具已登录且 manifest 含 AppID，但缺少上传私钥（WX_PRIVATE_KEY_PATH）

发布链路中「构建 → 预算 → E2E」已真实跑通，H5 侧覆盖营销 3 条与主链路 3 条；「上传 → 提审」与微信端 E2E 仍需要私钥、有权限的 AppID 与自动化端口，属于外部凭证/配置阻塞，不能以本地构建通过替代。

二、发布当天：H5 与小程序 ​

2.1 H5 发布 ​

bash
VERSION="1.4.2-$(date +%Y%m%d).${GITHUB_RUN_NUMBER:-1}"

pnpm build:h5
echo "$VERSION" > dist/build/h5/version.txt
pnpm ci:perf

# 制品归档（示例：本地目录）
mkdir -p artifacts
tar -czf "artifacts/h5-${VERSION}.tar.gz" -C dist/build/h5 .

# 上传 CDN（以 OSS 为例）
ossutil cp -r dist/build/h5/assets "oss://$BUCKET/releases/${VERSION}/assets" -f
ossutil cp dist/build/h5/index.html "oss://$BUCKET/index.html" -f
ossutil cp dist/build/h5/version.txt "oss://$BUCKET/version.txt" -f

验证：

bash
curl -s "https://$DOMAIN/version.txt"
# 期望输出刚发布的 VERSION

curl -sI "https://$DOMAIN/index.html" | grep -i cache-control
# 期望：no-cache（index.html 不能被长缓存）

2.2 微信小程序发布 ​

bash
CI_VERSION="$VERSION" \
CI_DESC="发布 ${VERSION}：结算页改版 + 优惠券修复" \
WX_APPID="$WX_APPID" \
WX_PRIVATE_KEY_PATH="$WX_PRIVATE_KEY_PATH" \
pnpm ci:upload:weixin

上传后仍有三步人工动作：

  1. 微信公众平台 → 版本管理 → 将开发版设为体验版；
  2. 体验版扫码走一遍「登录 → 加购 → 下单 → 支付 → 退款申请」；
  3. 提交审核，填写版本说明与测试账号。

审核通过后：

  • 10% 灰度：使用微信「分阶段发布」能力；
  • 观察 30 分钟：崩溃率、支付成功率、客诉；
  • 逐级放量到 100%。

三、完整 GitHub Actions（H5 + 小程序双流水线） ​

yaml
name: Release

on:
  push:
    tags: ['v*']

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  verify:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: ecommerce-mini-program
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with: { version: 10 }
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          cache-dependency-path: ecommerce-mini-program/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
      - run: pnpm typecheck && pnpm test:run && pnpm ci:guard
      - run: pnpm build:all && pnpm ci:perf
      - uses: actions/upload-artifact@v4
        with:
          name: dist-${{ github.ref_name }}
          path: ecommerce-mini-program/dist/build

  h5:
    needs: verify
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: dist-${{ github.ref_name }}
          path: dist
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist/h5
      - uses: actions/deploy-pages@v4

  wechat:
    needs: verify
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: ecommerce-mini-program
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with:
          name: dist-${{ github.ref_name }}
          path: dist/build
      - uses: pnpm/action-setup@v4
        with: { version: 10 }
      - run: pnpm install --frozen-lockfile
      - name: 写入上传私钥
        run: |
          mkdir -p secrets
          printf '%s' "$WX_PRIVATE_KEY" > secrets/private.wx.key
      - run: node scripts/ci/upload.mjs mp-weixin
        env:
          WX_APPID: ${{ secrets.WX_APPID }}
          WX_PRIVATE_KEY_PATH: secrets/private.wx.key
          CI_VERSION: ${{ github.ref_name }}
          CI_DESC: ${{ github.event.head_commit.message }}
      - name: 清理私钥
        if: always()
        run: rm -rf secrets

关键点：verify 只构建一次，h5 与 wechat 都下载同一份 artifact。这样两个端发布的一定是同一个 commit 的产物。

四、回滚 Runbook ​

4.1 判定条件 ​

出现以下任一情况，立即停止放量并启动回滚评估：

  • 崩溃率较上一版本上升超过 0.2 个百分点；
  • 支付成功率下降超过 1 个百分点；
  • 核心接口错误率连续 5 分钟超过 1%；
  • 出现数据错误（金额、库存、订单状态）。

4.2 H5 回滚（目标 5 分钟） ​

bash
# 1. 切回上一个版本目录
ln -sfn "releases/$LAST_GOOD_VERSION" current

# 2. 刷新 CDN 的 index.html 与 version.txt
ossutil cp "releases/$LAST_GOOD_VERSION/index.html" oss://$BUCKET/index.html -f
ossutil cp "releases/$LAST_GOOD_VERSION/version.txt" oss://$BUCKET/version.txt -f

# 3. 验证
curl -s "https://$DOMAIN/version.txt"

4.3 小程序回滚（目标 10 分钟） ​

  1. 微信公众平台 → 版本管理 → 选择上一个线上版本 → 回退；
  2. 若接口不兼容，先在服务端打开「兼容旧版」开关；
  3. 通知客服与运营：当前版本已回退，关注客诉。

注意：回退次数有限，且审核中的版本需先撤回。因此服务端接口至少保持两个版本向后兼容。

4.4 App 回滚 ​

场景动作
前端逻辑问题下发旧 wgt，或打开 kill switch
原生代码问题应用商店提交上一版；Android 可分发旧 APK 到内测渠道
接口不兼容服务端兼容层 + 强制更新提示

五、发布后 24 小时 ​

text
□ 版本分布：新版本占比是否按预期增长
□ 崩溃率：与上一版本对比（JS / Native / ANR 分开看）
□ 支付成功率：按渠道拆分
□ 核心接口 P95：是否劣化
□ 客诉关键词：退款、闪退、白屏、支付失败
□ 体积趋势：ci:perf 的历史记录是否异常

任何一项异常，按「先止血（开关/回滚）→ 再定位 → 最后修复」的顺序处理，不要在线上边排查边改代码。

六、验收清单 ​

bash
cd ecommerce-mini-program

# 1. 从 tag 构建可复现（六端全跑）
pnpm build:h5 && test -f dist/build/h5/index.html && echo "H5 OK"
pnpm build:mp-weixin && pnpm build:mp-alipay && pnpm build:mp-toutiao && pnpm build:mp-qq && pnpm build:mp-baidu

# 2. 体积门禁
pnpm ci:perf

# 3. 安全与分层（仓库根目录）
cd .. && pnpm security:scan && pnpm security:trivy:ci && pnpm depcruise

# 4. 文档门禁
pnpm docs:build && pnpm check:snippets

security:trivy:ci 为阻断模式：HIGH / CRITICAL 任一命中即退出码 1。2026-11-05 起依赖漏洞已清零，CI 的 security job 会阻断不合规合并；.trivyignore 保持为空。

演练通过的标志：

  • 任意一个历史制品能在 5 分钟内重新部署；
  • H5 回滚后 version.txt 与预期一致；
  • 关闭开关后新用户不再进入新链路，且无需发版；
  • 发布记录里能查到「谁、何时、发了哪个版本、何时回滚」。

H5 的部署细节（Nginx、CDN、CORS、HTTPS）继续阅读 12.3 企业级 H5 发布；性能基线与体积门禁见 23.3 Lighthouse CI 与真机矩阵。
