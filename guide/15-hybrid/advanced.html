15.2 进阶应用：跨容器通信与跨端拉起 ​

一、H5 ↔ 小程序：postMessage + 双向拉起 ​

场景：独立 H5 编辑器嵌在小程序里 ​

你的团队有一个独立部署在 CDN 上的富文本编辑器（纯 Vue 3 H5 项目），现在想把它嵌进 uni-app 小程序里，让用户在小程序内也能编辑文档。用户编辑完后，小程序页面需要能拿到内容并保存。

mermaid
sequenceDiagram
    participant MP as 小程序宿主
    participant H5 as H5 编辑器
    participant CDN as 后端 API

    MP->>H5: 打开 web-view?docId=123
    H5->>CDN: GET /api/doc/123
    CDN-->>H5: 文档 JSON
    H5->>H5: 用户开始编辑

    Note over H5,MP: 保存时 H5 → 小程序
    H5->>MP: wx.miniProgram.postMessage({save, draft})
    H5->>MP: wx.miniProgram.navigateTo 携带 finalData
    Note right of MP: 收到消息触发 @message

    Note over H5,MP: 小程序 → H5（拉起编辑）
    MP->>H5: web-view src 追加参数 / ref=xxx
    H5->>MP: 监听 query 变化，重新加载

H5 侧代码（独立 Vue 3 项目） ​

ts
// h5-editor/src/bridge/mp.ts
/**
 * 小程序 <-> H5 双向桥接
 * 小程序 web-view 会自动注入 wx 对象
 */

declare global {
  interface Window {
    wx: any
    __wxjs_environment: string
    receiveFromMiniProgram: (payload: any) => void
  }
}

export function isInMiniProgram(): boolean {
  return window.__wxjs_environment === 'miniprogram'
}

/** 向小程序宿主发消息 */
export function sendToMiniProgram(type: string, data: any = {}) {
  if (!isInMiniProgram()) return

  const payload = { type, data, timestamp: Date.now() }

  // 1. postMessage（小程序在后退/分享/销毁时会收到）
  window.wx.miniProgram.postMessage({ data: payload })

  // 2. 如果需要实时触发小程序逻辑，用 navigateTo 携带参数
  //    小程序可以在 onLoad 里解析 payload
  const encoded = encodeURIComponent(JSON.stringify(payload))
  window.wx.miniProgram.navigateTo({
    url: `/pages/webview-callback/callback?payload=${encoded}`,
    fail: () => {
      // navigateTo 可能因为小程序没有这个页面而失败，降级处理
      console.warn('navigateTo 失败，仅 postMessage')
    },
  })
}

/** 接收来自小程序的消息 */
export function onReceiveFromMiniProgram(handler: (payload: any) => void) {
  window.receiveFromMiniProgram = handler
}

/** 拉起另一个小程序（wx-open-launch-weapp 场景下） */
export function launchOtherMiniProgram(appId: string, path: string) {
  if (!isInMiniProgram()) return
  window.wx.miniProgram.navigateToMiniProgram({
    appId,
    path,
    fail: (err: any) => console.warn('拉起其他小程序失败', err),
  })
}

import { ref, computed } from 'vue'

const props = defineProps<{ docId: string }>()

const editorUrl = computed(() =>
  `https://your-cdn.com/h5-editor/index.html?docId=${props.docId}&env=mp`
)

const callbackData = ref<any>(null)

/**
 * web-view 的 message 事件不是实时的，
 * 它只在：后退、组件销毁、分享、特定 navigateTo 时触发
 * 所以配合 wx.miniProgram.navigateTo 携带 payload 更可靠

function onH5Message(e: { detail: { data: any[] } }) {
  const messages = e.detail.data
  if (!messages?.length) return

  // 取最后一条（最新）
  const latest = messages[messages.length - 1]
  console.log('[web-view] 收到消息:', latest)

  if (latest?.type === 'save') {
    callbackData.value = latest.data
  }
}

function onWebviewLoad() {
  console.log('[web-view] 加载完成')
}

/** H5 通过 navigateTo 跳转到的回调页面处理完后，回消息给 H5 */
function saveAndClose() {
  uni.showToast({ title: '保存成功', icon: 'success' })
  // 返回上一页（会触发 web-view 的 @message）
  uni.navigateBack()
}

// 如果 H5 通过 wx.miniProgram.navigateTo 跳了回调页
// 需要在回调页 onLoad 里解析 payload，再 postMessage 回去
// 参见下方「H5 跳小程序页面的回调处理」
</script>

H5 跳小程序页面的回调处理（更可靠的方式） ​

ts
// pages/webview-callback/callback.vue (小程序侧)
// H5 用 navigateTo 携带 payload 跳过来的处理
onLoad(options) {
  if (options.payload) {
    const payload = JSON.parse(decodeURIComponent(options.payload))

    // 1. 处理业务逻辑（比如保存草稿到服务器）
    uni.request({
      url: `${BASE_URL}/api/draft/save`,
      method: 'POST',
      data: payload.data,
      success: () => {
        // 2. 回消息给 H5（通过 URL 参数形式，下次 H5 load 时带上）
        //    或用 web-view 的 src 变更触发 H5 重新加载
        uni.navigateBack()
      },
    })
  }
}

真实可生产的 postMessage 封装 ​

小程序 web-view 的 postMessage 有一个大问题：消息会累积成数组，而且只在特定时机触发。下面这个封装帮你解决：

ts
// utils/webview-messager.ts
/**
 * 小程序 web-view 消息管理器
 * 解决 postMessage 消息积压 + 触发时机不确定的问题
 */
type Handler = (data: any) => void

const messageQueue: any[] = []
const handlers = new Map<string, Handler>()
let processing = false

/** 注册消息处理器 */
export function registerHandler(type: string, handler: Handler) {
  handlers.set(type, handler)
  flushQueue()
}

/** 从 @message 事件里接收到原始数据后喂进来 */
export function feed(rawMessages: any[]) {
  rawMessages.forEach((msg) => {
    if (msg?.type) messageQueue.push(msg)
  })
  flushQueue()
}

function flushQueue() {
  if (processing || messageQueue.length === 0) return
  processing = true

  while (messageQueue.length > 0) {
    const msg = messageQueue.shift()!
    const handler = handlers.get(msg.type)
    if (handler) {
      try { handler(msg.data) } catch (e) { console.error(e) }
    } else {
      console.warn(`[Messager] 未注册的消息类型: ${msg.type}`, msg)
    }
  }

  processing = false
}

/**
 * 清理过期消息（避免消息堆积）
 * 比如只保留最近 5 分钟内的
 */
export function cleanupExpired() {
  const FIVE_MIN = 5 * 60 * 1000
  const now = Date.now()
  for (let i = messageQueue.length - 1; i >= 0; i--) {
    if (now - (messageQueue[i].timestamp ?? 0) > FIVE_MIN) {
      messageQueue.splice(i, 1)
    }
  }
}

二、H5 ↔ App：evalJS + plus.webview 双向通道 ​

场景：uni-app App 内嵌独立 H5 电商活动页 ​

App 首页有一个「双11活动」入口，点开后是一个独立部署的 H5 活动页。用户在 H5 里下了单，App 侧需要能拿到订单号并跳转到「我的订单」页。反过来，用户在 App 里登录后，token 需要同步注入 H5 页面。

<template>
  <view class="activity-page">

    <view class="nav-bar">

<script setup lang="ts">
// #ifdef APP-PLUS
import { onMounted, onUnmounted } from 'vue'

let h5Webview: any = null

const H5_URL = 'https://your-h5.com/activity/double11'

onMounted(async () => {
  // 1. 先等 plus API 就绪
  await new Promise<void>((resolve) => {
    plus.ready ? plus.ready(resolve) : document.addEventListener('plusready', resolve)
  })

  const currentWebview = plus.webview.currentWebview()

  // 2. 创建 H5 子 webview
  h5Webview = plus.webview.create(
    `${H5_URL}?token=${getToken()}`,
    'activity-webview',
    {
      top: '88px',     // 让出自定义导航栏高度
      bottom: '0px',
      progress: { color: '#ff4444', height: '2px' },
      scalable: false,
    },
    {
      // 额外参数，H5 侧可以通过 plus.webview.currentWebview().getURL() 带参数
      userId: getUserId(),
      theme: 'dark',
    }
  )

  // 3. 监听 H5 发来的消息
  h5Webview.addEventListener('customEvent', onH5Message)
  h5Webview.addEventListener('close', onH5Close)

  currentWebview.append(h5Webview)
})

onUnmounted(() => {
  h5Webview?.removeEventListener('customEvent', onH5Message)
  h5Webview?.close('none')
})

function getToken() {
  return uni.getStorageSync('token') ?? ''
}

/** H5 通过 postMessageToUniNView 发来的消息 */
function onH5Message(evt: { detail: any }) {
  const msg = evt.detail
  console.log('[App ← H5]', msg)

  switch (msg.action) {
    case 'orderCreated':
      uni.navigateTo({ url: `/pages/order/detail?orderId=${msg.data.orderId}` })
      break
    case 'needLogin':
      uni.showModal({
        title: '提示',
        content: '需要先登录',
        success: (r) => r.confirm && uni.navigateTo({ url: '/pages/login/login' }),
      })
      break
    case 'share':
      uni.shareWithSystem({ summary: msg.data.shareText })
      break
  }
}

/** 向 H5 注入消息 */
function sendMessage() {
  if (!h5Webview) return
  h5Webview.evalJS(`
    if (typeof window.onAppMessage === 'function') {
      window.onAppMessage(${JSON.stringify({
        type: 'tokenRefreshed',
        token: getToken(),
      })})
    }
  `)
}

function closeWebview() {
  uni.navigateBack()
}
// #endif
</script>

H5 侧（跑在 uni-app App 的 web-view 里） ​

ts
// h5-activity/src/bridge/app.ts
declare global {
  interface Window {
    plus: any
    onAppMessage: (payload: any) => void
  }
}

export function isInUniApp(): boolean {
  return /uni-app/i.test(navigator.userAgent) || !!window.plus
}

/** 向 uni-app App 宿主发消息 */
export function sendToApp(action: string, data: any = {}) {
  if (!isInUniApp()) return

  // HTML5+ webview 专属 API
  try {
    const current = window.plus.webview.currentWebview()
    if (!current) return

    // 方式一：postMessageToUniNView（App 宿主通过 'customEvent' 监听）
    current.postMessageToUniNView(
      { action, data, ts: Date.now() },
      'customEvent'
    )

    // 方式二：evalJS 调用宿主暴露的全局函数
    // 宿主侧需要 window.onH5Message = function(payload){}
    const hostWebview = current.parent?.() ?? current.opener?.()
    if (hostWebview) {
      hostWebview.evalJS(`
        if (typeof window.onH5Message === 'function') {
          window.onH5Message(${JSON.stringify({ action, data })})
        }
      `)
    }
  } catch (e) {
    console.warn('[Bridge] 向 App 发消息失败:', e)
  }
}

/** 接收来自 App 宿主的消息 */
export function onAppMessage(handler: (payload: any) => void) {
  window.onAppMessage = handler
}

通用桥接层（H5 一次写，三端兼容） ​

如果你在写一个独立 H5 页面，它可能被 App web-view 也可能被小程序 web-view 加载，写一层通用桥接是必选项：

ts
// h5-common/src/bridge/universal-bridge.ts
/**
 * 三端通用桥接层
 * 自动检测容器环境，调用对应的通信方式
 */

type Env = 'app' | 'mp-weixin' | 'h5'

export function detectEnv(): Env {
  if (window.__wxjs_environment === 'miniprogram') return 'mp-weixin'
  if (/uni-app/i.test(navigator.userAgent) || !!window.plus) return 'app'
  return 'h5'
}

export function post(action: string, data: any = {}) {
  const env = detectEnv()
  const payload = { action, data, ts: Date.now() }

  switch (env) {
    case 'mp-weixin':
      window.wx?.miniProgram?.postMessage?.({ data: payload })
      break
    case 'app':
      try {
        const cur = window.plus?.webview?.currentWebview?.()
        cur?.postMessageToUniNView?.(payload, 'customEvent')
      } catch (e) { /* ignore */ }
      break
    case 'h5':
      // 纯 H5 环境，用 BroadcastChannel 或 window.open 的 postMessage
      if (opener) opener.postMessage(payload, '*')
      break
  }
}

export function on(handler: (payload: any) => void) {
  // App 宿主 evalJS 会调用 window.onBridgeMessage
  window.onBridgeMessage = handler

  // 纯 H5 环境下监听
  window.addEventListener('message', (e) => {
    if (e.data?.action) handler(e.data)
  })
}

三、App ↔ 原生 SDK：requireNativePlugin 完整桥接层 ​

标准调用模式 ​

uni.requireNativePlugin 的核心范式：封装成一个 Service 类 → 用条件编译隔离 → JS 侧回调 Promise 化。

ts
// src/services/amap.ts
/**
 * 高德地图原生插件桥接层
 * HBuilderX 插件市场搜索「高德地图 3D」勾选后即可使用
 */

type LocationCallback = (result: {
  code: number
  latitude?: number
  longitude?: number
  address?: string
  message?: string
}) => void

// 只有在 App 端才 requireNativePlugin
// #ifdef APP-PLUS
const amap = uni.requireNativePlugin('AMap3DMap')
// #endif

export const AMapService = {
  /**
   * 单次定位
   */
  getCurrentLocation(): Promise<{ lat: number; lng: number; address: string }> {
    return new Promise((resolve, reject) => {
      // #ifdef APP-PLUS
      amap.getCurrentLocation(
        {
          accuracy: 'high',    // high: 高精度, low: 低功耗
          timeout: 10000,      // 10 秒超时
          isNeedAddress: true,  // 是否返回逆地理编码
        },
        (res: LocationCallback) => {
          if (res.code === 0) {
            resolve({
              lat: res.latitude!,
              lng: res.longitude!,
              address: res.address ?? '',
            })
          } else {
            reject(new Error(res.message ?? '定位失败'))
          }
        }
      )
      // #endif

      // #ifndef APP-PLUS
      // 小程序 / H5 端降级：用 uni.getLocation
      uni.getLocation({
        type: 'gcj02',
        success: (r) => resolve({ lat: r.latitude, lng: r.longitude, address: '' }),
        fail: (e) => reject(e),
      })
      // #endif
    })
  },

  /**
   * 持续定位（常用于打车、外卖场景）
   * 返回一个取消函数
   */
  startContinuousUpdates(onUpdate: (loc: { lat: number; lng: number }) => void): () => void {
    // #ifdef APP-PLUS
    amap.startContinuousLocation({ interval: 2000 }, (res: any) => {
      if (res.code === 0 && res.latitude) {
        onUpdate({ lat: res.latitude, lng: res.longitude })
      }
    })
    return () => amap.stopContinuousLocation()
    // #endif

    // #ifndef APP-PLUS
    console.warn('连续定位仅 App 端支持')
    return () => {}
    // #endif
  },

  /**
   * 打开原生地图选点界面（比如配送地址选择）
   */
  async pickLocation(): Promise<{ lat: number; lng: number; poiName: string }> {
    // #ifdef APP-PLUS
    return new Promise((resolve, reject) => {
      amap.openPOISearchPicker({}, (res: any) => {
        if (res.code === 0) {
          resolve({
            lat: res.latitude,
            lng: res.longitude,
            poiName: res.poiName,
          })
        } else {
          reject(new Error(res.message))
        }
      })
    })
    // #endif

    // #ifndef APP-PLUS
    // 降级：小程序端用腾讯地图选点组件
    return Promise.reject(new Error('请在 App 端使用'))
    // #endif
  },
}

三端条件编译的威力 ​

上面的代码里三次出现 // #ifdef APP-PLUS 块。uni-app 编译器在构建时会把不属于目标平台的代码块彻底删掉——小程序包里完全不会有 requireNativePlugin 相关的代码，H5 包里只会有 uni.getLocation 的降级逻辑。这就是零运行时开销的跨端桥接。

后端流程（简化 Node.js） ​

ts
// server/src/routes/auth.ts
import express from 'express'
import jwt from 'jsonwebtoken'
import axios from 'axios'

const router = express.Router()

// 微信开放平台的 AppID / AppSecret（统一管理小程序和 App）
const WX_MP = { appId: process.env.WX_MP_APPID, secret: process.env.WX_MP_SECRET }
const WX_APP = { appId: process.env.WX_APP_APPID, secret: process.env.WX_APP_SECRET }

const JWT_SECRET = process.env.JWT_SECRET!

/**
 * 小程序 / App 都用同一个接口，前端传 platform 区分
 */
router.post('/login-by-wx', async (req, res) => {
  const { code, platform } = req.body as { code: string; platform: 'mp' | 'app' }

  const { appId, secret } = platform === 'mp' ? WX_MP : WX_APP

  // 1. 用 code 换 access_token + openid + unionid
  const wxRes = await axios.get(
    `https://api.weixin.qq.com/sns/jscode2session`,
    { params: { appid: appId, secret, js_code: code, grant_type: 'authorization_code' } }
  )

  const { openid, unionid, session_key, errcode, errmsg } = wxRes.data
  if (errcode) return res.status(400).json({ msg: errmsg })

  // 2. 查找或创建用户（unionid 是唯一锚点）
  let user = await db.users.findOne({ unionid })
  if (!user) {
    user = await db.users.create({
      unionid,
      openid_mp: platform === 'mp' ? openid : null,
      openid_app: platform === 'app' ? openid : null,
    })
  } else {
    // 如果之前只在一端登录，现在补齐另一端的 openid
    if (platform === 'mp' && !user.openid_mp) user.openid_mp = openid
    if (platform === 'app' && !user.openid_app) user.openid_app = openid
    await user.save()
  }

  // 3. 签发 JWT
  const token = jwt.sign(
    { userId: user._id, unionid, platform },
    JWT_SECRET,
    { expiresIn: '30d' }
  )

  res.json({
    code: 0,
    data: { token, userId: user._id, unionid },
  })
})

/**
 * JWT 验证中间件（H5 也能用 cookie 自动携带）
 */
export const authMiddleware = (req, res, next) => {
  const token =
    req.headers.authorization?.replace('Bearer ', '') ||   // App / 小程序
    req.cookies?.token                                      // H5 cookie 同步

  if (!token) return res.status(401).json({ msg: '未登录' })

  try {
    req.user = jwt.verify(token, JWT_SECRET)
    next()
  } catch {
    res.status(401).json({ msg: 'Token 过期或无效' })
  }
}

小程序 / App 前端登录 ​

ts
// src/services/auth.ts
/** 三端统一登录入口 */
export async function wxLogin(platform: 'mp' | 'app') {
  // 1. 小程序用 uni.login，App 也用 uni.login（内部调微信 SDK）
  const loginRes = await new Promise<UniApp.LoginRes>((resolve, reject) => {
    uni.login({
      provider: 'weixin',
      success: resolve,
      fail: reject,
    })
  })

  // 2. 发给后端换 JWT
  const { data } = await uni.request({
    url: `${BASE_URL}/api/auth/login-by-wx`,
    method: 'POST',
    data: { code: loginRes.code, platform },
  })

  if (data.code === 0) {
    uni.setStorageSync('token', data.data.token)
    uni.setStorageSync('userId', data.data.userId)
    return data.data
  }

  throw new Error(data.msg)
}

H5 cookie 同步（关键一环） ​

三端统一登录里，H5 的 token 同步是最容易踩坑的部分。正确做法：

  1. 小程序 / App 登录后，把 JWT 以 token 字段存下来。
  2. 打开 H5 页时，URL 携带 ?jwt=xxx 参数。
  3. H5 首次加载时，用 query 参数里的 jwt 调 /api/auth/set-cookie 把 token 写到 cookie。
  4. 后续 H5 的请求走 cookie 自动携带（axios withCredentials: true）。
ts
// h5-editor/src/main.ts（H5 入口）
const urlParams = new URLSearchParams(location.search)
const jwtFromQuery = urlParams.get('jwt')

if (jwtFromQuery) {
  // 让后端把 JWT 写进 HttpOnly Cookie
  fetch(`${API_BASE}/api/auth/set-cookie`, {
    method: 'POST',
    credentials: 'include',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ token: jwtFromQuery }),
  }).finally(() => {
    // 清理 URL
    history.replaceState({}, '', location.pathname)
  })
}

六、FAQ ​

Q1：为什么不直接用 URL query 传大对象？

URL 有长度限制（不同浏览器/容器差异大，通常 2KB~8KB）。传大对象时务必用 postMessage，或者分两步：先传一个 ref id，再让接收方用这个 id 去后端拉完整数据。

Q2：小程序 web-view 跳转其他小程序的 wx-open-launch-weapp 和 wx.miniProgram.navigateToMiniProgram 有什么区别？

  • wx.open-launch-weapp 是 H5 里的一个自定义标签（类似 button），用户点击后才能拉起另一个小程序。适合活动页里的「跳转到商城小程序」场景。
  • wx.miniProgram.navigateToMiniProgram 是 JSSDK 方法，可以在 JS 里直接调用（不需要用户点击），但只能在「小程序内打开另一个小程序」场景下用，H5 里不能用。

Q3：unionid 不是所有用户都有？

对。用户必须关注过你的公众号 / 登录过你的小程序 / 安装过你的 App 后，微信才会在对应的 jscode2session 响应里返回 unionid。第一次登录的用户可能只有 openid。所以后端要做「unionid 关联延迟」的设计：如果这次返回了 unionid，就把之前只有 openid 的记录合并到同一个用户下。

Q4：plus.webview.evalJS 有什么限制？

  • evalJS 的目标 webview 必须是你创建的或者当前页的父子关系，不能跨层级 evalJS。
  • evalJS 字符串不能超过 1MB（超过会被 HTML5+ 引擎截断），大对象要先 stringify 再考虑分片。
  • evalJS 是异步执行的，不能指望它立刻有返回值——需要 H5 侧再用 postMessage 回传结果。
