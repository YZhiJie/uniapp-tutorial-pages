8.2 进阶应用：分包、长列表、图片与包体积优化 ​

一、分包：把首屏不需要的代码移出主包 ​

jsonc
// pages.json
{
  "pages": [
    { "path": "pages/index/index" },
    { "path": "pages/goods/list" },
    { "path": "pages/goods/detail" }
  ],
  "subPackages": [
    {
      "root": "pages/order",
      "pages": [
        { "path": "confirm" },
        { "path": "list" },
        { "path": "detail" }
      ]
    },
    {
      "root": "pages/marketing",
      "pages": [{ "path": "lottery" }, { "path": "invite" }]
    }
  ],
  "preloadRule": {
    "pages/goods/detail": {
      "network": "wifi",
      "packages": ["pages/order"]
    }
  }
}

策略：

  1. 主包只放 tabBar 页与公共依赖；订单、活动、设置等低频页面进分包。
  2. 按业务域分包，兼顾独立下载与团队边界；分包之间避免互相引用页面，公共代码放主包或独立分包（微信「独立分包」适用按需启动场景）。
  3. 用 preloadRule 在 WiFi 下预下载高概率进入的分包，用户点进去时已经就绪；蜂窝网络下谨慎预加载。
  4. 分包内引用的图片放分包目录，随分包下载而非打进主包。

微信端还可开启按需注入与注入占位组件：

jsonc
// manifest.json → mp-weixin 配置
{
  "mp-weixin": {
    "lazyCodeLoading": "requiredComponents"
  }
}

二、长列表：分页 + 虚拟滚动 ​

基础：触底分页 ​

vue
<template>
  <view class="list">
    <view v-for="item in list" :key="item.id" class="row">{{ item.title }}</view>
    <view class="status">{{ statusText }}</view>
  </view>
</template>

<script setup lang="ts">
import { ref } from 'vue'
import { onReachBottom } from '@dcloudio/uni-app'

interface Row { id: number; title: string }
const list = ref<Row[]>([])
const page = ref(1)
const loading = ref(false)
const finished = ref(false)

async function load() {
  if (loading.value || finished.value) return
  loading.value = true
  try {
    const res = await goodsApi.list({ page: page.value, size: 20 })
    list.value.push(...res.list)
    finished.value = list.value.length >= res.total
    page.value++
  } finally {
    loading.value = false
  }
}

onReachBottom(() => load())
load()

const statusText = computed(() =>
  loading.value ? '加载中…' : finished.value ? '没有更多了' : '上拉加载更多'
)
</script>

进阶：上千行用虚拟列表 ​

原理：容器只渲染可视区 + 上下缓冲的节点，用一个等高占位元素撑出总滚动高度，滚动时更新可见区间。下面的演练场内置 10,000 条数据，可以切换「普通渲染」直观对比掉帧：

在 uni-app 中落地要点：

  • 固定行高（64rpx/96rpx）是最简单高效的方案；可变行高需缓存测量值，复杂度高，优先重新设计 UI。
  • 用 scroll-view + @scroll（节流到一帧一次）计算 start/end。
  • App 端可评估官方/社区 recycle 方案；跨端通用时手写虚拟列表更可控。

三、数据更新：减少通信量与频率 ​

ts
// ❌ 反例：高频、全量大对象
watch(inputText, (val) => {
  pageData.allResults = search(val) // 每次输入整表替换
})

// ✅ 正例：防抖 + 局部更新 + 最小 payload
import { debounce } from '@/utils/debounce'
const onSearch = debounce(async (kw: string) => {
  const list = await api.search(kw)
  resultList.value = list // 只更新结果列表这一个字段
}, 300)

防抖效果可在演练场直接修改参数对比请求次数：

其他规则：

  • 定时器、滚动回调里的状态修改合并到下一帧（requestAnimationFrame 思路；小程序可节流到 100ms）。
  • 与渲染无关的数据（接口原始报文、计时器 id）不放进响应式对象，用普通变量。
  • 列表更新用「追加/局部修改」，避免整表重新赋值导致全量 diff。
  • 复杂表单用 v-model.lazy（H5）或在 blur 时提交，减少输入期更新。

四、图片优化（投入产出比最高） ​

  1. 格式：WebP/AVIF（小程序支持 WebP），同画质体积减半。
  2. 尺寸：CDN 图片处理参数按容器尺寸请求，不要加载 1080px 原图显示 200rpx 缩略图。
  3. 懒加载：<image lazy-load>（小程序/部分端支持）；H5 由浏览器原生 loading 或 IntersectionObserver。
  4. 占位：骨架屏或低质量占位图（LQIP），降低白屏感知。
  5. 雪碧图/图标：小图标用 iconfont（注意小程序字体加载规则）或 base64（只对极小图标）。
  6. 长列表中图片给固定宽高，避免图片加载后回流（CLS）。

五、包体积治理 ​

  • 定期在构建产物中按体积排序找大头：未使用的大 npm 库、未压缩的 JSON、整包引入的工具库（import _ from 'lodash' → 按需引入或 es-toolkit）。
  • 地图、图表、富文本解析等重型库评估动态加载/分包加载。
  • 静态资源上 CDN，本地只留 tabBar 等必须离线的图。
  • 去除 console 与 sourcemap（生产包按平台配置）。
  • Tree-shaking 友好：只使用 ESM 具名导入，不导出大而全的 barrel 文件。

六、启动链路提速清单 ​

  1. onLaunch 中不做阻塞首屏的请求；登录态从本地读取即可渲染。
  2. 首屏数据在 onLoad 立即发起（而不是等组件 mounted）；两个独立接口并行 Promise.all。
  3. 首屏先展示骨架/缓存数据，二次进入用「缓存先渲染 + 后台刷新」（stale-while-revalidate）。
  4. 合并埋点 SDK 初始化等非关键逻辑到首屏后。
  5. 小程序控制同步 API：getStorageSync 等在启动路径上的调用保持个位数。

常见问题 ​

Q：开了分包后引用报错？ 分包不可引用其他分包的私有模块；公共代码放主包 src/shared（会增加主包体积，权衡），或使用分包异步化能力。

Q：虚拟列表闪烁/白屏？ 缓冲区太小（建议 ≥ 一屏）；滚动节流过于激进；图片高度未固定导致回流。逐步排查这三点。

Q：图片在小程序端不懒加载？lazy-load 仅在 page 与 scroll-view 内生效，自定义容器/Swiper 中需自行实现可见性判断。
