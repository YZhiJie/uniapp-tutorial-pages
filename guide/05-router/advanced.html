5.2 进阶应用：路由拦截、鉴权守卫与页面通信 ​

为什么需要拦截器 ​

业务中大量页面需要登录：订单、收藏、发布内容。如果每个页面 onLoad 都写一遍 token 判断，极易漏网。uni-app 提供 uni.addInterceptor 可以拦截路由 API。

封装统一路由守卫 ​

ts
// src/utils/router-guard.ts
const WHITE_LIST = new Set([
  '/pages/index/index',
  '/pages/login/index',
  '/pages/goods/list',
  '/pages/goods/detail'
])

function isLoggedIn() {
  return Boolean(uni.getStorageSync('token'))
}

/** 拼接完整路径（含 query），并解析出纯 path */
function resolvePath(url: string) {
  return url.split('?')[0]
}

function guard(options: { url: string }, defaultNext: () => void) {
  const path = resolvePath(options.url)
  if (WHITE_LIST.has(path) || isLoggedIn()) {
    defaultNext()
    return
  }
  // 记录目标页，登录成功后回跳
  const redirect = encodeURIComponent(options.url)
  uni.redirectTo({ url: `/pages/login/index?redirect=${redirect}` })
}

export function setupRouterGuard() {
  ;['navigateTo', 'redirectTo', 'reLaunch', 'switchTab'].forEach((api) => {
    uni.addInterceptor(api, {
      invoke(args: { url: string }) {
        guard(args, () => {
          // 放行：invoke 返回 true 继续原跳转
        })
        // invoke 同步模型：返回 false 可中止；这里通过自定义标志控制
        const path = resolvePath(args.url)
        return WHITE_LIST.has(path) || isLoggedIn()
      },
      fail(err) {
        console.warn('[router] 跳转失败', err)
      }
    })
  })
}

上面展示了拦截器的注册方式；实际项目里更常用「拦截 + 手动重放」模式，语义更清晰：

ts
// src/utils/router-guard.ts（推荐版）
uni.addInterceptor('navigateTo', {
  invoke(args) {
    const path = args.url.split('?')[0]
    if (WHITE_LIST.has(path) || isLoggedIn()) return true

    uni.showToast({ title: '请先登录', icon: 'none' })
    const redirect = encodeURIComponent(args.url)
    setTimeout(() => {
      uni.redirectTo({ url: `/pages/login/index?redirect=${redirect}` })
    }, 300)
    return false // 中止本次跳转
  }
})

在 App.vue 的 onLaunch 中安装：

vue
<script setup lang="ts">
import { onLaunch } from '@dcloudio/uni-app'
import { setupRouterGuard } from '@/utils/router-guard'

onLaunch(() => {
  setupRouterGuard()
})
</script>

WARNING

switchTab 的 url 不带 query，需要参数时通过 store 传递。reLaunch 一般用于登录/登出，通常直接放行，避免守卫死循环。

登录页处理回跳 ​

ts
// pages/login/index.vue
import { onLoad } from '@dcloudio/uni-app'

let redirect = '/pages/index/index'
onLoad((query) => {
  if (query?.redirect) redirect = decodeURIComponent(String(query.redirect))
})

async function onLogin() {
  await loginApi({ phone, code })
  uni.showToast({ title: '登录成功', icon: 'success' })

  // tabBar 页必须 switchTab，其余 reLaunch 清栈进入
  const tabPages = ['/pages/index/index', '/pages/cart/index', '/pages/mine/index']
  const path = redirect.split('?')[0]
  if (tabPages.includes(path)) {
    uni.switchTab({ url: path })
  } else {
    uni.reLaunch({ url: redirect })
  }
}

页面通信方案一：eventChannel（A → B → 回传 A） ​

选择地址、选择商品等「打开新页选择后回传」场景：

ts
// A 页：打开选择页并监听回传
uni.navigateTo({
  url: '/pages/address/picker',
  events: {
    // B 页 emit('selected', data) 时触发
    selected(data: { id: number; detail: string }) {
      address.value = data
    }
  },
  success(res) {
    // 也可主动向 B 页发数据
    res.eventChannel.emit('preselect', { id: currentId.value })
  }
})
ts
// B 页：选择后回传
const instance = getCurrentPages().pop()!
const eventChannel = (instance as any).getOpenerEventChannel?.()

function choose(addr: Address) {
  eventChannel?.emit('selected', addr)
  uni.navigateBack()
}

// 接收 A 页预填数据
eventChannel?.on('preselect', (data: { id: number }) => {
  currentId.value = data.id
})

页面通信方案二：全局状态 + onShow 刷新 ​

返回上一页刷新数据（购物车角标、列表状态）更推荐状态驱动：

ts
// A 页
onShow(() => {
  cartStore.fetchCount()
})

// B 页完成操作后只改 store
cartStore.add(goods)
uni.navigateBack()
// A 页 onShow 自动感知，无需事件耦合

选型口诀：一次性、强相关的回调用 eventChannel；持续性、多页面共享的数据用 Pinia。

tabBar 角标与红点 ​

ts
// 购物车数量变化时
uni.setTabBarBadge({ index: 1, text: String(count) })
// 无具体数字
uni.showTabBarRedDot({ index: 1 })
// 移除
uni.removeTabBarBadge({ index: 1 })

数字超过 99 建议显示「99+」，避免角标撑破布局。

拦截器的常见坑 ​

  1. 重复注册：热更新可能重复执行 onLaunch，守卫注册逻辑要保证幂等（模块级标志位）。
  2. 拦截不到：navigateBack 没有标准 invoke 拦截语义，返回拦截用页面 onBackPress（App/H5）或在返回前主动 navigateBack 的业务封装。
  3. 白名单维护：详情页常需要「未登录可看，下单才拦」——放行页面、拦截动作（按钮点击再跳登录），不要一刀切。
  4. 小程序启动场景：扫码进入的场景参数在 onLaunch(options) 中，需配合路由守卫做「落地页 + 登录后重放」。

常见问题 ​

Q：H5 端能用 vue-router 守卫吗？ uni-app H5 端内部有适配路由，但业务代码统一用 uni.* API + addInterceptor，不要直接操作 vue-router 实例，否则小程序端无法编译。

Q：如何做路由切换动画/转场埋点？ 转场样式由平台控制；埋点可在拦截器 invoke 统一上报 path，再配合页面 onShow 计算停留时长。
