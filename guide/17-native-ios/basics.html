17.1 基础入门：Xcode 工程结构与 Swift / Objective-C ​

iOS 侧的门槛比 Android 更「硬」：必须有 Mac、必须有 Apple Developer 账号、签名链路更长。但真正让前端同学卡住的通常不是语言，而是 Xcode 工程、CocoaPods、证书与描述文件这三件套。

本章先建立 iOS 原生开发的最小认知：工程长什么样、Swift/ObjC 怎么写、依赖怎么管、调试怎么看。下一章再写 uni-app 的 WXModule / WXComponent。

一、环境准备 ​

1.1 必备工具 ​

工具作用检查命令
macOS唯一能完整构建 iOS 的系统sw_vers
Xcode 15/16编译器、模拟器、签名、Instrumentsxcodebuild -version
Command Line Toolsxcodebuild、xcrun、simctlxcode-select -p
CocoaPods三方 SDK 依赖管理pod --version
Apple Developer 账号真机调试 / 上架developer.apple.com
bash
# 安装 Command Line Tools
xcode-select --install

# 接受许可
sudo xcodebuild -license accept

# 安装 CocoaPods（推荐用 Homebrew 管理 Ruby 环境）
brew install cocoapods
pod --version

# 查看可用模拟器
xcrun simctl list devices available

1.2 版本基线 ​

项推荐值说明
Xcode15.4+上架 App Store 要求当年新版 SDK
iOS Deployment Target13.0–15.0太低会被审核质疑，太高丢用户
Swift5.9+与 Xcode 配套
CocoaPods1.15+老版本对 Xcode 16 兼容差

企业项目在 Podfile 里锁定 platform :ios, '13.0'，并在 CI 固定 Xcode 版本，避免「本地能 archive，CI 签名失败」。

二、Xcode 工程结构 ​

一个典型的 iOS App / Framework 工程：

text
UniDemoNative/
├── UniDemoNative.xcodeproj/          # 工程文件（project.pbxproj 是核心）
├── UniDemoNative/
│   ├── AppDelegate.swift             # 应用入口（SwiftUI 项目为 App.swift）
│   ├── SceneDelegate.swift           # 多窗口 / 生命周期
│   ├── ViewController.swift          # 页面
│   ├── Info.plist                    # 权限、URL Scheme、ATS 等
│   ├── Assets.xcassets/              # 图片、颜色、AppIcon
│   ├── PrivacyInfo.xcprivacy         # 隐私清单（上架必需）
│   └── UniDemoNative-Bridging-Header.h  # Swift 调 ObjC 的桥接头
├── Podfile                           # CocoaPods 依赖声明
├── Podfile.lock                      # 锁定版本，必须提交
└── UniDemoNative.xcworkspace/        # pod install 后用它打开工程

2.1 关键文件职责 ​

文件作用常见错误
project.pbxproj工程配置（target、build phase、签名）手改易坏，优先用 Xcode UI
Info.plist权限文案、CFBundleIdentifier、URL Scheme缺隐私文案被拒
Podfile依赖与 platform忘记 use_frameworks! 导致 Swift 库不可用
Podfile.lock依赖锁定不提交导致团队版本漂移
PrivacyInfo.xcprivacy声明数据采集与 API 使用上架 ITMS-91053 警告

2.2 Target 与 Scheme ​

  • Target：真正产出二进制的单元（App、Framework、Extension）。
  • Scheme：开发时的构建/运行配置（Debug/Release、测试、Archive）。
  • 插件通常是 Framework target，产物是 .framework。
bash
# 查看工程里的 scheme
xcodebuild -list -project UniDemoNative.xcodeproj

三、Swift / Objective-C 必须掌握的最小语法 ​

uni-app 的 iOS 插件接口是 Objective-C 协议（WXModuleProtocol / WXComponent）。你可以用 Swift 写，但必须理解 ObjC 的类、消息、协议与内存管理。

3.1 Swift 基础 ​

swift
// 值类型 vs 引用类型
struct DeviceInfo {          // 值类型，赋值即拷贝
    let brand: String
    let model: String
}

final class DemoBridge {     // 引用类型，class 才能继承 NSObject
    var onResult: ((DeviceInfo) -> Void)?

    func emit(_ info: DeviceInfo) {
        onResult?(info)      // 可选闭包调用
    }
}
Swift 概念对应 ObjC说明
class@interface引用类型
struct无直接对应值类型，不能暴露给 ObjC
protocol@protocol协议
extensionCategory扩展方法
@objc暴露给运行时Swift 方法要能被 ObjC 调用必须加
weak / unownedweak / assign避免循环引用

3.2 Swift 调 ObjC：桥接头 ​

objc
// UniDemoNative-Bridging-Header.h
#import <WeexSDK/WXModuleProtocol.h>
#import <WeexSDK/WXSDKInstance.h>
swift
// Swift 模块
@objc(NativeDemoModule)
final class NativeDemoModule: NSObject, WXModuleProtocol {
    weak var weexInstance: WXSDKInstance?

    @objc(getDeviceInfo:callback:)
    func getDeviceInfo(_ options: [String: Any], callback: @escaping WXModuleCallback) {
        callback([
            "code": 0,
            "data": [
                "model": UIDevice.current.model,
                "osVersion": UIDevice.current.systemVersion
            ]
        ])
    }
}

@objc(NativeDemoModule) 决定运行时类名，必须与插件 package.json 里的 class 一致。

3.3 Objective-C 基础 ​

objc
// 类声明
@interface NativeDemoModule : NSObject <WXModuleProtocol>
@property (nonatomic, weak) WXSDKInstance *weexInstance;
@end

// 方法声明：带两个参数
- (void)getDeviceInfo:(NSDictionary *)options callback:(WXModuleCallback)callback;
概念说明
strong / weak / copy属性内存语义；delegate、callback 用 weak/copy
ARC自动引用计数，但循环引用仍需手动破
Block闭包；捕获 self 容易循环引用，用 __weak typeof(self) weakSelf = self;
@protocol协议；WXModuleProtocol 就是
Category给类加方法，不能加属性（除非关联对象）

bash

4.2 常见问题 ​

现象原因处理
[!] Unable to find a specification本地索引旧 / 源不可达pod repo update，检查网络代理
use of undeclared identifier用了 .xcodeproj 而不是 .xcworkspace重新打开 workspace
Swift 库提示 module not found缺 use_frameworks!加上后 pod install
架构冲突 arm64模拟器与真机架构不同EXCLUDED_ARCHS[sdk=iphonesimulator*] = arm64（Apple Silicon 注意）
Podfile.lock 冲突多人升级了不同版本统一版本后重新 pod install

五、UIViewController 生命周期与线程 ​

5.1 生命周期 ​

text
init → loadView → viewDidLoad → viewWillAppear → viewDidAppear
     → viewWillDisappear → viewDidDisappear → deinit

插件相关的注意点：

  • 在 viewDidLoad 里做一次性初始化；不要在 init 里访问 view。
  • 页面消失时暂停相机 / 定位 / 动画，viewDidAppear 再恢复。
  • deinit 里注销通知、释放资源；ARC 不会帮你注销 NotificationCenter（iOS 9+ 弱引用后部分场景可省略，但显式注销更稳）。

5.2 线程模型 ​

队列用途规则
Main QueueUI 更新所有 UI 操作必须回主线程
Global Queue网络 / 文件 / 计算不能直接改 UI
Serial Queue有序任务避免竞态
swift
DispatchQueue.global(qos: .userInitiated).async {
    let data = self.fetchData()
    DispatchQueue.main.async {
        self.updateUI(data)   // 回主线程
    }
}

六、LLDB 与 Instruments ​

6.1 LLDB 常用命令 ​

text
po self.view            # 打印对象
p someValue             # 打印基础类型
bt                      # 调用栈
thread list             # 所有线程
breakpoint set -n "-[NativeDemoModule getDeviceInfo:callback:]"
continue

Xcode 调试技巧：

  • View Debugger：运行时点「调试视图层次」，直接看原生 View 的 frame 与层级。
  • Breakpoint Condition：只在高频异常时命中，例如 deviceModel == "iPhone15,2"。
  • Zombie Objects：排查「message sent to deallocated instance」。

6.2 Instruments ​

工具用途典型问题
Time ProfilerCPU 热点主线程卡顿、重复计算
Allocations内存分配大图、频繁创建对象
Leaks内存泄漏Block 循环引用、未注销监听
Zombies野指针访问已释放对象
Network网络请求重复请求、大包体

启动方式：Xcode → Product → Profile（⌘I）→ 选择模板。
