17.2 进阶应用：WXModule 的 .m 实现与 WXComponent ​

iOS 插件同样只有两种形态：无 UI 的 WXModule 和有 UI 的 WXComponent。与 Android 不同的是，iOS 侧没有注解，靠 协议 + 宏 + 运行时类名 完成注册。

本章给出可直接编译的 Objective-C 实现，并说明 Swift 混编、Framework 构建、内存与线程的工程约束。

一、iOS 插件的注册链路 ​

text
uni.requireNativePlugin('UniNativeDemo')
        │
        ▼
nativeplugins/UniNativeDemo/package.json
        │  class: "NativeDemoModule"
        ▼
Objective-C 运行时类 NativeDemoModule
        │  WX_EXPORT_METHOD(@selector(getDeviceInfo:callback:))
        ▼
JS 侧 plugin.getDeviceInfo({}, cb)

四个对齐点：

  1. package.json 的 id 与 requireNativePlugin 一致。
  2. iOS plugins[].class 与 @implementation 的类名一致（不是文件名）。
  3. 方法用 WX_EXPORT_METHOD 导出，选择器参数数量与 JS 调用一致。
  4. 产物 .framework 放进 nativeplugins/<id>/ios/。

二、WXModule：Objective-C 实现 ​

2.1 头文件 ​

objc
// nativeplugins/UniNativeDemo/ios/NativeDemoModule.h
#import <Foundation/Foundation.h>
#import <WeexSDK/WXModuleProtocol.h>

NS_ASSUME_NONNULL_BEGIN

@interface NativeDemoModule : NSObject <WXModuleProtocol>

/// weex 注入的实例，弱引用，避免循环引用
@property (nonatomic, weak) WXSDKInstance *weexInstance;

@end

NS_ASSUME_NONNULL_END

2.2 实现文件 ​

objc
// nativeplugins/UniNativeDemo/ios/NativeDemoModule.m
#import "NativeDemoModule.h"
#import <UIKit/UIKit.h>

@implementation NativeDemoModule

// 导出给 JS：plugin.getDeviceInfo({}, callback)
WX_EXPORT_METHOD(@selector(getDeviceInfo:callback:))

// 导出给 JS：plugin.showToast({ text }, callback)
WX_EXPORT_METHOD(@selector(showToast:callback:))

#pragma mark - 设备信息

- (void)getDeviceInfo:(NSDictionary *)options callback:(WXModuleCallback)callback {
    UIDevice *device = [UIDevice currentDevice];

    NSDictionary *data = @{
        @"brand": @"Apple",
        @"model": device.model ?: @"unknown",
        @"osVersion": device.systemVersion ?: @"unknown",
        @"abi": [self currentArchitecture]
    };

    if (callback) {
        callback(@{ @"code": @0, @"message": @"ok", @"data": data });
    }
}

- (NSString *)currentArchitecture {
#if TARGET_CPU_ARM64
    return @"arm64";
#elif TARGET_CPU_X86_64
    return @"x86_64";
#else
    return @"unknown";
#endif
}

#pragma mark - Toast

- (void)showToast:(NSDictionary *)options callback:(WXModuleCallback)callback {
    NSString *text = options[@"text"] ?: @"Hello from native";

    // 所有 UI 操作必须回主线程
    dispatch_async(dispatch_get_main_queue(), ^{
        UIWindow *window = [UIApplication sharedApplication].keyWindow;
        if (!window) {
            if (callback) callback(@{ @"code": @5002, @"message": @"no key window" });
            return;
        }

        UILabel *toast = [[UILabel alloc] initWithFrame:CGRectZero];
        toast.text = text;
        toast.font = [UIFont systemFontOfSize:15];
        toast.textColor = [UIColor whiteColor];
        toast.backgroundColor = [[UIColor blackColor] colorWithAlphaComponent:0.75];
        toast.textAlignment = NSTextAlignmentCenter;
        toast.numberOfLines = 0;
        toast.layer.cornerRadius = 8;
        toast.layer.masksToBounds = YES;
        [toast sizeToFit];

        CGRect frame = toast.frame;
        frame.size.width += 32;
        frame.size.height += 24;
        frame.origin.x = (window.bounds.size.width - frame.size.width) / 2;
        frame.origin.y = window.bounds.size.height - frame.size.height - 80;
        toast.frame = frame;

        [window addSubview:toast];

        dispatch_after(dispatch_time(DISPATCH_TIME_NOW, (int64_t)(2.0 * NSEC_PER_SEC)),
                       dispatch_get_main_queue(), ^{
            [toast removeFromSuperview];
        });

        if (callback) callback(@{ @"code": @0, @"message": @"ok" });
    });
}

@end

2.3 关键点 ​

项说明
WX_EXPORT_METHOD必须写，否则 JS 侧方法为 undefined
选择器getDeviceInfo:callback: 对应 JS 的两个参数
WXModuleCallback可以多次调用；一次性场景调用后置 nil
weexInstance必须 weak，否则实例之间循环引用
线程默认在主线程执行；耗时任务自行 dispatch_async
类名@implementation NativeDemoModule 必须与 package.json 的 class 一致

2.4 回调与内存 ​

objc
// 一次性回调
if (callback) callback(result);

// 保活回调：保存到属性，注意 copy
@property (nonatomic, copy) WXModuleCallback locationCallback;

// 停止时释放
- (void)stopLocation {
    if (self.locationCallback) {
        self.locationCallback(@{ @"code": @0, @"message": @"stopped" });
        self.locationCallback = nil;
    }
}

两个高频泄漏：

  • Block 里强引用 self，self 又持有 Block → 循环引用。用 __weak typeof(self) weakSelf = self;。
  • 把回调存进单例 / 静态变量 → 页面销毁后仍持有 JS 上下文。

三、Swift 混编：另一种写法 ​

如果团队以 Swift 为主，可以不写 .m，用 Swift + 桥接头：

swift
// NativeDemoModule.swift
import UIKit

@objc(NativeDemoModule)
final class NativeDemoModule: NSObject, WXModuleProtocol {
    weak var weexInstance: WXSDKInstance?

    @objc(getDeviceInfo:callback:)
    func getDeviceInfo(_ options: [String: Any], callback: @escaping WXModuleCallback) {
        callback([
            "code": 0,
            "message": "ok",
            "data": [
                "brand": "Apple",
                "model": UIDevice.current.model,
                "osVersion": UIDevice.current.systemVersion,
                "abi": "arm64"
            ]
        ])
    }
}

桥接头：

objc
// UniDemoNative-Bridging-Header.h
#import <WeexSDK/WXModuleProtocol.h>
#import <WeexSDK/WXSDKInstance.h>

Swift 混编的额外约束：

  • 类必须继承 NSObject，方法必须 @objc。
  • struct、泛型、enum（非 @objc）不能直接暴露。
  • 生成的 Framework 需要开启 BUILD_LIBRARY_FOR_DISTRIBUTION = YES，否则宿主编译器版本不一致会报 module compiled with Swift X cannot be imported。
  • @objc(ClassName) 必须与 package.json 的 class 一致。

四、WXComponent：原生 UI ​

4.1 组件实现 ​

objc
// NativeDemoView.h
#import <WeexSDK/WXComponent.h>

@interface NativeDemoView : WXComponent
@end
objc
// NativeDemoView.m
#import "NativeDemoView.h"
#import <UIKit/UIKit.h>

@interface NativeDemoView ()
@property (nonatomic, strong) UILabel *label;
@end

@implementation NativeDemoView

- (UIView *)loadView {
    UIView *container = [[UIView alloc] init];
    container.backgroundColor = [UIColor colorWithRed:0 green:0.478 blue:1 alpha:1];

    UILabel *label = [[UILabel alloc] initWithFrame:container.bounds];
    label.textColor = [UIColor whiteColor];
    label.textAlignment = NSTextAlignmentCenter;
    label.font = [UIFont systemFontOfSize:16];
    label.autoresizingMask = UIViewAutoresizingFlexibleWidth | UIViewAutoresizingFlexibleHeight;
    [container addSubview:label];
    self.label = label;

    return container;
}

- (void)viewDidLoad {
    [super viewDidLoad];

    UITapGestureRecognizer *tap =
        [[UITapGestureRecognizer alloc] initWithTarget:self action:@selector(onTap)];
    [self.view addGestureRecognizer:tap];
}

- (void)updateAttributes:(NSDictionary *)attributes {
    [super updateAttributes:attributes];

    if (attributes[@"label"]) {
        self.label.text = attributes[@"label"];
    }
    if (attributes[@"bgColor"]) {
        self.view.backgroundColor = [self colorFromHex:attributes[@"bgColor"]];
    }
}

- (void)onTap {
    [self fireEvent:@"onNativeClick" params:@{
        @"timestamp": @([[NSDate date] timeIntervalSince1970] * 1000)
    }];
}

- (UIColor *)colorFromHex:(NSString *)hex {
    // 简化示例：生产环境请做完整校验
    unsigned int value = 0;
    NSScanner *scanner = [NSScanner scannerWithString:[hex stringByReplacingOccurrencesOfString:@"#" withString:@""]];
    [scanner scanHexInt:&value];
    return [UIColor colorWithRed:((value >> 16) & 0xFF) / 255.0
                            green:((value >> 8) & 0xFF) / 255.0
                             blue:(value & 0xFF) / 255.0
                            alpha:1.0];
}

@end

4.2 nvue 使用 ​

vue
<!-- pages/native/native-demo.nvue -->
<template>
  <view class="page">
    <native-demo-view
      label="iOS 原生组件"
      bg-color="#007aff"
      style="width: 300rpx; height: 120rpx;"
      @onNativeClick="onClick"
    />
  </view>
</template>

<script setup>
function onClick(e) {
  console.log('native click', e.detail)
}
</script>

约束：

  • 只能用于 .nvue 页面。
  • 标签名是注册名的大驼峰转 kebab-case。
  • 样式通过 updateStyles: 同步，高度依赖 WXComponent 的布局系统，不要直接在 loadView 里写死 frame。
  • 事件通过 fireEvent:params: 抛出，JS 侧用 @eventName 接收。

4.3 生命周期 ​

objc
- (void)viewDidLoad { [super viewDidLoad]; /* 初始化 */ }
- (void)viewWillUnload { [super viewWillUnload]; /* 暂停 */ }
- (void)dealloc { /* 注销通知、释放资源 */ }

WXComponent 的 dealloc 不保证在主线程，释放 UI 相关资源时注意线程。

五、打包成 Framework ​

5.1 创建 Framework Target ​

  1. Xcode → File → New → Target → Framework。
  2. 把 NativeDemoModule.h/.m、NativeDemoView.h/.m 加入 target。
  3. Build Settings：
    • Defines Module = YES
    • Build Libraries for Distribution = YES（Swift 混编必开）
    • Deployment Target 与插件 package.json 一致
    • Supported Platforms 至少包含 iphoneos

5.2 构建真机 Framework ​

bash
xcodebuild \
  -project UniDemoNative.xcodeproj \
  -scheme UniDemoNative \
  -configuration Release \
  -sdk iphoneos \
  -derivedDataPath ./build \
  BUILD_LIBRARY_FOR_DISTRIBUTION=YES \
  build

# 产物
ls ./build/Build/Products/Release-iphoneos/UniDemoNative.framework

# 检查架构（必须包含 arm64）
lipo -info ./build/Build/Products/Release-iphoneos/UniDemoNative.framework/UniDemoNative

5.3 合并模拟器与真机（可选） ​

本地调试需要模拟器架构时，用 lipo -create 合并；但上架包必须移除 x86_64，否则会被 App Store 拒绝。

bash
# 真机 arm64 + 模拟器 x86_64
lipo -create \
  Release-iphoneos/UniDemoNative.framework/UniDemoNative \
  Release-iphonesimulator/UniDemoNative.framework/UniDemoNative \
  -output UniDemoNative

六、调试 ​

6.1 日志 ​

objc
NSLog(@"[UniNativeDemo] init, model=%@", UIDevice.currentDevice.model);

查看方式：

  • Xcode → Window → Devices and Simulators → 选中真机 → Open Console。
  • 命令行：idevicesyslog | grep UniNativeDemo（需安装 libimobiledevice）。

6.2 断点 ​

  1. 用 Xcode 打开插件工程或宿主离线工程。
  2. Product → Scheme → Edit Scheme → Run → Executable 选择已安装的 App。
  3. Debug → Attach to Process，选择真机上的 App。
  4. 在 NativeDemoModule 方法里下断点，触发 JS 调用。
  5. 自定义基座是 Release 配置时断点可能不生效，日常调试用 Debug 基座或原生宿主工程。

6.3 常见崩溃 ​

现象原因处理
unrecognized selector方法没导出 / 选择器写错WX_EXPORT_METHOD 与 @selector 对齐
message sent to deallocated instance回调持有已释放对象弱引用 + 判空
UI 不更新在后台线程改 UI切主线程
组件空白在 vue 页面使用改 .nvue
module compiled with Swift 5.xSwift 版本不匹配开 BUILD_LIBRARY_FOR_DISTRIBUTION
App Store 拒绝 x86_64模拟器架构混入上架前 lipo 剥离

七、本章检查清单 ​

  • [ ] .h 中声明 WXModuleProtocol 与 weak weexInstance
  • [ ] .m 中每个 JS 方法都有 WX_EXPORT_METHOD
  • [ ] JS 侧 Object.keys(plugin) 能看到方法
  • [ ] 原生 UI 只在 .nvue 页面使用
  • [ ] Framework 的 lipo -info 包含 arm64
  • [ ] Swift 混编已开启 BUILD_LIBRARY_FOR_DISTRIBUTION
