18.2 进阶应用：nvue 原生渲染与原生 View 嵌入 ​

uni-app 的 App 端有两种渲染方式：WebView 渲染（普通 vue 页面）和 原生渲染（nvue 页面）。绝大多数业务用 vue 页面就够了；但长列表、复杂动画、原生组件场景，nvue 能显著降低通信与渲染成本。

本章讲清三件事：nvue 的边界、原生 View 的两种嵌入方式（浮层 vs 布局内）、原生页面与 uni 页面栈如何协同。

一、nvue 与 vue 页面：先选渲染方式 ​

维度vue 页面（WebView）nvue 页面（原生渲染）
渲染引擎系统 WebViewWeex 原生渲染
布局能力CSS 完整仅 Flex，限制多
长列表依赖虚拟列表 / 分页<list> / <recycle-list> 原生回收
动画性能受 WebView 限制原生动画更稳
原生组件不能直接嵌入自定义原生 View支持 WXComponent
开发体验熟悉、生态完整样式坑多、调试难
适用90% 业务页长列表、直播、地图、相机、复杂动画

选择原则：

  • 默认 vue 页面，不要为了「性能」全站 nvue。
  • 只有出现 1000+ 条滚动列表、原生相机预览、复杂手势动画、原生地图 时，才把对应页面改成 nvue。
  • 同一个页面不要既想用完整 CSS，又想用原生组件；这是 nvue 最主要的误用。

二、nvue 的 Flex 布局限制 ​

nvue 不是浏览器，样式能力是 Weex 的子集。

2.1 必须记住的五条 ​

  1. 只支持 Flex 布局，默认 flex-direction: column（Web 默认是 row）。
  2. 不支持 display: grid、float、position: sticky。
  3. 选择器只支持 class 选择器，不支持标签、后代、伪类组合。
  4. 文字必须放在 <text> 里，直接写文本不会渲染。
  5. display: none 用 v-if 替代；v-show 在 nvue 里行为不一致。

2.2 正确写法 ​

vue
<!-- pages/native/nvue-list.nvue -->
<template>
  <view class="page">
    <view class="header">
      <text class="title">nvue 长列表</text>
    </view>

    <list class="list" @loadmore="loadMore">
      <cell v-for="item in items" :key="item.id" class="cell">
        <view class="row">
          <image class="avatar" :src="item.avatar" />
          <view class="meta">
            <text class="name">{{ item.name }}</text>
            <text class="desc">{{ item.desc }}</text>
          </view>
        </view>
      </cell>
      <cell v-if="loading" class="loading">
        <text class="loading-text">加载中...</text>
      </cell>
    </list>
  </view>
</template>

<script setup lang="ts">
import { ref } from 'vue'

interface Row {
  id: number
  name: string
  desc: string
  avatar: string
}

const items = ref<Row[]>([])
const loading = ref(false)

function loadMore() {
  if (loading.value) return
  loading.value = true
  // 模拟分页；真实项目接接口
  setTimeout(() => {
    items.value.push(
      ...Array.from({ length: 20 }, (_, i) => ({
        id: items.value.length + i,
        name: `用户 ${items.value.length + i}`,
        desc: '原生列表回收，滚动更稳',
        avatar: 'https://picsum.photos/80'
      }))
    )
    loading.value = false
  }, 500)
}
</script>

.page { flex: 1; background-color: #f5f6f7; }
.header { height: 88rpx; justify-content: center; align-items: center; background-color: #ffffff; }
.title { font-size: 32rpx; font-weight: bold; color: #222222; }
.list { flex: 1; }
.cell { padding: 24rpx; }
.row { flex-direction: row; align-items: center; }
.avatar { width: 80rpx; height: 80rpx; border-radius: 40rpx; margin-right: 24rpx; }
.meta { flex: 1; flex-direction: column; }
.name { font-size: 30rpx; color: #222222; }
.desc { margin-top: 8rpx; font-size: 24rpx; color: #999999; }
.loading { height: 88rpx; justify-content: center; align-items: center; }
.loading-text { font-size: 24rpx; color: #999999; }
</style>

2.3 常见样式坑 ​

写法nvue 表现正确做法
display: flex; flex-direction: row 省略默认纵向显式写 flex-direction: row
<view>文本</view>文本不显示用 <text>文本</text>
width: 50% 在部分嵌套场景计算异常用 flex: 1 或固定 rpx
margin: 0 auto不支持用 justify-content: center
background-image支持有限用 <image> 或纯色
box-shadow支持有限用边框/背景模拟
overflow: visible裁剪行为不同拆分层级

3.2 手势动画 ​

复杂拖拽 / 回弹用 BindingX 或 uni.createAnimation。原则：

  • 动画属性优先用 transform / opacity，避免触发布局重排。
  • 列表滚动中的动画要限制数量，否则原生线程也会掉帧。
  • 动画状态用 ref 驱动，不要在 setInterval 里直接改样式字符串。

四、nvue 与 vue 页面混用 ​

4.1 规则 ​

  • nvue 页面必须在 pages.json 注册，文件后缀 .nvue。
  • nvue 页面不能作为普通组件被 vue 页面引入。
  • vue 页面可以跳转 nvue 页面，反之亦然。
  • nvue 里可以使用 easycom 组件，但组件必须兼容 nvue（不能依赖 DOM）。
  • 全局样式、uni.scss 变量在 nvue 中支持有限，建议单独维护 nvue 样式。

4.2 渐进式迁移 ​

text
1. 先保留 vue 页面，列表分页 + 虚拟列表优化
2. 压测发现滚动仍卡顿 → 单独把列表页改成 .nvue
3. 抽出共享的 TS 逻辑（composable / service）
4. 保持页面路由不变，仅改文件后缀与样式
5. 建立 nvue 样式基线，避免每个页面重新踩坑

4.3 降级策略 ​

ts
// 同一业务逻辑，按渲染模式选择实现
export function createListAdapter() {
  // #ifdef APP-PLUS
  return { useNativeList: true }
  // #endif
  // #ifndef APP-PLUS
  return { useNativeList: false }
  // #endif
}

H5 / 小程序没有 nvue，必须保证 vue 版本可用；nvue 只是 App 端的性能增强，不是唯一实现。

五、原生 View 的两种嵌入方式 ​

这是最容易混淆的地方：

方式API是否参与布局适用
浮层plus.nativeObj.View❌ 覆盖在页面上蒙层、悬浮按钮、调试面板
布局内嵌nvue + WXComponent✅ 参与 Flex 布局原生地图、相机预览、原生播放器

5.1 浮层：plus.nativeObj.View ​

js
// #ifdef APP-PLUS
function showNativeMask() {
  const mask = new plus.nativeObj.View('native-mask', {
    top: '0px',
    left: '0px',
    width: '100%',
    height: '100%',
    backgroundColor: '#80000000'
  })

  mask.draw([
    {
      tag: 'rect',
      id: 'panel',
      rect: { top: '35%', left: '10%', width: '80%', height: '30%' },
      radius: '16px',
      color: '#ffffff'
    },
    {
      tag: 'text',
      id: 'title',
      text: '原生浮层',
      rect: { top: '38%', left: '10%', width: '80%', height: '40px' },
      size: '18px',
      color: '#222222',
      align: 'center'
    },
    {
      tag: 'rect',
      id: 'close',
      rect: { top: '55%', left: '35%', width: '30%', height: '48px' },
      radius: '8px',
      color: '#007aff'
    },
    {
      tag: 'text',
      id: 'close-text',
      text: '关闭',
      rect: { top: '55%', left: '35%', width: '30%', height: '48px' },
      size: '16px',
      color: '#ffffff',
      align: 'center'
    }
  ])

  mask.addEventListener('click', () => {
    mask.close()
  })

  mask.show()
}
// #endif

特点：

  • 创建后独立于页面 DOM，不参与页面布局。
  • 适合蒙层、引导层、悬浮球、原生广告位。
  • 不能嵌入 <view> 内部，也不能被页面 overflow 裁剪。
  • 页面切换时要手动 close()，否则会一直覆盖。

5.2 布局内嵌：nvue + WXComponent ​

vue
<!-- pages/native/native-demo.nvue -->
<template>
  <view class="page">
    <view class="header"><text>原生组件区域</text></view>
    <native-demo-view
      label="我是原生 View"
      bg-color="#007aff"
      style="width: 600rpx; height: 300rpx;"
    />
  </view>
</template>

WXComponent 的实现见 16.2 与 17.2。关键点：

  • 原生 View 由 initComponentHostView / loadView 创建。
  • 宽高由 nvue 的 Flex 布局决定，不要在原生代码里写死屏幕尺寸。
  • 事件通过 fireEvent 抛给 JS。
  • 销毁时释放相机 / 传感器 / 播放器。

六、原生页面与 uni 页面栈协同 ​

6.1 为什么需要原生页面 ​

有些页面是历史原生代码、或者必须用原生导航 / 原生地图，不能改写成 uni 页面。这时用 plus.webview 创建独立原生 webview，或者用 plus.runtime.openURL 拉起原生 Activity / ViewController。

6.2 创建并显示原生页面 ​

js
// #ifdef APP-PLUS
let nativePage = null

function openNativePage() {
  if (nativePage) {
    nativePage.show('slide-in-right', 300)
    return
  }

  nativePage = plus.webview.create(
    '/hybrid/native.html',
    'native-page',
    {
      top: '0px',
      bottom: '0px',
      popGesture: 'close',
      titleNView: {
        type: 'default',
        titleText: '原生页面',
        autoBackButton: true
      }
    }
  )

  nativePage.addEventListener('close', () => {
    nativePage = null
  })

  nativePage.show('slide-in-right', 300)
}

function closeNativePage() {
  if (!nativePage) return
  nativePage.close('slide-out-right', 300)
}
// #endif

6.3 生命周期协同 ​

uni 页面事件原生页面处理
onLoad创建 / 预加载原生页
onShownativePage.show() 恢复显示
onHidenativePage.hide() 避免后台继续渲染
onUnloadnativePage.close() 释放
ts
import { onShow, onHide, onUnload } from '@dcloudio/uni-app'

onShow(() => {
  // #ifdef APP-PLUS
  nativePage?.show()
  // #endif
})

onHide(() => {
  // #ifdef APP-PLUS
  nativePage?.hide()
  // #endif
})

onUnload(() => {
  // #ifdef APP-PLUS
  nativePage?.close()
  nativePage = null
  // #endif
})

关键认知：

  • getCurrentPages() 不包含 plus.webview 创建的原生页面。
  • 原生页面有自己的返回栈，uni 的 navigateBack 管不到它。
  • 原生页面里的 H5 与 uni 页面通信，走 evalJS / postMessage（见 15.2）。
  • Android 的物理返回键、iOS 的侧滑返回要单独处理，否则会出现「页面关不掉」或「栈错乱」。
