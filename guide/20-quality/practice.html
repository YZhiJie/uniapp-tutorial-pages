20.3 实战案例：Playwright E2E、uni-automator 与覆盖率门禁 ​

单元与组件测试保证「零件对」，E2E 保证「装起来能走」。本篇给两条真正可落地的链路：

  • H5 端 Playwright：无需 Apple 账号、无需真机，CI 可直接跑。
  • 微信小程序 uni-automator：依赖 HBuilderX 与微信开发者工具，给出完整配置与前置条件。

一、Playwright：H5 主链路 E2E ​

1.1 安装与配置 ​

bash
pnpm add -D @playwright/test
pnpm exec playwright install chromium
ts
// playwright.config.ts
import { defineConfig, devices } from '@playwright/test'

export default defineConfig({
  testDir: 'e2e',
  timeout: 30_000,
  retries: process.env.CI ? 2 : 0,
  reporter: process.env.CI ? [['github'], ['html', { open: 'never' }]] : 'list',
  use: {
    baseURL: 'http://localhost:5173',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
    video: 'retain-on-failure'
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'mobile', use: { ...devices['iPhone 13'] } }
  ],
  webServer: {
    command: 'pnpm dev:h5',
    url: 'http://localhost:5173',
    reuseExistingServer: !process.env.CI,
    timeout: 120_000
  }
})

1.2 用 page.route 隔离后端 ​

E2E 不依赖真实后端：在网络层拦截并返回固定数据，链路稳定、可断言。

ts
// e2e/checkout.spec.ts
import { expect, test } from '@playwright/test'

const home = {
  banners: [],
  categories: [{ id: 'c1', name: '手机' }],
  feed: { list: [{ id: 'g1', name: '测试商品', price: 99 }], hasMore: false },
  cartCount: 0,
  flags: { newUser: false }
}

test.beforeEach(async ({ page }) => {
  await page.route('**/bff/home**', (route) => route.fulfill({ json: home }))
  await page.route('**/api/cart', (route) =>
    route.fulfill({ json: { lines: [{ skuId: 'g1', quantity: 1 }] } })
  )
})

test('首页进入商详并加入购物车', async ({ page }) => {
  await page.goto('/')
  await expect(page.getByText('测试商品')).toBeVisible()
  await page.getByText('测试商品').click()
  await page.getByRole('button', { name: '加入购物车' }).click()
  await expect(page.getByTestId('cart-badge')).toHaveText('1')
})

test('未登录点击结算跳转登录页', async ({ page }) => {
  await page.goto('/#/pages/cart/cart')
  await page.getByRole('button', { name: '去结算' }).click()
  await expect(page).toHaveURL(/login/)
})

选择器优先级：getByRole > getByTestId > 文本。避免用 nth-child 之类的结构选择器，页面改布局就全红。

1.3 CI 任务 ​

yaml
e2e:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: pnpm/action-setup@v4
    - run: pnpm install --frozen-lockfile
    - run: pnpm exec playwright install --with-deps chromium
    - run: pnpm exec playwright test
    - uses: actions/upload-artifact@v4
      if: failure()
      with:
        name: playwright-report
        path: playwright-report/

二、uni-automator：小程序端自动化 ​

2.1 前置条件（缺一不可） ​

条件说明
HBuilderX需开启「设置 → 安全设置 → 服务端口」
微信开发者工具需开启「设置 → 安全设置 → 服务端口」，并登录有该 AppID 权限的账号
项目已编译先生成 dist/dev/mp-weixin，自动化运行在该产物上
端口未被占用HBuilderX 默认 12333，微信工具默认 9420

macOS / Windows 均可；Linux CI 不支持微信开发者工具，小程序 E2E 只能在带 GUI 的机器或自托管 runner 上跑。

2.2 配置 ​

bash
pnpm add -D @dcloudio/uni-automator jest jest-environment-node
js
// uni-automator.config.js
module.exports = {
  testEnvironment: 'node',
  testTimeout: 60_000,
  testMatch: ['<rootDir>/e2e-mp/**/*.spec.js'],
  globalSetup: '@dcloudio/uni-automator/dist/global-setup.js',
  globalTeardown: '@dcloudio/uni-automator/dist/global-teardown.js'
}

2.3 用例 ​

js
// e2e-mp/checkout.spec.js
const automator = require('@dcloudio/uni-automator')

describe('小程序结算链路', () => {
  let miniProgram

  beforeAll(async () => {
    miniProgram = await automator.launch({
      projectPath: process.cwd(),
      platform: 'mp-weixin',
      cliPath: process.env.HBUILDERX_CLI // HBuilderX cli 绝对路径
    })
  })

  afterAll(async () => {
    await miniProgram.close()
  })

  test('加入购物车后角标更新', async () => {
    const page = await miniProgram.reLaunch('/pages/index/index')
    await page.waitFor(1000)

    const goods = await page.$('.goods-card')
    await goods.tap()
    await page.waitFor(500)

    const addBtn = await page.$('.add-cart')
    await addBtn.tap()

    const badge = await page.$('[data-test="cart-badge"]')
    expect(await badge.text()).toBe('1')
  })
})
bash
# 需要先在 HBuilderX 中打开并运行到微信开发者工具
HBUILDERX_CLI=/Applications/HBuilderX.app/Contents/MacOS/cli \
  pnpm exec jest --config uni-automator.config.js

限制说明：本仓库 CI 没有 HBuilderX 与微信开发者工具，因此该用例仅提供配置与脚本，未在流水线中执行。落地时请把它放在自托管 macOS runner 或本地发版前执行，并在 PR 模板里注明「小程序 E2E：本地已验证」。

三、覆盖率门禁与棘轮 ​

bash
pnpm test:coverage
# 当前阈值：statements 70 / branches 85 / functions 88 / lines 70

提升节奏建议：

阶段动作目标
第 1 周只统计、不改阈值记录基线
第 2–4 周每补一组测试，阈值 +2%逐步爬坡
稳定期新增代码要求 diff 覆盖率 ≥ 70%防止新债

diff 覆盖率（只统计本次改动行）适合存量项目，避免「为了达标去补无意义测试」。可用 diff-cover 在 CI 中生成报告：

bash
pnpm test:coverage
pnpm dlx diff-cover coverage/coverage-final.json --compare-branch=origin/main --fail-under=70

四、flaky 治理：不稳定用例比没有用例更糟 ​

现象常见根因处理
偶发超时等待固定 sleep改为等待可观测状态（元素可见 / 接口完成）
顺序相关用例共享登录态或数据库每个用例独立初始化，禁止依赖执行顺序
只在 CI 失败本机有缓存、CI 冷启动慢提高超时只治标；先排查资源与并发
随机数据冲突随机数无种子固定 seed 或使用唯一前缀

治理流程：

  1. 连续 3 次重跑仍失败的用例，打 @flaky 标签移出阻塞队列，24 小时内必须修复或删除。
  2. 允许 CI retries: 2，但报告中单独统计「重试后通过」的比例，超过 5% 触发治理。
  3. 失败必须留证据：trace、截图、视频、控制台日志，否则无法定位。
ts
test('@flaky 优惠券叠加（待修复）', async ({ page }) => {
  test.fixme(true, '优惠券接口时序不稳定，见 ISSUE-123')
})

五、一套完整的质量门禁 ​

bash
pnpm lint
pnpm typecheck
pnpm test                 # 单测 + store/composable
pnpm test:coverage        # 覆盖率阈值
pnpm depcruise            # 分层依赖
pnpm security:scan        # 密钥与危险 API
pnpm exec playwright test # H5 E2E

CI 中按「快 → 慢」排序，前面的失败直接短路，节省 runner 时间。

六、验收标准 ​

bash
# H5 E2E 可独立运行
pnpm exec playwright test
# 期望：2 个用例通过；故意改错按钮文案后失败并产出 trace

# 覆盖率门禁真实生效
pnpm test:coverage
# 期望：低于阈值时退出码 1

小程序链路的验收以「本地按 2.1 前置条件跑通 1 条用例」为准，并在文档中明确记录未纳入 CI 的原因。
