7.2 进阶应用：条件编译与平台分支 ​

条件编译是 uni-app 跨端治理的核心武器：编译期物理剪枝，不属于目标平台的代码不会进入产物。

平台标识速查 ​

标识生效平台
H5H5
APP-PLUSApp（包含 Android/iOS）
APP-PLUS-NVUE / APP-ANDROID / APP-IOSApp 细分（nvue / Android / iOS）
MP-WEIXIN微信小程序
MP-ALIPAY支付宝小程序
MP所有小程序
WEB同 H5

一、JS / TS 中的条件编译 ​

ts
// src/services/location.ts
export function getLocationOnce(): Promise<{ latitude: number; longitude: number }> {
  return new Promise((resolve, reject) => {
    uni.getLocation({
      type: 'gcj02',
      success: (res) => resolve({ latitude: res.latitude, longitude: res.longitude }),
      fail: reject
    })
  })
}

export function openMap(latitude: number, longitude: number) {
  // #ifdef H5
  window.open(`https://uri.amap.com/marker?position=${longitude},${latitude}`)
  // #endif

  // #ifndef H5
  uni.openLocation({ latitude, longitude })
  // #endif
}
  • #ifdef X：仅 X 平台保留。
  • #ifndef X：除 X 外保留。
  • #ifdef X || Y：多平台或；#ifdef X && !Z 也支持。
  • 必须成对出现 // #endif，嵌套不推荐，复杂分支抽函数。

也可以做平台专属文件：

ts
// #ifdef H5
import { payByH5 } from './pay/h5'
// #endif
// #ifdef MP-WEIXIN
import { payByWeixin } from './pay/mp-weixin'
// #endif

更彻底的方式是同名文件后缀，编译器按平台选择（推荐用于大段差异实现）：

text
src/platforms/pay/pay.h5.ts
src/platforms/pay/pay.mp-weixin.ts
src/platforms/pay/pay.app-plus.ts
ts
// 通过条件编译 re-export，业务代码只 import 统一入口
// #ifdef H5
export * from './pay/pay.h5'
// #endif
// #ifdef MP-WEIXIN
export * from './pay/pay.mp-weixin'
// #endif
// #ifdef APP-PLUS
export * from './pay/pay.app-plus'
// #endif

二、template 中的条件编译 ​

vue
<template>
  <view class="share-entry">
    <!-- #ifdef MP-WEIXIN -->
    <button open-type="share" class="share-btn">分享给微信好友</button>
    <!-- #endif -->

    <!-- #ifndef MP-WEIXIN -->
    <button class="share-btn" @tap="invokeShare">分享给好友</button>
    <!-- #endif -->
  </view>
</template>

注释必须紧贴节点；小程序端 open-type="share" 是触发转发的唯一合规方式，用分支隔离最干净。

三、CSS/SCSS 中的条件编译 ​

scss
.banner {
  height: 320rpx;
  /* #ifdef H5 */
  background-image: url('/static/banner-h5.png');
  background-attachment: fixed;
  /* #endif */
  /* #ifdef MP-WEIXIN */
  background-image: url('https://cdn.example.com/banner-mp.png');
  /* #endif */
}

平台专属样式类也可配合运行时平台类名：页面根节点加 :class="platform"，样式中写 .h5 .x { }。但首选编译期分支（零运行时成本、不产生冗余代码）。

四、pages.json / manifest.json 中的条件编译 ​

JSON 文件中使用注释形式（uni-app 的 JSON 是 JSON5 风格，支持注释指令）：

jsonc
{
  "pages": [
    {
      "path": "pages/index/index",
      "style": {
        "navigationBarTitleText": "首页"
        // #ifdef H5
        , "titleNView": false
        // #endif
      }
    },
    // #ifdef MP-WEIXIN
    {
      "path": "pages/wx-only/follow",
      "style": { "navigationBarTitleText": "关注公众号" }
    }
    // #endif
  ]
}

manifest.json 同理处理各端配置（App 模块权限、小程序 appid、H5 router base 等）。

五、静态资源目录级条件编译 ​

text
static/
├─ common/          # 四端共用
├─ mp-weixin/       # 命名约定（需自行按分支引用）

配合代码分支引用不同路径；构建产物会包含未引用裁剪之外的全部 static 资源，体积敏感时使用分包 static（分包目录下的资源随分包下载）。

适配层架构：把差异关进笼子 ​

反模式：页面里到处是 ifdef，业务逻辑与平台判断纠缠。

推荐模式：面向接口编程的适配层。

text
src/
├─ platforms/
│  ├─ share.ts          # 统一入口（条件 re-export）
│  ├─ share.h5.ts
│  ├─ share.mp-weixin.ts
│  ├─ share.app-plus.ts
│  ├─ location/         # 定位适配（含权限说明）
│  └─ storage/          # 大数据存储适配
├─ pages/               # 只调用 platforms 暴露的统一函数

统一接口约定：

ts
// src/platforms/share/types.ts
export interface SharePayload {
  title: string
  desc?: string
  link?: string
  imageUrl?: string
}
export interface ShareService {
  share(payload: SharePayload): Promise<void>
  isSupported(): boolean
}

页面代码：

ts
import { shareService } from '@/platforms/share'

await shareService.share({ title: '一起来学 uni-app', link: inviteUrl })

新增平台（如抖音小程序）时只需新增一个实现文件，页面零改动——这就是开闭原则在跨端项目里的落地。

安全区与状态栏的统一封装 ​

ts
// src/utils/ui.ts
export function getStatusBarInfo() {
  const win = uni.getWindowInfo()
  const statusBarHeight = win.statusBarHeight ?? 0

  // #ifdef MP-WEIXIN
  const capsule = uni.getMenuButtonBoundingClientRect()
  return {
    statusBarHeight,
    navBarHeight: capsule.bottom + (capsule.top - statusBarHeight) * 2,
    menuButton: capsule
  }
  // #endif

  // #ifndef MP-WEIXIN
  return { statusBarHeight, navBarHeight: 44 }
  // #endif
}

常见问题 ​

Q：为什么提示“条件编译未生效”？ 检查：注释语法是否精确（// #ifdef 空格不能少）；平台标识拼写；JSON 中指令是否在合法注释位置；文件是否真的被当前平台构建包含。

Q：运行时判断平台（uni.getDeviceInfo）和条件编译怎么选？ 能在编译期确定的一律条件编译（零成本、不泄露平台代码）；只有依赖运行时状态（系统版本号、设备型号）才用运行时判断。
