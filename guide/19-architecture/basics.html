19.1 基础入门：五层架构与依赖方向 ​

项目从「能跑」到「能长期维护」，分水岭不是用了多少设计模式，而是依赖方向是否可控。页面直接调接口、组件直接读全局 store、工具函数反向依赖业务，短期写得快，三个月后每改一个需求都要全链路回归。

本篇给出适用于 uni-app 的五层结构，以及把「依赖方向」变成 CI 门禁的方法。

一、五层职责 ​

层目录职责不应该做的事
表现层pages/、components/渲染、交互、路由参数直接拼接口 URL、写业务规则
应用层（用例层）application/编排一次完整业务动作（下单、支付、登录）操作 DOM、直接读页面状态
领域层domain/纯业务规则：价格计算、状态机、校验依赖 uni.*、依赖网络
数据访问层data/API、transport、Repository、DTO 转换包含 UI 文案与页面跳转
基础设施层infra/、platform/、config/、utils/存储、请求适配、环境配置、通用工具依赖上层业务

依赖只能自上而下：表现层 → 应用层 → 领域层 / 数据访问层 → 基础设施层，同层可以互相引用，反向依赖一律禁止。

mermaid
flowchart TB
    P[表现层 pages / components] --> A[应用层 application<br/>用例编排]
    A --> D[领域层 domain<br/>纯业务规则]
    A --> R[数据访问层 data<br/>Repository / API / ACL]
    D --> I[基础设施层 infra / platform / utils]
    R --> I
    P -.禁止.-> R
    D -.禁止.-> A
    I -.禁止.-> A

三、一个最小用例：结算 ​

领域层只做纯计算，不碰网络与 UI：

ts
// src/domain/pricing/priceOrder.ts
export interface CartLine {
  skuId: string
  price: number
  quantity: number
}

export interface PriceInput {
  lines: CartLine[]
  freight: number
  discount: number
}

export function priceOrder({ lines, freight, discount }: PriceInput) {
  const goodsAmount = lines.reduce((sum, line) => sum + line.price * line.quantity, 0)
  const payable = Math.max(0, goodsAmount + freight - discount)
  return {
    goodsAmount: Number(goodsAmount.toFixed(2)),
    freight,
    discount,
    payable: Number(payable.toFixed(2))
  }
}

应用层编排「算价 → 提交订单」，依赖通过参数注入，方便测试替换：

ts
// src/application/checkout/useCheckout.ts
import { computed, ref } from 'vue'
import { priceOrder } from '@/domain/pricing/priceOrder'
import type { CartLine } from '@/domain/pricing/priceOrder'
import { orderRepository } from '@/data/repositories/orderRepository'

export function useCheckout(deps = { priceOrder, orderRepository }) {
  const lines = ref<CartLine[]>([])
  const freight = ref(0)
  const discount = ref(0)
  const submitting = ref(false)

  const price = computed(() =>
    deps.priceOrder({ lines: lines.value, freight: freight.value, discount: discount.value })
  )

  async function submit(input: { addressId: string; couponId?: string }) {
    if (submitting.value || lines.value.length === 0) return null
    submitting.value = true
    try {
      return await deps.orderRepository.create({
        lines: lines.value,
        addressId: input.addressId,
        couponId: input.couponId
      })
    } finally {
      submitting.value = false
    }
  }

  return { lines, freight, discount, submitting, price, submit }
}

表现层只剩绑定：

vue
<!-- src/pages/checkout/confirm.vue -->
<script setup lang="ts">
import { useCheckout } from '@/application/checkout/useCheckout'

const { lines, price, submitting, submit } = useCheckout()

async function onSubmit() {
  const order = await submit({ addressId: 'addr-1' })
  if (order) uni.redirectTo({ url: `/pages/order/result?id=${order.id}` })
}
</script>

<template>
  <view class="confirm">
    <text>应付：{{ price.payable }}</text>
    <button :loading="submitting" :disabled="submitting" @click="onSubmit">提交订单</button>
  </view>
</template>

页面不再知道价格怎么算、订单接口长什么样；换后端字段只改 data/，改优惠规则只改 domain/。

四、把依赖方向变成门禁 ​

规则写在 scripts/layers.config.mjs，用仓库自带的 depcruise 脚本执行（下面是五层工程的示意配置；仓库内实际文件按电商示例的目录名调整为 api/transport/stores 等，规则含义一致）：

js
// scripts/layers.config.mjs
export const layers = {
  pages: ['components', 'composables', 'application', 'stores', 'data', 'domain', 'config', 'utils', 'types'],
  components: ['components', 'composables', 'types', 'utils'],
  application: ['domain', 'data', 'config', 'utils', 'types'],
  domain: ['types', 'utils'],
  data: ['domain', 'config', 'utils', 'types'],
  stores: ['data', 'domain', 'config', 'utils', 'types'],
  utils: ['types'],
  config: ['types']
}
bash
# 检查整个电商示例工程（默认目录）
pnpm depcruise

# 检查任意 uni-app 工程
node scripts/depcruise.mjs path/to/src

脚本按「导入语句 → 目标目录 → 所属层」判定，发现越层立即非零退出。它同时放行 import type（类型依赖不产生运行时耦合），并支持登记技术债：

js
export const exemptions = [
  { file: 'utils/track.ts', imports: ['api/core'], reason: '待迁移到 api/telemetry' }
]

团队装了 dependency-cruiser 时，可以用同一套层定义写 .dependency-cruiser.cjs，在 PR 里输出可视化依赖图；两者结论一致，脚本保证离线也能拦截。

五、验收标准 ​

bash
pnpm depcruise
# 期望：✅ 分层依赖检查通过（已登记的技术债只警告）

# 反向验证：在 pages 里加一行 import { http } from '@/data/transport'
pnpm depcruise
# 期望：❌ pages → transport 越层依赖，退出码 1

能通过以下三问，才算真正建立了分层：

  1. 页面里能否找到接口 URL、价格公式、订单状态迁移？——找到即说明职责泄漏。
  2. 领域函数能否不启动 uni-app 环境直接跑单测？——不能则说明依赖了运行时。
  3. 新增一条越层导入，CI 是否会红？——不会则规则还是纸面约定。
