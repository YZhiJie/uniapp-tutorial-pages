11.3 实战案例：从 0 完成一个跨端工具箱 ​

这是整个教程的毕业项目。你将独立完成一个可在 H5、微信小程序、App 三端运行的工具箱 App，把前面所有模块的知识串成一条线。

产品定义 ​

应用名：随身工具箱

功能范围（MVP）：

  1. 工具宫格首页：扫码识别、定位打卡、文本记录、二维码生成（可基于第三方库/插件）
  2. 扫码：支持 URL/WiFi/文本识别，结果入库，可复制、可跳转
  3. 定位打卡：地图展示 + 记录列表，支持逆地址解析
  4. 记录：增删改查、按类型筛选、本地持久化
  5. 导出：CSV/JSON，三端都能拿到文件
  6. 我的：权限状态查看、清空数据、关于、订阅消息/通知引导

里程碑一：工程基线（对应模块 2） ​

  • [ ] 用 degit dcloudio/uni-preset-vue#vite-ts 创建 CLI 工程，pnpm 管理
  • [ ] ESLint flat config + Prettier + git pre-commit（2.3）
  • [ ] 路径别名、环境变量、@dcloudio/types
  • [ ] Pinia 注册、请求层骨架（即使主要离线，也预留同步 API）

目录：

text
src/
├─ pages/index records scan location settings
├─ platforms/{scanner,location,storage,share,permission}/
├─ services/{db,records-repository,export,sync-queue}.ts
├─ stores/{records,app}.ts
├─ components/{uni-button,uni-card,empty-state,list-cell}
└─ api/request.ts

里程碑二：数据层（对应模块 6、11.2） ​

  • [ ] 定义 LocalDatabase 接口与三端实现
  • [ ] records store：列表、筛选、增删改，变更写本地
  • [ ] 同步队列（先留接口，后接云端）：outbox 模式，监听网络状态回放

验收：杀掉应用再打开，数据完整；列表滚动 60fps（千条记录时用虚拟列表，8.2）。

里程碑三：能力集成（对应模块 7、11.1/11.2） ​

  • [ ] 扫码：H5 提供图片上传降级；小程序/App 原生扫码
  • [ ] 定位：完整权限流程（申请/拒绝/引导设置），坐标系统一
  • [ ] 分享：平台分支；兜底用海报图方案
  • [ ] 振动/剪贴板等小反馈：扫码成功 uni.vibrateShort()

验收：对照 7.3 权限验收清单逐端通过。

里程碑四：页面与交互（对应模块 3、5） ​

  • [ ] 宫格首页（自定义布局，图标 + 名称 + 角标）
  • [ ] 类型安全路由封装（5.3）
  • [ ] 记录列表：分组、空状态、触底分页（本地查询分页）
  • [ ] 表单页：校验、编辑复用、防重复提交

验收：全部跳转使用统一路由封装；无硬编码 url 字符串。

里程碑五：导出与通知（对应模块 11.2） ​

  • [ ] CSV/JSON 导出三端验证（iOS/Android/微信/H5 各一次）
  • [ ] 小程序订阅消息 / App 本地通知的打卡提醒
  • [ ] 设置页：权限状态展示、清除缓存、版本信息

里程碑六：性能与发布（对应模块 8、1） ​

  • [ ] 跑一遍 8.3 性能审计清单，记录量化表
  • [ ] 主包体积检查：导出页等放分包
  • [ ] 图片资源全部 CDN/压缩，图标用字体或雪碧图
  • [ ] 小程序：配置合法域名、隐私协议（现行审核必需）、订阅消息模板
  • [ ] App：manifest 权限说明文案、自定义基座真机回归后云打包
  • [ ] H5：部署 HTTPS、history 回退配置、页面 title/meta（若内嵌 web）

扩展挑战（学有余力） ​

  1. 云端同步：接入登录体系，实现 outbox 增量同步与多端冲突合并（可参考 10.3 离线消息窗口 的 seq 思路）。
  2. 二维码生成：canvas 离屏绘制，保存相册走 11.2 保存图片流程。
  3. 国际化：vue-i18n 接入中英双语，注意文案长度变化对布局的影响。
  4. 主题切换：深色模式跟随系统（CSS 变量 + uni.onThemeChange）。
  5. 自动化测试：把类型判断、坐标转换、CSV 转义、状态机等纯函数用 Vitest 覆盖（本教程站点的 tests 目录 就是参考组织方式）。

最后的建议 ​

  • 每学完一个模块就把代码提交到 git，commit message 写清「解决了什么问题」。
  • 遇到 API 行为差异，先查官方文档对应平台的「兼容性说明」表格，再写条件编译。
  • 跨端开发的最高境界不是「所有端一模一样」，而是用同一套业务内核，给出各平台用户最熟悉的体验。
