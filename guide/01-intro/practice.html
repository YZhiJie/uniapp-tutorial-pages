1.3 实战案例：第一个多端页面与四端产物对比 ​

本篇假设你尚未搭建环境，只需先安装 HBuilderX（正式版）即可完成全部操作；CLI 工程化方式在下一模块详解。

步骤一：创建项目 ​

  1. HBuilderX → 文件 → 新建 → 项目 → 选择 uni-app。
  2. 模板选择「Vue 3」版本的默认模板（标识为 Vue 3 + Vite）。
  3. 勾选启用 TypeScript（本教程后续代码均为 TS）。

生成的核心目录：

text
my-first-app/
├─ pages/
│  └─ index/index.vue        # 首页
├─ static/                  # 不参与编译的静态资源
├─ App.vue                  # 应用根组件（全局生命周期）
├─ main.ts                  # 入口：createSSRApp
├─ pages.json               # 页面路由与导航配置
├─ manifest.json            # 应用标识与各端配置
└─ uni.scss                 # 全局 scss 变量（可选）

main.ts 的标准形态：

ts
import { createSSRApp } from 'vue'
import App from './App.vue'

export function createApp() {
  const app = createSSRApp(App)
  return { app }
}

即使只做小程序也要用 createSSRApp：这是 uni-app 的统一入口约定，与服务端渲染无关，照写即可。

步骤二：写第一个跨端页面 ​

替换 pages/index/index.vue：

vue
<template>
  <view class="container">
    <view class="card">
      <text class="title">平台指纹</text>
      <text class="line">当前平台：{{ platform }}</text>
      <text class="line">窗口宽度：{{ windowWidth }}px</text>
      <text class="line">像素比：{{ pixelRatio }}</text>
    </view>
    <button type="primary" @click="getSystemInfo">重新读取设备信息</button>
  </view>
</template>

<script setup lang="ts">
import { ref } from 'vue'
import { onShow } from '@dcloudio/uni-app'

const platform = ref('')
const windowWidth = ref(0)
const pixelRatio = ref(0)

function readInfo() {
  const info = uni.getDeviceInfo()
  const win = uni.getWindowInfo()
  platform.value = info.platform // devtools / ios / android / mac / windows…
  windowWidth.value = win.windowWidth
  pixelRatio.value = win.pixelRatio
}

// uni-app 页面生命周期：页面显示时触发
onShow(() => {
  readInfo()
})

function getSystemInfo() {
  readInfo()
  uni.showToast({ title: '信息已更新', icon: 'success' })
}
</script>

<style scoped>
.container {
  padding: 32rpx;
}
.card {
  padding: 40rpx;
  margin-bottom: 32rpx;
  border-radius: 20rpx;
  background: #f4f7ff;
  display: flex;
  flex-direction: column;
  gap: 12rpx;
}
.title {
  font-size: 36rpx;
  font-weight: 700;
  margin-bottom: 12rpx;
}
.line {
  font-size: 28rpx;
  color: #475569;
}
</style>

要点回顾：

  • onShow 不是 Vue 的生命周期，而是从 @dcloudio/uni-app 导入的页面生命周期。
  • 设备信息被拆成了 getDeviceInfo() 与 getWindowInfo() 等小 API（旧的 getSystemInfoSync 仍可用，但新代码推荐按用途拆分的接口）。

步骤三：三端运行对照 ​

H5 ​

HBuilderX 中：运行 → 运行到浏览器 → Chrome。观察：

  • 页面是标准 DOM：打开 DevTools，能看到 <uni-page-body>、<uni-view> 等自定义元素。
  • platform 在桌面浏览器上是 mac / windows，因为它读的是真实宿主环境。

微信小程序 ​

  1. 安装微信开发者工具，并在 HBuilderX 配置其安装路径。
  2. 运行 → 运行到小程序模拟器 → 微信开发者工具。
  3. 首次需要微信开发者工具开启「服务端口」（设置 → 安全设置）。

观察：

  • 工程被编译到 dist/dev/mp-weixin，微信开发者工具实际打开的是这个产物目录。
  • WXML 面板里没有 <uni-view>，而是小程序原生组件树。
  • DevTools 的 Storage/Network 面板与浏览器完全不同。

App（真机） ​

  1. 手机开启开发者模式与 USB 调试（Android）或用数据线连接并信任（iOS）。
  2. 运行 → 运行到手机或模拟器 → 基座标准调试。
  3. HBuilderX 会把「标准基座」App 安装到手机，再把 JS 资源推送到基座中执行。

观察：

  • 导航栏、按钮反馈明显更接近原生控件。
  • 改代码后支持热更新同步到真机。
  • 正式发布需要在 HBuilderX 中「云打包/本地打包」生成独立安装包（或使用 uni-app x 的原生打包）。

步骤四：做一张三端差异观察表 ​

在同一个页面上逐项实验并记录（强烈建议自己动手，而不是只看结论）：

实验项H5微信小程序App
platform 返回值桌面系统名devtools/真机环境ios/android
加一段 document.title = 'x'✅ 生效❌ 报错/无效❌ 不可依赖
CSS position: fixed正常受原生导航栏影响，需预留安全区同小程序
100vh 含义浏览器视口不含/含导航栏因端而异建议用 100% + flex
uni.scanCode走 H5 降级方案（不可用或需自定义）微信原生扫码原生扫码

可以刻意在代码中加入一个平台分支，直观感受条件编译：

ts
function share() {
  // #ifdef H5
  navigator.clipboard?.writeText(window.location.href)
  uni.showToast({ title: '链接已复制', icon: 'none' })
  // #endif
  // #ifdef MP-WEIXIN
  uni.showShareMenu({ withShareTicket: true })
  // #endif
}

练习 ​

  1. 新增第二个页面 pages/about/about.vue，在 pages.json 注册，首页加按钮用 uni.navigateTo 跳转（提示：跳转 API 会在 模块 5 细讲）。
  2. 把设备信息写进 Pinia store（可先预习 6.2），在第二页读取。
  3. 在微信开发者工具的 Network 面板观察首屏加载的资源清单，记录数量；H5 端再记录一次，思考差异来源。
