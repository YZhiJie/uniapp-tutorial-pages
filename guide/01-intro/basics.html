1.1 基础入门：uni-app 是什么、能做什么 ​

学习目标 ​

  • 能用一句话向同事解释 uni-app 的定位
  • 说出 uni-app 的四个主要发布端与各自的运行载体
  • 能根据项目需求判断「该不该用 uni-app」

一句话定位 ​

uni-app 是一个使用 Vue 语法开发、可同时发布到多个平台的跨端框架：一份代码经过条件编译，产出 H5、iOS/Android App、各家小程序（微信/支付宝/抖音等）的安装包或网页。

本教程基于 uni-app 的 Vue 3 + Vite 版本（社区也称 vue3 版），它与 Vue 2 版的区别见下表：

对比项Vue 2 版（旧）Vue 3 + Vite 版（本教程）
语法Options API 为主Composition API + <script setup>
构建webpackVite，冷启动与热更新显著更快
状态管理VuexPinia
TypeScript支持一般一等公民，模板类型检查完整
新项目建议不再使用首选

生态全景：uni-app 提供了什么 ​

  1. 运行时 API：uni.request、uni.navigateTo、uni.scanCode 等以 uni.* 命名的统一 API，内部按平台调用不同实现。
  2. 内置组件：<view>、<text>、<scroll-view>、<swiper> 等，编译后映射为各端的真实组件（H5 上映射为适配过的 DOM 标签）。
  3. 工程配置：pages.json（页面注册与导航样式）、manifest.json（应用标识与各端配置）。
  4. 插件市场与 uni-ui：DCloud 插件市场提供大量现成组件、UTS 插件、原生 SDK 封装；uni-ui 是官方扩展组件库。
  5. uni-app x（UTS）：更激进的下一代分支，编译为平台原生（Kotlin/Swift），性能更强但生态与写法有差异。本教程聚焦主流稳定的 uni-app Vue3 版，新项目选型时可把 x 版作为专项调研。

与常见技术方案对比 ​

方案语言/语法小程序支持App 性能Web 生态复用适合场景
uni-appVue 3✅ 原生级良好（weex/原生渲染 + webview 混合）高需要同时覆盖小程序 + App + H5
原生微信小程序WXML/WXS/JS✅ 仅微信❌低只做微信生态、追求极致平台特性
React Native / FlutterReact / Dart❌（需另写）最好中只要 App，不要小程序
纯 H5（Vue/React）Vue/React❌需套壳最高只要浏览器

关键结论：当目标平台包含“小程序”且团队熟悉 Vue 时，uni-app 几乎是成本最低的统一方案。

最小页面长什么样 ​

vue
<!-- pages/index/index.vue -->
<template>
  <view class="page">
    <text class="title">{{ message }}</text>
    <button type="primary" @click="onTap">点我计数</button>
    <text>已点击 {{ count }} 次</text>
  </view>
</template>

<script setup lang="ts">
import { ref } from 'vue'

const message = ref('你好，uni-app')
const count = ref(0)

function onTap() {
  count.value++
  // uni.* API 在所有端都可用
  uni.showToast({ title: `第 ${count.value} 次点击`, icon: 'none' })
}
</script>

<style>
.page {
  display: flex;
  flex-direction: column;
  gap: 24rpx;
  padding: 48rpx 32rpx;
}
.title {
  font-size: 40rpx;
  font-weight: 700;
}
</style>

注意三个与普通 Web Vue 项目不同的细节：

  • 根节点用 <view> 而不是 <div>，文字建议包在 <text> 里（小程序端 text 才能被选中/长按）。
  • 尺寸单位大量使用 rpx（750rpx 恒等于屏幕宽度），而不是 px。
  • 交互反馈不用 alert，而是 uni.showToast / uni.showModal。

选型决策：什么时候不该用 uni-app ​

适合：

  • 业务需要同时上线微信小程序 + App + H5，团队希望共享 70% 以上代码。
  • 表单、列表、电商、社交、工具类等常规信息流应用。
  • 团队已掌握 Vue 3，迁移成本最低。

需要谨慎：

  • 重动画/重图形（3D 游戏、复杂视频剪辑轨道）：请专项验证渲染性能或选原生引擎。
  • 只在一个平台上线且强依赖该平台最新独占能力：直接原生开发等待时间更短。
  • 需要极复杂的原生底层能力（蓝牙协议栈、自定义渲染管线）：评估 UTS 插件开发成本。

常见问题 ​

Q：uni-app 是不是“低代码/套壳工具”？ 不是。它是标准的 Vue 工程，有完整的组件化、npm 依赖、TypeScript、构建流水线，产物质量取决于工程水平——这也是本教程存在的意义。

Q：H5 端为什么不能直接用 DOM API？ 编译到小程序时没有 DOM。代码里一旦出现 document.querySelector，就意味着放弃了小程序端。跨端代码应使用 uni.* API 与组件 refs，把 DOM 操作隔离到 H5 专属分支（7.2 条件编译会讲）。

Q：版本号怎么选？ HBuilderX 正式版与 @dcloudio/* npm 包版本是配套发布的。CLI 项目请保持所有 @dcloudio 包同一版本号，不要单独升级某一个；具体版本号以 DCloud 官方发布说明为准。
