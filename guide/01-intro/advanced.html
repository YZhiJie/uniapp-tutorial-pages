1.2 进阶应用：核心原理与多端编译机制 ​

学习目标 ​

  • 画出 uni-app 在小程序端的双线程模型，并解释数据从点击到渲染的完整路径
  • 说清「编译时」和「运行时」各做了什么
  • 理解为什么频繁修改数据会导致小程序卡顿（为模块 8 埋点）

双线程模型（小程序端最关键的架构） ​

微信小程序从设计上把代码拆进两个线程：

  • 逻辑层（AppService / JSCore）：运行你的 JS/TS：业务逻辑、Pinia store、网络请求、uni.* 调用。没有 DOM、没有 window。
  • 视图层（WebView / Skyline）：运行模板编译后的渲染代码，负责 UI 绘制与事件捕获。
mermaid
sequenceDiagram
  participant U as 用户
  participant V as 视图层(WebView)
  participant B as native 桥(JSBridge)
  participant L as 逻辑层(JSCore)
  U->>V: 点击按钮
  V->>B: 事件(tap, dataset)
  B->>L: 序列化后转发
  L->>L: 执行 onClick / 修改 ref
  L->>B: 下发数据差异
  B->>V: setData 合并渲染
  V->>U: UI 更新

每次响应式数据改变，最终都会变成一次（或被合并的）跨线程数据传输。数据要被序列化、经过原生桥、再在视图层 diff 渲染。这条链路就是后面所有性能经验的根源：

传输数据量越大、频率越高，UI 越卡。

H5 端逻辑层与视图层在同一个浏览器线程，不存在 JSBridge 成本；App 端则是「逻辑层独立 JSCore + 原生渲染/webview 渲染」的混合架构，成本介于两者之间。

编译时：编译器替你做了什么 ​

以 Vue 3 + Vite 版为例，源码进入构建后按目标平台走不同插件流水线：

.vue 单文件组件
   │
   ├─ template 编译
   │    ├─ H5：编译为标准 Vue 虚拟节点（运行到浏览器 DOM）
   │    └─ 小程序：编译为各平台的 wxml/wxss/axml 等模板文件 + 渲染函数描述
   ├─ script
   │    ├─ <script setup> 经 Vue SFC 编译
   │    └─ 条件编译指令在这一步“剪枝”，不属于当前平台的代码直接消失
   ├─ style：rpx 换算、条件样式、css 变量
   └─ pages.json / manifest.json：转换为各平台配置

值得记住的三点：

  1. 条件编译是物理删除，不是运行时 if。// #ifdef MP-WEIXIN 包裹的代码不会出现在 H5 产物里（在线体验：条件编译演练场）。
  2. 组件与 API 存在“映射表”：<view> 在 H5 产物里是一个带样式约定的 <uni-view> 自定义元素；uni.request 在 H5 走 XHR/fetch，在小程序走 wx.request。
  3. easycom 自动注册在编译期扫描 components/组件名/组件名.vue，免 import 即可使用（详见 3.2）。

运行时：一个点击事件的完整旅程 ​

以「点击按钮加入购物车」为例：

  1. 视图层捕获 tap，把事件对象（含 dataset）经 JSBridge 发给逻辑层。
  2. 逻辑层执行 cartStore.add(goodsId)：Pinia 修改 state，Vue 的响应式系统标记依赖。
  3. 同一次事件循环内的多次数据修改会被 Vue 调度器合并，下一个微任务统一计算组件更新。
  4. 小程序运行时把更新序列化为 setData 数据（只传变化路径上的数据），经桥下发。
  5. 视图层合并数据、重新渲染对应节点；如果有原生反馈（震动/Toast），则并行调用原生能力。

工程启示：

  • 不要在一个滚动回调里高频改大对象：即便 Vue 合并了，最后一次 setData 仍可能携带巨大 payload。
  • 长列表场景使用「分页数据 + 虚拟列表」，避免单个页面数据节点无限增长。
  • 与视图无关的数据（计时器、缓存、接口原始报文）不必放进响应式 state，可用普通变量/模块单例存放。

手动验证编译产物 ​

用 CLI 工程（下一章会搭建）可以直接看到剪枝效果：

bash
# H5 产物：dist/build/h5，是标准静态站点
pnpm build:h5

# 微信小程序产物：dist/build/mp-weixin，用微信开发者工具导入即可
pnpm build:mp-weixin

打开两个产物目录对比同一个页面：H5 目录里是 JS chunk + HTML；小程序目录里是 app.js / app.json / pages/**/*.wxml。对照源码搜索某个只写在 #ifdef MP-WEIXIN 里的字符串，你会发现它只存在于小程序产物中。

常见问题 ​

Q：既然最终要 setData，为什么还需要 Vue 的响应式？ Vue 负责精准算出“哪些组件依赖哪些数据”，让运行时可以只下发变化路径而不是整页数据。没有这层依赖追踪，每次更新都只能全量下发。

Q：逻辑层和视图层为什么不放在一个线程？ 小程序平台的安全与管控设计：逻辑层无法直接操作 UI，无法通过 JS 跳出沙箱；代价就是通信开销。Skyline 渲染引擎在持续降低这部分成本。

Q：App 端是 webview 套壳吗？ 不是简单套壳。uni-app App 端大量内置组件与导航是原生控件，页面逻辑跑在独立 JS 引擎；但复杂自定义 UI 区域仍可能基于 webview，性能分析时要区分（见 8.1 性能度量）。
