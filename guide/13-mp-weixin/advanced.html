13.2 进阶应用：微信能力深度集成 ​

基础入门讲的是"产物长什么样"，本篇讲真正让小程序跟其他端拉开差距的能力：鉴权、支付、消息触达、手机号——这些几乎是所有微信小程序产品的标配，链路多、坑点多、后端和前端要一起配合。

学习目标 ​

  • 跑通 uni.login → code2session → openid/unionid 的完整鉴权链路，理解四端（H5 / App / 小程序）的登录差异
  • 能用 uni.requestPayment 正确调起微信支付，清楚后端签名参数和客户端字段对应关系
  • 配置一次性 / 长期订阅消息模板并完成客户端申请 + 后端发送闭环
  • 实现 getPhoneNumber 一键登录和小程序分包

一、鉴权体系：openid / unionid 与 code2session ​

先搞懂三个 ID ​

概念生成方作用域何时拿到
code微信一次性、5 分钟有效调 wx.login 返回，临时凭证
openid微信一个用户 + 一个 AppID 唯一后端拿 code 换 session_key/openid
unionid微信开放平台一个用户 + 一个开放平台账号 唯一仅当小程序绑定了开放平台主体时才有
session_key微信解密用户敏感数据（手机号等）同上，换 openid 时一起返回

关键：openid 仅在当前小程序唯一。如果你的产品有多个小程序或还要打通 App / 公众号，必须拿到 unionid 做跨端账号合并。

完整 code2session 链路 ​

前端（uni-app）：

ts
// src/services/auth/wechat-login.ts
export async function wechatLogin(): Promise<{ openid: string; unionid?: string }> {
  // uni.login 内部会根据平台调 wx.login / plus.login / OAuth
  const res = await new Promise<UniApp.LoginRes>((resolve, reject) => {
    uni.login({ provider: 'weixin', success: resolve, fail: reject })
  })

  if (!res.code) throw new Error('登录失败：未获得 code')

  // 把 code 发给后端，后端用 AppID + AppSecret 换 openid/session_key
  const { data } = await uni.request({
    url: `${BASE_URL}/auth/wechat/code2session`,
    method: 'POST',
    data: { code: res.code }
  })

  if ((data as any).code !== 0) throw new Error((data as any).message)
  return (data as any).data
}

后端（Node.js / Express 示例，真实项目替换成你自己的框架）：

ts
// server/routes/auth.ts
import express from 'express'
import axios from 'axios'

const router = express.Router()

router.post('/wechat/code2session', async (req, res) => {
  const { code } = req.body
  if (!code) return res.status(400).json({ code: 1, message: '缺少 code' })

  // 用 AppID + AppSecret + code 向微信服务器换 openid/session_key
  // https://api.weixin.qq.com/sns/jscode2session
  const { data: wxRes } = await axios.get('https://api.weixin.qq.com/sns/jscode2session', {
    params: {
      appid: process.env.WX_APPID,
      secret: process.env.WX_APP_SECRET,
      js_code: code,
      grant_type: 'authorization_code'
    }
  })

  // 微信返回可能是 { openid, session_key, unionid } 或 { errcode, errmsg }
  if (wxRes.errcode) {
    return res.json({ code: 1, message: `微信错误 ${wxRes.errcode}: ${wxRes.errmsg}` })
  }

  const { openid, session_key, unionid } = wxRes

  // 数据库里根据 openid / unionid 查找或创建用户
  const user = await findOrCreateUser({ openid, unionid })

  // 签发自己的业务 JWT（不要把 openid 直接当地下令牌）
  const token = signJwt({ uid: user.id, openid }, '2h')

  res.json({ code: 0, data: { token, openid, unionid } })
})

uni.login 四端差异 ​

uni.login({ provider: 'weixin' }) 在四个端行为不同，你必须清楚哪些字段只有小程序端才给：

端uni.login 内部调用返回字段注意点
微信小程序wx.logincode（有），openid/unionid（无，后端换）小程序独有链路
H5（微信内）OAuth2 跳转code（URL query 里），需自己解析不是自动返回，要用 uni.getProvider 取 code
H5（非微信）不支持 weixin provider调起 uni.login 会 fail需账号密码/手机号登录
Appplus.login 或 uni.login({ provider: 'weixin' })code + authResult + 用户信息App 走开放平台授权，需要集成微信 SDK

统一登录适配层：

ts
// src/services/auth/login.ts
export async function loginByPlatform(): Promise<{ token: string; user: User }> {
  // #ifdef MP-WEIXIN
  const { token, openid } = await wechatLogin()
  return { token, user: await fetchMe(token) }
  // #endif

  // #ifdef H5
  // H5 端一般是手机号+短信/密码
  const { token } = await smsLogin()
  return { token, user: await fetchMe(token) }
  // #endif

  // #ifdef APP-PLUS
  // App 支持一键登录（运营商）+ 微信授权双通道
  const channel = preferQuickLogin() ? 'quick' : 'wechat'
  const { token } = channel === 'quick' ? await quickLogin() : await wechatLogin()
  return { token, user: await fetchMe(token) }
  // #endif
}

二、微信支付：签名链路与字段对照 ​

谁负责什么 ​

  • 前端：调起 uni.requestPayment，展示支付结果（success / fail / cancel）。不参与签名、不拼金额。
  • 后端：调用微信统一下单 API（v3/pay/transactions/jsapi），拿到 prepay_id，按规则拼接待签名字符串并签名，把签名后的参数返回给前端。
  • 微信服务器：校验签名，扣款，回调通知后端支付结果。

后端统一下单（JSAPI 支付，小程序场景） ​

ts
// server/services/pay.ts
import axios from 'axios'
import * as crypto from 'crypto'

/**
 * 小程序 JSAPI 支付 —— 后端统一下单
 * @param openid  用户 openid
 * @param outTradeNo 业务订单号
 * @param amountFen 金额（分）
 */
export async function createJsapiPayParams(
  openid: string,
  outTradeNo: string,
  amountFen: number
) {
  const body = {
    appid: process.env.WX_APPID,
    mchid: process.env.WX_MCH_ID,
    description: '商品描述',
    out_trade_no: outTradeNo,
    notify_url: process.env.WX_PAY_NOTIFY_URL,
    amount: { total: amountFen, currency: 'CNY' },
    payer: { openid }
  }

  // v3 接口需要请求签名（商户私钥）
  const { data } = await axios.post(
    'https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi',
    body,
    { headers: buildWechatAuthHeaders('POST', '/v3/pay/transactions/jsapi', JSON.stringify(body)) }
  )

  const prepayId = data.prepay_id

  // 返回给小程序端的 5 个参数（官方规定顺序）
  const signParams = {
    appId: process.env.WX_APPID,
    timeStamp: String(Math.floor(Date.now() / 1000)),
    nonceStr: crypto.randomBytes(16).toString('hex'),
    package: `prepay_id=${prepayId}`,
    signType: 'RSA'
  }

  // 拼接签名串 → RSA 私钥签名 → 转 base64
  const signString = [
    signParams.appId,
    signParams.timeStamp,
    signParams.nonceStr,
    signParams.package,
    '' // signType 固定位置，但待签不含 signType
  ].join('\n') + '\n'

  const paySign = crypto.sign('RSA-SHA256', signString, privateKey).toString('base64')

  return { ...signParams, paySign }
}

老版本 v2 接口用 MD5 / HMAC-SHA256 + 商户 API key，package 字段格式不同。新项目一律用 v3。

前端调起支付 ​

ts
// src/services/pay/mp-weixin-pay.ts
export async function payByWechat(
  openid: string,
  outTradeNo: string,
  amountFen: number
): Promise<{ paid: boolean; transactionId?: string }> {
  // 1. 后端统一下单（前端不参与签名）
  const { data: params } = await uni.request({
    url: `${BASE_URL}/pay/create`,
    method: 'POST',
    data: { openid, outTradeNo, amount: amountFen, channel: 'jsapi' }
  })

  if ((params as any).code !== 0) throw new Error((params as any).message)

  const p = (params as any).data

  // 2. 调起 uni.requestPayment
  return new Promise((resolve, reject) => {
    uni.requestPayment({
      provider: 'wxpay',
      timeStamp: p.timeStamp,
      nonceStr: p.nonceStr,
      package: p.package,
      signType: p.signType,
      paySign: p.paySign,
      success(res) {
        // 注意：success 只代表客户端收到了支付成功回调，
        // 最终支付结果必须以后端 notify_url 的异步通知为准
        resolve({ paid: true })
      },
      fail(err) {
        const msg = String(err.errMsg || '')
        if (msg.includes('cancel') || msg.includes('cancel')) {
          resolve({ paid: false }) // 用户取消不算失败
        } else {
          reject(new Error(msg))
        }
      }
    })
  })
}

易踩的五个坑 ​

  1. 字段顺序：后端签名时待签名字符串的字段顺序必须是 appId\n timeStamp\n nonceStr\n package\n \n，一个字符不能差。
  2. 金额单位：微信接口所有金额都是分，用 integer，前端输入元的时候记得 × 100 再转整。
  3. 异步通知：success 回调不能作为支付到账依据；必须以后端 notify_url 收到的签名校验通知为准。
  4. 版本号：uni.requestPayment 在某些老 uni-app 版本上 provider 字段拼写不同（曾经有 wx / weixin 等），建议显式传 provider: 'wxpay'。
  5. 商户号与 AppID 绑定：商户号必须在微信商户后台绑定你的小程序 AppID，否则 JSAPI 下单会报错"非本商户号的 AppID"。

三、订阅消息：一次性 / 长期 / 半长期 ​

概念速记 ​

类型单次订阅消息数用户触发有效期
一次性N 次（用户每次确认）wx.requestSubscribeMessage一次订阅用完即止
长期无限（一次授权一直能发）同上，但模板必须标记"长期订阅"长期（可撤回）
半长期（设备订阅）需要用户每次在"设备"里点击订阅原生组件触发见官方文档

微信自 2023 年后已逐步收缩长期订阅模板开放范围，新项目优先用一次性订阅，按业务流程触发用户主动订阅（如下单完成时弹订阅"发货通知"）。

客户端申请订阅 ​

vue
<!-- 下单完成页：申请"发货通知"订阅 -->
<template>
  <button @tap="requestSubscribe">订阅发货通知</button>
</template>

<script setup>
const TEMPLATE_IDS = ['TPL_ID_ORDER_SHIPPED']

async function requestSubscribe() {
  try {
    // tmplIds 必须是 JSON 数组，每个元素是公众平台 → 订阅消息里创建的模板 ID
    const res = await new Promise<UniApp.RequestSubscribeMessageRes>((resolve, reject) => {
      uni.requestSubscribeMessage({
        tmplIds: TEMPLATE_IDS,
        success: resolve,
        fail: reject
      })
    })

    // 返回值示例：{ TPL_ID_ORDER_SHIPPED: 'accept' | 'reject' | 'ban' | 'filter' }
    const status = res[TEMPLATE_IDS[0]]
    if (status === 'accept') {
      uni.showToast({ title: '订阅成功', icon: 'success' })
    } else if (status === 'reject') {
      uni.showToast({ title: '已拒绝订阅', icon: 'none' })
    } else if (status === 'ban') {
      uni.showModal({ title: '订阅消息已被封禁', content: '请在设置中开启' })
    }
  } catch (e) {
    // 基础库 < 2.43.0 或其他错误
    uni.showToast({ title: '订阅消息不可用', icon: 'none' })
  }
}
</script>

后端发送订阅消息 ​

ts
// server/services/subscribe.ts
import axios from 'axios'

export async function sendSubscribeMessage(params: {
  openid: string
  templateId: string
  page?: string         // 消息点击跳转的小程序页面
  data: Record<string, string>
}) {
  const accessToken = await getOrRefreshAccessToken() // 缓存 access_token（2 小时有效）

  const { data } = await axios.post(
    `https://api.weixin.qq.com/cgi-bin/message/subscribe/send?access_token=${accessToken}`,
    {
      touser: params.openid,
      template_id: params.templateId,
      page: params.page,              // 可选：小程序页面路径，如 pages/order/detail?id=1
      data: {
        // 模板变量名 → 值（根据你公众平台模板定义的字段名）
        thing1: { value: '您的订单已发货' },
        thing2: { value: '顺丰快递 SF1234567890' },
        time3: { value: new Date().toLocaleString() }
      },
      miniprogram_state: 'formal'      // formal | developer | trial
    }
  )

  if ((data as any).errcode !== 0) {
    throw new Error(`订阅消息发送失败: ${(data as any).errmsg}`)
  }
  return data
}

四、getPhoneNumber 手机号一键登录 ​

getPhoneNumber 让用户授权后，微信把加密的手机号数据给前端，前端发后端用 session_key 解密得到真实手机号。注意 session_key 必须是当前登录那次 wx.login 换来的，过期或重新登录都会失效。

客户端 ​

vue
<template>
  <button open-type="getPhoneNumber" @getphonenumber="onGetPhoneNumber">
    一键授权手机号登录
  </button>
</template>

<script setup>
import { ref } from 'vue'

const loading = ref(false)

async function onGetPhoneNumber(e: any) {
  if (loading.value) return
  if (e.detail.errMsg !== 'getPhoneNumber:ok') {
    uni.showToast({ title: '授权被取消', icon: 'none' })
    return
  }
  loading.value = true
  try {
    const { data } = await uni.request({
      url: `${BASE_URL}/auth/wechat/phone`,
      method: 'POST',
      data: {
        code: e.detail.code,   // 新版接口返回 code，后端拿 code 换手机号
        // 老版本（基础库 2.21.2 以下）返回 encryptedData + iv，后端用 session_key 解密
      }
    })
    if ((data as any).code === 0) {
      uni.showToast({ title: '登录成功', icon: 'success' })
      uni.redirectTo({ url: '/pages/mine/mine' })
    }
  } finally {
    loading.value = false
  }
}
</script>

新版（2023.08 起） 微信把手机号接口改成了"code 换手机号"——用户点授权后前端拿到 code，后端用 access_token + code 调 https://api.weixin.qq.com/wxa/business/getuserphonenumber 拿明文手机号。老版本的 encryptedData + iv + session_key 解密方案已逐步淘汰。

后端手机号解密（新版 code 模式） ​

ts
// server/routes/auth.ts —— 手机号登录
router.post('/wechat/phone', async (req, res) => {
  const { code } = req.body
  const accessToken = await getOrRefreshAccessToken()

  // 用 code 换手机号
  const { data: wxRes } = await axios.post(
    `https://api.weixin.qq.com/wxa/business/getuserphonenumber?access_token=${accessToken}`,
    { code }
  )

  if ((wxRes as any).errcode !== 0) {
    return res.json({ code: 1, message: `微信错误 ${(wxRes as any).errmsg}` })
  }

  const phone = (wxRes as any).phone_info.purePhoneNumber
  // 根据手机号查找或创建用户，签发业务 token
  const user = await findOrCreateByPhone(phone)
  const token = signJwt({ uid: user.id }, '2h')
  res.json({ code: 0, data: { token, phone } })
})

使用 getPhoneNumber 的前置条件 ​

  1. 小程序主体为非个人主体（企业、政府、媒体等均可）。
  2. 小程序类目属于允许使用手机号的类目（如电商、社区等）。
  3. 已在公众平台 → 开发 → 接口设置中申请「手机号快速验证组件」权限。
  4. 用户必须主动点击带 open-type="getPhoneNumber" 的按钮——不能通过 JS 自动触发。

五、小程序分包：体积管理利器 ​

为什么分包重要 ​

  • 小程序主包体积上限 2MB（2022 年起主包 + 所有分包总计 20MB）。
  • 主包只放启动页和 tabbar 相关页面，其他功能按业务模块拆成独立分包，用户按需下载。

uni-app 里怎么配 ​

在 pages.json 里直接写 subPackages（uni-app 对原生 subpackages 做了别名）：

jsonc
{
  "pages": [
    { "path": "pages/index/index", "style": { "navigationBarTitleText": "首页" } },
    { "path": "pages/mine/mine", "style": { "navigationBarTitleText": "我的" } },
    { "path": "pages/login/login", "style": { "navigationBarTitleText": "登录" } }
  ],
  "subPackages": [
    {
      "root": "pages/trade",
      "name": "trade",
      "pages": [
        { "path": "order", "style": { "navigationBarTitleText": "订单" } },
        { "path": "order-detail", "style": { "navigationBarTitleText": "订单详情" } },
        { "path": "refund", "style": { "navigationBarTitleText": "退款" } }
      ]
    },
    {
      "root": "pages/user",
      "name": "user",
      "pages": [
        { "path": "address", "style": { "navigationBarTitleText": "收货地址" } },
        { "path": "setting", "style": { "navigationBarTitleText": "设置" } }
      ]
    }
  ],
  "globalStyle": { "navigationBarTextStyle": "black" }
}

编译产物与原生 app.json 的对应 ​

编译后生成的 app.json：

jsonc
{
  "pages": ["pages/index/index", "pages/mine/mine", "pages/login/login"],
  "subpackages": [
    {
      "root": "pages/trade",
      "name": "trade",
      "pages": ["order", "order-detail", "refund"]
    },
    {
      "root": "pages/user",
      "name": "user",
      "pages": ["address", "setting"]
    }
  ],
  "lazyCodeLoading": "requiredComponents"
}

完全是原生小程序的 subpackages 配置，uni 不做任何特殊处理。路由跳转的时候写完整路径即可：

ts
// 主包 → 分包
uni.navigateTo({ url: '/pages/trade/order-detail?id=1' })

// 分包之间跳转同样写完整路径
uni.navigateTo({ url: '/pages/user/address' })

分包预下载 ​

用户在主包时，可以提前让微信后台预下载常用分包，减少进入分包时的白屏：

jsonc
// pages.json
{
  "preloadRule": {
    "pages/index/index": {
      "network": "wifi",
      "packages": ["trade", "user"]
    }
  }
}

分包的几个坑 ​

  1. 静态资源路径：分包目录下的图片引用必须用绝对路径 /static/... 或者 分包根内相对路径，跨分包不能直接引用。
  2. 组件跨包：分包不能引用另一个分包的自定义组件。把公共组件放到主包或分包 A 当依赖分包 B 组件时，B → A 单向依赖，A 不能反向依赖 B。
  3. 页面栈：分包跳转走的是完整路径，跟主包一样有 10 页栈上限。
  4. 启动性能：分包不会在启动时加载，所以主包要保持极简。用开发者工具「代码依赖分析」查看每个文件的体积占比。
  5. 真机分包加载失败：弱网下分包下载可能失败，业务层需要捕获并降级（或给用户重试）：
ts
try {
  await new Promise<void>((resolve, reject) => {
    uni.navigateTo({ url: '/pages/trade/order', success: () => resolve(), fail: reject })
  })
} catch (e) {
  uni.showModal({
    title: '页面加载失败',
    content: '网络不佳，是否重试？',
    success: ({ confirm }) => confirm && uni.reLaunch({ url: '/pages/trade/order' })
  })
}

常见问题 ​

Q：openid 和 unionid 到底该存哪个？ 单小程序项目两个都存；有跨端需求（多小程序、App、公众号）一定要拿 unionid 做账号主键。获取 unionid 的前提：小程序绑定到微信开放平台的同一个主体下。

Q：支付的时候用户把 App 杀了，钱付了但前端没收到 success 怎么办？ 后端 notify_url 的异步通知才是真凭实据。前端在支付页提供"查询支付结果"按钮，用户杀了 App 重新进入后可以点一下主动向后端查订单状态。后端也要在每次定时任务里对未收到 success 但已扣款的订单做补偿。

Q：订阅消息为什么用户点了"总是保持以上选择"之后就再也收不到了？ 用户点的是"总是拒绝"。引导用户在首次触发时只弹一个模板，不要一次弹 N 个——多模板一起用户更容易点拒绝。

Q：分包体积总是超怎么办？ ① 用 static/ + CDN 托管图片，主包静态资源尽量为空；② 把大的第三方库改成按需引入或放分包；③ 用分包异步化 + 按需注入；④ 用 uni-vue-i18n 等国际化库时，把语言包分包。
