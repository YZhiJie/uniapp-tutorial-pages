13.1 基础入门：uni-app 小程序编译产物与原生差异 ​

你写的是 Vue 单文件组件，跑起来的是小程序原生代码。理解编译产物长什么样、uni 替你做了什么、哪些地方是透明等价、哪些地方有坑——这三件事是每个 uni-app 开发者必须建立的底层认知。

学习目标 ​

  • 看懂 dist/dev/mp-weixin/ 产物树，定位对应的 app.json / pages.json / 页面 wxml/wxss/js
  • 建立 uni API ↔ 原生 wx API 的映射心智模型，知道什么时候需要回退到 wx.xxx
  • 区分开发者工具模拟器、真机、iOS / Android 不同机型的调试差异，避免"我这儿没问题"

一、从源代码到编译产物 ​

执行 pnpm build:mp-weixin（或 HBuilderX 运行到微信开发者工具），编译器会在 dist/dev/mp-weixin/ 产出一份标准原生小程序项目。把这个目录整体"导入"微信开发者工具即可运行——里面没有任何 uni 运行时，只有小程序能吃下去的 wxml / wxss / js / json。

典型产物树：

text
dist/dev/mp-weixin/
├─ app.js                      # 全局入口，由 App.vue + main.js 生成
├─ app.json                    # 全局配置，由 manifest.json + pages.json 合并
├─ app.wxss                    # 全局样式，uni.scss 编译产物
├─ project.config.json         # 开发者工具项目配置
├─ sitemap.json                # 微信搜索索引规则
├─ pages/
│  ├─ index/
│  │  ├─ index.js              # 页面逻辑
│  │  ├─ index.json            # 页面配置（navigationBarTitleText 等）
│  │  ├─ index.wxml            # 页面结构（template 编译）
│  │  └─ index.wxss            # 页面样式
│  └─ detail/
│     ├─ detail.js
│     ├─ detail.json
│     ├─ detail.wxml
│     └─ detail.wxss
├─ components/
│  └─ uni-xxx/                 # uni 内置组件（如 uni-swiper）
├─ static/                     # 静态资源原样拷贝
└─ common/
   ├─ vendor.js                # 第三方库（vue / pinia / runtime）
   └─ xxx.js                   # 分包前的公共 chunk

app.json ↔ manifest.json + pages.json ​

原生小程序的 app.json 由两部分合并而成：

app.json 字段uni-app 来源备注
pagespages.json → pages[]页面路径数组，顺序即启动页
subpackagespages.json → subPackages[]分包配置直接透传
windowpages.json → globalStyle导航栏、背景色等
tabBarpages.json → tabBartab 图标建议放 static 目录
usingComponents编译器自动收集从 template 中扫描到的组件
permissionmanifest.json → mp-weixin → permission权限声明（如 scope.userLocation）
requiredPrivateInfosmanifest.json → mp-weixin → requiredPrivateInfos隐私接口声明（2023 年后必须配）
lazyCodeLoading固定 requiredComponentsuni 默认开启，降低首包体积

组件映射：uni 写的 view/text 去哪了？ ​

uni-app template 标签不是原样输出到 wxml，而是按"运行时组件映射表"替换：

uni template 标签编译后 wxml 标签备注
<view><view>一对一
<text><text>一对一
<image><image>一对一
<scroll-view><scroll-view>一对一
<swiper><swiper>一对一，但 wrapper 是 uni-swiper 运行时组件
<block><block>原生虚拟节点
<template><template>原生
<button><button>原生，配合 open-type 直接生效
<navigator><navigator>原生
<map><map>原生组件，注意层级和同层渲染
<video><video>原生组件

要点：原生小程序所有内置组件都直接可用，反过来——你在 template 里写 <button open-type="getPhoneNumber">，编译后就是原样的 wxml，uni 不做二次包装。只有 uni-* 前缀（如 uni-popup、uni-swiper）的组件才是 uni 自己实现的运行时组件。

一个页面的完整编译对照 ​

你写的 pages/index/index.vue：

vue
<template>
  <view class="root">
    <text class="title">你好 {{ name }}</text>
    <button @tap="sayHi">点我</button>
  </view>
</template>

<script setup>
import { ref } from 'vue'
const name = ref('uni-app')
function sayHi() {
  uni.showToast({ title: 'Hi', icon: 'success' })
}
</script>

<style lang="scss">
.root { padding: 20rpx; .title { font-size: 32rpx; } }
</style>

编译产物 pages/index/index.wxml（简化）：

xml
<view class="root">
  <text class="title">你好 {{name}}</text>
  <button bindtap="sayHi">点我</button>
</view>

pages/index/index.js（简化）：

js
const Vue = require('vue')
const { createSSRApp } = require('vue')
// ... uni runtime 初始化
App({
  onLaunch() { /* App.vue 的 onLaunch */ }
})

pages/index/index.wxss：

css
.root { padding: 20rpx; }
.root .title { font-size: 32rpx; }

可以看到：template 和 CSS 基本是直接翻译 + scoped 样式展开 + rpx 单位保留；JS 则被包装进一个 Vue 运行时容器。

二、uni API ↔ 原生 wx API 映射 ​

绝大多数 uni API 是薄封装，参数 / 回调直接透传到 wx.*。下面是高频 API 的对应关系：

uni API底层 wx API主要差异
uni.requestwx.request多了 Promise 返回、拦截器（uni.request 的 timeout 默认 60s）
uni.loginwx.login多平台分支；小程序端多返回 openid（需后端 code2session）
uni.getUserProfilewx.getUserProfile参数一致；uni 额外处理 H5 / App 分支
uni.requestPaymentwx.requestPayment参数名和字段有差异（见 13.2）
uni.requestSubscribeMessagewx.requestSubscribeMessage一对一
uni.getSettingwx.getSetting一对一
uni.authorizewx.authorize一对一
uni.openSettingwx.openSetting一对一
uni.getLocationwx.getLocation多端实现，小程序端限制 scope 必须声明
uni.chooseImagewx.chooseMedia（新版）uni 兼容了老接口；返回值统一为 tempFiles
uni.scanCodewx.scanCode一对一
uni.showToastwx.showToast一对一
uni.setStorageSyncwx.setStorageSync一对一
uni.navigateTowx.navigateTo多了 H5 history；小程序返回参数通过 eventChannel
uni.setClipboardDatawx.setClipboardData一对一
uni.getSystemInfoSyncwx.getSystemInfoSyncuni 额外封装了窗口尺寸、rpx 比例

典型差异示例：uni.requestPayment vs wx.requestPayment ​

参数结构是最容易"以为 uni 全覆盖"而踩坑的地方：

ts
// 原生 wx.requestPayment
wx.requestPayment({
  timeStamp: '1700000000',
  nonceStr: 'a1b2c3',
  package: 'prepay_id=wx123',
  signType: 'RSA',
  paySign: '签名',
  success(res) { /* ... */ },
  fail(err) { /* ... */ }
})
ts
// uni.requestPayment —— 参数名更通用（适配三端）
uni.requestPayment({
  provider: 'wxpay',
  timeStamp: '1700000000',
  nonceStr: 'a1b2c3',
  package: 'prepay_id=wx123',
  signType: 'RSA',
  paySign: '签名',
  success(res) { /* ... */ },
  fail(err) { /* ... */ }
})

上面看似乎只是多了一个 provider 字段。但后端签名算法、字段顺序、AppId、商户号这一整套是不变的——uni 没帮你做任何签名计算，全靠后端正确返回。永远不要在客户端拼装金额。完整的支付签名链路见 13.2。

什么时候应该直接用 wx API？ ​

有三种场景：

  1. API 还没被 uni 封装（例如 wx.getPrivacySetting、wx.onWindowResize 等较新接口）。
  2. uni 封装无法满足参数灵活性（例如 wx.requestPayment 的回调字段、wx.cloud 云开发相关）。
  3. 只在小程序端生效的原生能力（如 wx.openEmbeddedMiniProgram、wx.navigateToMiniProgram）。

直接调用的条件编译：

ts
// #ifdef MP-WEIXIN
wx.someNativeApi({
  param: 'xxx',
  success(res) { /* ... */ }
})
// #endif

或者统一用 uni.getSystemInfoSync() 判断平台后再兜底：

ts
const sys = uni.getSystemInfoSync()
if (sys.uniPlatform === 'mp-weixin') {
  // 小程序专属逻辑
}

三、调试环境三种形态：模拟器 vs 真机 vs 微信开发者工具 ​

小程序调试的"三大场景"结果可能不一样。常见问题：

行为开发者工具模拟器真机（iOS/Android）差异来源
网络请求默认合法域名白名单内可发必须配置 request 合法域名 + HTTPS模拟器可勾选"不校验合法域名"；真机不行
授权弹窗第一次就弹；关闭后能重新请求同左，但从设置页关闭后，wx.getSetting 会返回 false真机权限拒绝后必须引导到设置页
定位用电脑 IP 定位GPS + Wi-Fi 基站模拟器定位不准
clipboard 剪贴板正常部分安卓机型有限制低版本安卓 setClipboardData 可能 fail
getMenuButtonBoundingClientRect总是有值iOS 刘海 / 安卓胶囊位置不同模拟器始终返回一套值，真机要测不同机型
rpx 单位换算按 750 设计稿等比iOS / 安卓 DPI 差异极个别低版本安卓可能有 0.5px 偏差
CSS filter / mix-blend-mode支持低版本基础库不支持使用前查"基础库最低版本"
分包加载延迟加载模拟真实网络下有加载失败概率弱网真机测分包跳转
onShareAppMessage能触发但无法真正分享需真机点击触发分享走真机验
订阅消息模拟器能弹订阅框真机同，但部分模板类型真机才能发体验版真实验证

典型调试工作流 ​

text
1. 本地 HBuilderX / CLI 构建
2. 导入开发者工具 → 验证编译无错、页面能打开
3. 勾选"不校验合法域名"跑通主要逻辑
4. 体验版上传 → 手机扫码 → 真机测网络/权限/胶囊/支付/分享
5. 灰度发布到小范围用户
6. 全量上线

开发者工具里的常用面板 ​

  • AppData：实时查看页面 data（uni 的响应式数据在这里叫 data）
  • Network：抓包，注意真机的请求 URL 域名必须在小程序后台配置白名单
  • Storage：验证 uni.setStorage / uni.getStorage 读写
  • Console：uni-app 的 console.log 直接输出
  • Compiled：查看编译后的 wxml/wxss，排查样式差异
  • 真机调试：通过二维码连真机，可看真机控制台 log、实时网络请求、定位等

四、AppID、合法域名、云开发——三句话讲清 ​

AppID 是什么 ​

每个小程序的唯一标识。uni-app 的 manifest.json → 微信小程序配置 → AppID 填入后，编译产物里的 app.js 会带上它。AppID 可以在 微信公众平台 注册免费账号后获得（测试号也行）。

合法域名 ​

小程序只能请求已在公众平台配置的 HTTPS 域名（request / upload / download / socket 四种）。本地开发阶段可以在开发者工具右上角「详情 → 本地设置」勾选「不校验合法域名」，但真机必须配置。域名配置路径：公众平台 → 开发 → 开发管理 → 开发设置 → 服务器域名。

云开发 ​

uni-app 也支持微信云开发，但推荐直接调 wx.cloud.init() 再用原生 wx.cloud.database() / wx.cloud.callFunction()。云端逻辑不参与 uni 编译，属于原生小程序侧能力。

常见问题 ​

Q：为什么我在开发者工具里一切正常，真机上 uni.request 全 fail？ 99% 是合法域名没配。先把接口域名加到公众平台「服务器域名 → request 合法域名」里，然后重新上传体验版。HTTPS 必须有效，证书链完整，TLS 版本 ≥ 1.2。

Q：uni 封装会不会拖慢性能？ 绝大多数 uni API 封装是一层同步转发 + Promise 包装，性能损耗可以忽略。真正有成本的是 Vue 运行时（小程序本身也在跑它）。你在模板里写的原生组件（<image>、<button>、<map>）渲染路径和原生小程序完全一致。

Q：编译后的产物我可以直接修改吗？ 可以临时修改用来快速验证，但不要——下次构建会覆盖。应该改源代码，条件编译和自定义运行时扩展都能覆盖绝大多数定制场景。

Q：开发者工具里有警告"建议使用新版基础库"怎么办？ 在公众平台 → 开发 → 管理 → 版本管理，把你的小程序基础库最低版本调上去（比如 2.33.0），然后代码里用 uni.getSystemInfoSync().SDKVersion 做版本判断兜底老用户。
