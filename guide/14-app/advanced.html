14.2 进阶应用：原生插件与 App 运行时能力 ​

跨过「能跑起来」的坎，真正让 App 进入生产环境的，是那些 JS 世界里没有现成方案的原生能力——长连接推送、地图 SDK、支付指纹、生物识别、以及最关键的：发版不依赖应用商店审核的热更新。

本章把它们拆解成四个主题：原生插件 → 热更新 → 推送 → 生物识别。

一、原生插件：uni.requireNativePlugin 全景 ​

uni.requireNativePlugin 是 uni-app 调用原生插件的唯一入口。HBuilderX 插件市场上有 500+ 现成插件（极光推送、高德地图、微信登录、支付宝支付等），直接在 manifest.json 里勾选即可，无需手动写一行原生代码。

目录结构 ​

离线/原生工程下，自定义插件按下面的目录组织：

JS 侧调用示例（极光推送） ​

js
// src/services/jpush.ts
// #ifdef APP-PLUS
const jpush = uni.requireNativePlugin('JPush')

export const JPushService = {
  // 初始化（onLaunch 里调用）
  init(appKey: string) {
    jpush.init({ appKey, channel: 'developer-default' }, (res: any) => {
      console.log('[JPush] init ok', res)
    })
    // 监听点击通知栏事件
    jpush.addEventListener('clicknotification', (payload: any) => {
      uni.navigateTo({ url: payload.payload?.url ?? '/pages/index/index' })
    })
  },

  // 设置别名（业务用户 ID 绑定）
  setAlias(userId: string) {
    jpush.setAlias({ alias: userId }, (res: any) => {
      if (res.code !== 0) console.warn('[JPush] setAlias fail', res)
    })
  },

  // 停止推送（退出登录时）
  stop() {
    jpush.stopPush()
  },
}
// #endif

一个完整的 Android 原生插件（简化版） ​

当现成插件无法满足需求时（比如你需要调用某家银行的私有 SDK），就要自己写。下面以 JPush Android 端模块为例展示骨架：

java
// android/app/src/main/java/com/yourplugin/YourPluginModule.java
package com.yourplugin;

import com.taobao.weex.annotation.JSMethod;
import com.taobao.weex.bridge.JSCallback;
import com.taobao.weex.common.WXModule;
import cn.jpush.android.api.JPushInterface;
import android.content.Context;
import android.app.Application;

public class YourPluginModule extends WXModule {

    /**
     * uni.requireNativePlugin('YourPlugin').init(options, callback)
     */
    @JSMethod(uiThread = false)
    public void init(android.util.Pair<String, Object> options, JSCallback callback) {
        Context ctx = mWXSDKInstance.getContext().getApplicationContext();
        String appKey = (String) options.second;

        // 初始化极光
        JPushInterface.setDebugMode(true);
        JPushInterface.init(ctx);

        callback.invokeAndKeepAlive(new String[]{"OK", JPushInterface.getRegistrationID(ctx)});
    }

    @JSMethod(uiThread = true)
    public void stopPush() {
        Context ctx = mWXSDKInstance.getContext().getApplicationContext();
        JPushInterface.stopPush(ctx);
    }
}

要点：

  • 继承 WXModule，注解 @JSMethod 标记暴露给 JS 的方法；
  • uiThread = false 表示方法在后台线程执行，不阻塞 UI；
  • 通过 mWXSDKInstance.getContext() 拿到 Activity / Application Context；
  • callback 用 invokeAndKeepAlive 可以回调多次（长连接场景）。

二、热更新：wgt 包 + 灰度 + 回滚 ​

用户装的 App 不是浏览器——你不能指望他们每次都去应用商店更版。热更新（Hot Code Push）是 App 端必不可少的发版手段。

uni-app App 端的热更新基于 wgt 包（一种把 www/ 资源压缩成的 zip，改后缀为 .wgt）。机制很简单：App 启动时请求你的服务器拿「版本清单」，如果发现有比本地新的 wgt，就下载 → 校验签名 → 解压覆盖 www/ 目录 → 重启应用。

mermaid
sequenceDiagram
    participant App as App 启动
    participant CDN as 你的 CDN
    participant API as 版本服务
    App->>API: GET /api/app/version?platform=android&local=2.1.0
    API-->>App: { wgtUrl, version: "2.1.1", force: false, grayRatio: 0.2 }
    App->>App: 判断是否需要更新 + 灰度命中
    App->>CDN: 下载 .wgt
    CDN-->>App: wgt 文件 + md5
    App->>App: plus.runtime.verify + install
    App->>App: plus.runtime.restart()

客户端实现 ​

ts
// src/services/hot-update.ts
// #ifdef APP-PLUS
export async function checkAndUpdate() {
  const res = await uni.request({
    url: `${BASE_URL}/api/app/version`,
    data: { platform: 'android', local: plus.runtime.versionName },
  })
  const update = res.data.data
  if (!update?.wgtUrl) return

  // 强更直接弹窗
  if (update.force) {
    uni.showModal({
      title: '发现新版本',
      content: '必须更新才能继续使用',
      showCancel: false,
      success: () => downloadAndInstall(update.wgtUrl),
    })
    return
  }

  // 灰度：对 userId hash 到 0~1，命中 grayRatio 则拉新包
  const hash = Math.abs(hashCode(getUserId())) / 0x7fffffff
  if (hash < (update.grayRatio ?? 0)) {
    uni.showModal({
      title: '有新版本，是否更新？',
      success: (r) => r.confirm && downloadAndInstall(update.wgtUrl),
    })
  }
}

function downloadAndInstall(wgtUrl: string) {
  uni.showLoading({ title: '更新中...', mask: true })
  plus.runtime.download(
    wgtUrl,
    (downloaded) => {
      plus.runtime.install(
        downloaded.filename,
        { force: true },
        () => { uni.hideLoading(); plus.runtime.restart() },
        (err) => { uni.hideLoading(); console.error('install fail', err) },
      )
    },
    (err) => { uni.hideLoading(); console.error('download fail', err) },
  )
}

function hashCode(s: string): number {
  let h = 0
  for (let i = 0; i < s.length; i++) h = ((h << 5) - h + s.charCodeAt(i)) | 0
  return h
}
// #endif

安全与回滚 ​

风险应对
wgt 包被篡改plus.runtime.install 第二个参数开启签名校验：{ certificate: "base64公钥" }，客户端只接受你签名过的包
更新后崩溃/白屏版本清单里保留「上一个稳定版本」，App 连崩溃 3 次后自动下载上一个版本的 wgt 回滚
热更新包含原生插件变更wgt 只能更新前端资源，原生插件 / manifest.json / 证书改动必须走应用商店重新发版。清单里用 minNativeVersion 标明当前 wgt 需要的最低原生版本
灰度包全量事故版本服务加开关：grayRatio=0 立即关闭；rollbackVersion 字段一键让所有灰度用户回滚到指定版本

发版节奏建议 ​

Day 0  发布 5% 用户灰度 → 监控崩溃率 + 核心接口成功率
Day 2  扩到 20% → 看评论区反馈 + 客服工单
Day 4  扩到 50%
Day 6  全量 100%

三、推送服务：七路覆盖 ​

Android 中国厂商推送是出了名的混乱——每家都要接各自的 SDK。iOS 则统一走 APNs。实际项目里没人自己逐家接入，都是用「聚合推送」：极光推送（JPush）、个推（Getui）、友盟（Umeng）三家任选一家，一次 SDK 覆盖全量通道。

通道一览 ​

通道平台是否需要单独 SDK说明
APNsiOS是（但聚合 SDK 已封装）唯一官方通道，DevToken 由 APNs 颁发
华为 HMS Push华为 EMUI是需要华为开发者账号 + AppID
小米 MiPush小米 MIUI是需申请 AppID / AppKey
OPPO PushOPPO ColorOS是需 OPPO 开发者平台备案
vivo Pushvivo OriginOS是vivo 开发者平台申请
FCMAndroid 原生 / 海外是国内厂商 ROM 基本不走 FCM
聚合通道全平台一次集成JPush / 个推 / 友盟，自动选最优通道下发

plus.push 系统推送（低优先级） ​

如果你只是发个通知，不需要长连接，也可以直接用 plus.push：

js
// #ifdef APP-PLUS
// 监听系统通知
plus.push.addEventListener('click', (msg) => {
  uni.navigateTo({ url: msg.payload })
})

// 本地通知
plus.push.createMessage('标题', '正文', {
  cover: 'static/app/icon.png',
  payload: JSON.stringify({ type: 'order', id: '12345' }),
})
// #endif

但实际生产里，80% 的团队会选择极光推送 + 厂商通道二次封装。原因很简单：系统推送无法保证送达率（Android 厂商 ROM 会杀进程），而聚合 SDK 会自动在退到后台时走厂商通道下发通知。

厂商通道 Checklist ​

每家厂商接入都要走「注册 → 填写 AppID/AppKey → 后台配置签名证书指纹」的流程：

  • [ ] 华为：开发者账号 → 创建移动应用 → 开通 Push 服务 → 拿到 appId / client_secret
  • [ ] 小米：AppId / AppKey / AppSecret，后台上传 MD5 小写的签名证书指纹（注意是 MD5 不是 SHA-1）
  • [ ] OPPO：AppKey / AppSecret，后台填写 PackageName + 证书指纹
  • [ ] vivo：AppId / AppKey / AppSecret
  • [ ] 全部把这些 Key 填进极光推送的控制台 → 极光会自动代你下发

四、生物识别 + 原生权限声明 ​

生物识别（指纹 / Face ID） ​

plus.android / plus.ios 都可以直接调原生生物识别 API。但更推荐用 uni-app 的条件编译 + 官方封装（或插件市场「生物认证」插件），一次写双端生效：

ts
// src/services/biometric.ts
export async function authenticate(reason: string): Promise<boolean> {
  // #ifdef APP-PLUS
  return new Promise((resolve) => {
    const isIOS = uni.getSystemInfoSync().platform === 'ios'
    if (isIOS) {
      const LAContext = plus.ios.importClass('LocalAuthentication.LAContext')
      const ctx = new LAContext()
      ctx.evaluatePolicy(
        2, // LAPolicyDeviceOwnerAuthenticationWithBiometrics
        reason,
        (ok, error) => resolve(!!ok),
      )
    } else {
      // Android BiometricPrompt
      const BiometricPrompt = plus.android.importClass('androidx.biometric.BiometricPrompt')
      const PromptInfo = plus.android.importClass('androidx.biometric.BiometricPrompt$PromptInfo')
      const info = new PromptInfo.Builder()
        .setTitle('身份验证')
        .setSubtitle(reason)
        .build()
      const prompt = new BiometricPrompt(mWXSDKInstance.getContext(), new BiometricCallback(resolve))
      prompt.authenticate(info)
    }
  })
  // #endif
  // #ifndef APP-PLUS
  return false // H5 / 小程序端不支持
  // #endif
}

Android 运行时权限示例 ​

ts
// #ifdef APP-PLUS
function requestLocation() {
  const Manifest = plus.android.importClass('android.Manifest')
  const ActivityCompat = plus.android.importClass('androidx.core.app.ActivityCompat')
  const mainActivity = plus.android.runtimeMainActivity()

  if (ActivityCompat.checkSelfPermission(mainActivity, Manifest.permission.ACCESS_FINE_LOCATION) !== 0) {
    ActivityCompat.requestPermissions(mainActivity, [Manifest.permission.ACCESS_FINE_LOCATION], 1001)
  }
}
// #endif
