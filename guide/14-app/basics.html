14.1 基础入门：uni-app App 构建原理 ​

App 端是 uni-app 最「重」的一个目标平台——不是因为代码复杂，而是因为你一夜之间要同时面对两个成熟且严肃的原生生态：Android（Gradle 构建、AAB 签名、ABI 选择）与 iOS（Xcode 工程、provisioning profile、Info.plist 沙盒限制）。新手最容易陷入的坑是：拿着一个 5 万行 H5 项目，就以为自己「打包」一下就是 App 了。远不是那么回事。

本章把 App 构建拆成三层看：打包路线 → 原生交互层 → 配置与资源。

一、三条打包路线：云打包 / 离线打包 / 原生工程 ​

uni-app 官方提供了三种生成 .apk / .ipa 的方式，分别对应不同成熟度的团队。选错路线会让你踩一两个月的坑。

对比表 ​

维度云打包离线打包原生工程
谁来编译DCloud 云端（免费额度 / HBuilderX 内置）本地 HBuilderX 调起本地 SDK你自己在 AS / Xcode 手动构建
环境准备仅需上传证书文件需本地安装 Android SDK、JDK、Xcode完整原生开发环境 + Gradle / CocoaPods
自定义原生库有限（云编译环境不透明）可插入 .aar / .framework完全可控，任意第三方 SDK
CI/CD 友好弱（命令行需 HBuilderX CLI）中等（HBuilderX CLI）强（gradlew assembleRelease / xcodebuild archive）
调试效率低（编译排队 + 失败日志不完整）中高（断点 + Logcat + Instruments）
适合场景个人开发者、原型、内部工具中小型企业、标准插件需求金融/电商/社交等重度 App、自研插件
典型耗时首次 ~3 min，增量 ~1 min首次 ~2 min，增量 ~30 s首次 ~5 min，增量 ~10 s

选择建议 ​

  • 能用云打包就先用：它让你一天内就能拿到真机。等到必须接入某家厂商的长连接 SDK、或者 Gradle 打包脚本报奇怪错误时，再切离线/原生。
  • iOS 打包：无论云/离线，最终都需要 Mac 上的 Xcode 证书与描述文件。如果团队没有 Mac，考虑用 Appuploader 或 Fastlane match 做证书自动化。
  • 原生工程路线：HBuilderX 提供「生成本地打包 App 资源」，把你的 uni-app 产物（www/ 目录）塞进一个模板原生工程。这是长期推荐的企业化路线。

二、HTML5+ / plus API 全景 ​

uni-app 在 App 端的底层运行时是 HTML5+ 引擎（一套 webview + 原生桥接层）。所有跨端 API（uni.navigateTo、uni.request、uni.getLocation）最终都落在 plus.* 命名空间上。

原生交互：plus.android.importClass / plus.ios.importClass ​

这是 uni-app App 端最强大也最需要克制的 API——它让你直接从 JS 调用任意 Android / iOS 原生类。

Android 端示例：调用 Toast + 剪贴板 ​

js
// App 端环境下执行（条件编译里）
// #ifdef APP-PLUS
plus.android.ready(() => {
  // 1. 导入原生类
  const Toast = plus.android.importClass('android.widget.Toast')
  const ClipboardManager = plus.android.importClass('android.content.ClipboardManager')
  const ClipData = plus.android.importClass('android.content.ClipData')

  // 2. 获取 Context
  const mainActivity = plus.android.runtimeMainActivity()

  // 3. 剪贴板写入
  const cm = mainActivity.getSystemService(
    plus.android.importClass('android.content.Context').CLIPBOARD_SERVICE
  )
  cm.setPrimaryClip(ClipData.newPlainText('label', '从 uni-app 写入的内容'))

  // 4. Toast
  Toast.makeText(mainActivity, '已复制', Toast.LENGTH_SHORT).show()
})
// #endif

iOS 端示例：调用系统相册选择器 ​

js
// #ifdef APP-PLUS
plus.ios.ready(() => {
  const UIImagePickerController = plus.ios.importClass('UIImagePickerController')
  const controller = new UIImagePickerController()
  controller.sourceType = 1 // 1=相册, 0=相机
  controller.delegate = {
    didFinishPickingMediaWithInfo: (picker, info) => {
      plus.ios.invoke(picker, 'dismissViewControllerAnimated:completion:', true, null)
      // info 里是图片路径 / NSData 引用
    },
  }
  const rootVC = plus.ios.invoke(
    plus.ios.runtimeMainActivity(), 'rootViewController'
  )
  plus.ios.invoke(rootVC, 'presentViewController:animated:completion:', controller, true, null)
})
// #endif

使用原则 ​

  • 不要在跨端业务代码里直接写 plus.*——所有原生调用都要包进「桥接层」并用条件编译隔离。
  • plus.android.ready / plus.ios.ready 必须等 DOM ready 后再调用，否则 runtimeMainActivity() 会返回 null。
  • plus API 性能比 uni.* 好，但只在 App 端生效。把它当作 uni.* 的补充，而不是替代。

三、manifest.json app-plus 核心配置 ​

manifest.json 是 uni-app App 端的「总开关」。所有原生级别的配置（权限、图标、启动页、白屏检测、SplashScreen 策略）都集中在这里。

四、证书 / 图标 / 启动页 Checklist ​

上线前漏一个就会被拒或 crash。把下面这份清单打印出来，让 QA 一项项勾：

签名证书 ​

项目AndroidiOS
调试证书HBuilderX 自动生成Xcode 自动生成 Development Profile
发布证书自签名 .jks（包名一致，有效期 ≥ 25 年）Apple Developer 证书 + App Store Distribution Profile
包名 / Bundle ID全小写 + 反向域名（如 com.example.shop）与 Android 保持同一业务前缀（如 com.example.shop）
证书备份.jks + 密码 + 别名，存密码库.p12 + .mobileprovision，导出密码存密码库

⚠️ Android 证书一旦丢失就无法覆盖升级——务必在保险柜里放一份。

图标 ​

  • [ ] Android：mdpi / hdpi / xhdpi / xxhdpi / xxxhdpi 五套，文件名统一 icon.png
  • [ ] iOS：CocoaPods / Asset Catalog 管理，必须有 1024×1024 的 App Store 大图（无透明通道，无 alpha）
  • [ ] 圆角：系统会自动裁切，不要在图标里自行做圆角（否则被截完后成了奇怪形状）
  • [ ] 图标上禁止出现「测试」「Demo」「Beta」字样——应用商店会拒

启动页（SplashScreen） ​

  • [ ] Android：分辨率 720×1280（mdpi 3:4:6:8 比例都要有）
  • [ ] iOS：使用 LaunchScreen.storyboard 替代静态图（iOS 14+ 推荐）
  • [ ] 启动页停留时间 ≥ 1s（否则体验差），≤ 3s（否则用户以为卡死）
  • [ ] SplashScreen 不要放营销图 / 版本号——应用商店审核会拒，只放 Logo + Slogan

权限声明 ​

  • [ ] Android AndroidManifest.xml：所有 <uses-permission> 都在 manifest.json 的 distribute.android.permissions 里列出
  • [ ] iOS Info.plist：所有 NS*UsageDescription 都写清楚业务用途，不能只写「需要访问相机」
  • [ ] 运行时权限（Android 6.0+ / iOS 13+）：在真正使用前调用 uni.authorize 主动申请，不要等系统弹窗
