24.3 实战案例：Mock Collector 闭环演练 ​

前面两篇分别设计了 SDK 与告警规则，这一篇把它们接到一个真实可跑的本地收集器上，完整验证 上报 → 去重 → 断网补传 → 脱敏 → 告警判定 五步。不需要真机、不需要云服务，CI 里也能跑。

一、闭环的五个检查点 ​

mermaid
flowchart LR
    A[业务埋点<br/>telemetry.track] --> B[队列 + 批量 + 采样]
    B --> C[POST /collect]
    C --> D[服务端按 event.id 去重]
    D --> E[/stats 统计/]
    E --> F[alert-evaluate<br/>P0-P3]
    B -.断网失败回队.-> B

下面五个检查点，正是这个演练要逐一证明的内容：

检查点验证手段通过标准
上报协议GET /health + POST /collect返回 {"ok":true}，事件被接收
服务端去重同一批次发两次第二次 accepted=0，duplicates 递增
离线补传先指向死端口，再切回真实地址失败批次回队，恢复后全部送达
隐私脱敏事件带 token/phone/password/stats 中只出现 ***
告警分级用错误率/崩溃率判定P0/P1 退出码 1，P2/P3 为 0

仓库内已提供两个零依赖脚本：scripts/mock-collector.mjs、scripts/telemetry-smoke.mjs，以及告警判定脚本 scripts/alert-evaluate.mjs。

二、启动收集器 ​

bash
# 终端 A：启动本地收集器（默认 127.0.0.1:8787）
pnpm telemetry:collector

# 终端 B：健康检查与清空
curl -s http://127.0.0.1:8787/health
# {"ok":true,"received":0}

curl -s -X POST http://127.0.0.1:8787/reset
# {"ok":true}

手动发一条事件，确认协议字段：

bash
curl -s -X POST http://127.0.0.1:8787/collect \
  -H 'content-type: application/json' \
  -d '[{"id":"manual-1","event":"page_view","ts":1790000000000,"sessionId":"s-1","props":{"route":"/pages/index"},"context":{"platform":"h5","appVersion":"1.0.0"}}]'
# {"ok":true,"accepted":1,"duplicates":0}

三、一键协议冒烟 ​

bash
pnpm telemetry:smoke

脚本会自己完成四件事（使用 Node 18+ 的 fetch 作为 uni.request 的替身，验证的是协议而不是 UI）：

  1. 健康检查并清空收集器；
  2. 把 5 条事件发往死端口 127.0.0.1:8799，断言全部失败且仍留在队列；再切回真实地址，断言补传 5 条；
  3. 同一批次连续发两次，断言第二次 accepted=0、duplicates=3；
  4. 发送带 token/phone/password 的事件，断言收集器中只有 ***。

预期输出：

text
✅ 1/4 健康检查通过
✅ 2/4 断网回队与恢复补传通过（5 条）
✅ 3/4 服务端按 event.id 去重通过
✅ 4/4 敏感字段脱敏通过

📊 /stats 汇总：
   total=9 duplicates=3
   byName={"page_view":1,"api_error":3,...}

✅ 遥测闭环冒烟通过

任何一步断言失败，脚本以退出码 1 结束，可直接挂到 CI。

本机实测（2026-11-04）：total=9、duplicates=3、byName.api_error=3，脱敏断言通过；node scripts/alert-evaluate.mjs 对含 3 条 api_error 的样本判定为 P1 并退出码 1，符合预期。

四、接入真实业务 SDK ​

把 24.1 的 createTelemetry 实例端点改成环境变量，开发期指向本地收集器：

ts
// src/services/telemetryInstance.ts
import { createTelemetry } from './telemetry'

const endpoint = import.meta.env.VITE_TELEMETRY_ENDPOINT ?? 'https://log.example.com/collect'

export const telemetry = createTelemetry({
  endpoint,
  sampleRate: import.meta.env.PROD ? 0.5 : 1,
  onContext: () => {
    const info = uni.getSystemInfoSync()
    return {
      platform: `${info.platform}/${info.system}`,
      appVersion: info.appVersion ?? 'dev',
      page: getCurrentPages().at(-1)?.route
    }
  }
})

telemetry.start()
bash
# .env.development
VITE_TELEMETRY_ENDPOINT=http://127.0.0.1:8787/collect

两端注意：

端注意事项
H5收集器已带 Access-Control-Allow-Origin: *，本地直连即可
微信小程序开发者工具勾选「不校验合法域名」；真机需把域名加入 request 合法域名并使用 HTTPS

五、断网补传演练（真机或 H5） ​

  1. 打开 DevTools → Network → 切到 Offline（小程序用开发者工具的「断网」）；
  2. 连续触发 25 条事件（例如反复进出页面），观察队列不超过 200 条；
  3. 恢复网络，等待一个 flush 周期（10 秒）或手动切后台触发 onHide；
  4. 查询收集器：
bash
curl -s http://127.0.0.1:8787/stats | node -e "
let s=''
process.stdin.on('data', c => s += c).on('end', () => {
  const stats = JSON.parse(s)
  console.log('total=', stats.total, 'duplicates=', stats.duplicates)
})"

期望：total 与触发条数一致，duplicates 为 0（若网络抖动导致重试，服务端去重后也不会重复入库）。

再验证持久化：上报前杀掉进程，重启后 SDK 的 restore() 会从 uni.setStorageSync 读回队列并补传。

六、脱敏检查 ​

bash
curl -s http://127.0.0.1:8787/stats
# 人工检查 latest 与 byName：
# - 不应出现真实 token、手机号、密码
# - 敏感字段值应为 "***"

也可以在冒烟脚本中断言，避免人工漏看：

bash
node scripts/telemetry-smoke.mjs | grep -q "脱敏通过" && echo "PASS"

七、告警模拟 ​

用收集器里的错误率直接判定级别：

bash
node scripts/alert-evaluate.mjs
# {"level":"P1","reason":"接口错误率 33.3% > 5%",...}
# exit 1（P1 会阻断发布门禁）

模拟崩溃率突增与支付成功率下跌：

bash
node scripts/alert-evaluate.mjs --crash-rate 1.4
# level=P0，exit 1

node scripts/alert-evaluate.mjs --crash-rate 0.2 --payment-success 99.6
# 若错误率也正常，则 level=P3，exit 0

接入 CI 时把这一步放在「发布前检查」，P0/P1 直接终止发布；判定规则与 24.2 的分级表保持一致。

八、完整验收命令 ​

bash
# 1. 启动收集器（后台）
pnpm telemetry:collector &

# 2. 协议冒烟
pnpm telemetry:smoke

# 3. 告警判定（P1 预期退出码 1，用于演示）
pnpm alert:evaluate || echo "expected: P1 blocks release"

# 4. 静态门禁
pnpm typecheck
pnpm check:snippets:strict

九、常见问题 ​

现象原因处理
/collect 404端口或路径写错确认 endpoint 以 /collect 结尾
H5 报 CORS收集器未启动或用了生产域名本地用 127.0.0.1，确认响应头
小程序真机收不到未配置合法域名 / 非 HTTPS开发期勾选不校验，真机走 HTTPS 域名
事件数量少于预期普通事件被采样关键事件 track(name, props, true) 跳过采样
重启后丢事件未调用 start() 或未持久化启动时 start()，确认 restore() 读到队列

十、自查 ​

  • 冒烟脚本能稳定复现「断网回队 + 恢复补传」，不是靠人工点页面。
  • 同一 event.id 重复上报不会造成统计翻倍。
  • 收集器中检索不到任何原始敏感值。
  • 告警判定有明确退出码，能作为发布门禁。
  • 本地收集器只是验证工具，生产仍然使用具备鉴权、限流、TTL 的后端服务。
